- 要补齐：`node Plugins/dsh-ops/bin/dsh-ops.mjs provision-shells --pwsh`（约 106MB，pin 7.6.6），装完 `ladder` 应显示 `source: provisioned`。

## 2. billion-context 复核

### 2.1 版本升级 0.1.198 → 0.1.201（已完成）

```powershell
$node = "D:\Tools\DeepSeek Harness\Dependency\nodejs\node.exe"
$cli  = "D:\Tools\DeepSeek Harness\source\apps\cli\lib\bin.js"
& $node $cli plugin --profile web add billion-context@0.1.201   # 退出码 0
```

升级后核验：`node_modules/billion-context/package.json` = `0.1.201`；profile `package.json` 的 spec = `^0.1.201`；`pnpm-lock.yaml` 两处 0.1.201；`pnpm-workspace.yaml` 的 `minimumReleaseAgeExclude` 自动追加 `billion-context@0.1.201`。

**为什么必须升**：0.1.198 含 #3600 回归，而本 profile 的 `agent-preset-registry.selectedDefault = ptc`。PTC 预设把所有工具收进单个 `run_code` omnibus，顶层 tools 里没有 `compress`：

```js
// 0.1.198 dist/index.js — resolveLaneDecisions
const compressReachable = !input.pluginMode || declaredTools.has("compress")
  || !profile.toolsHostScopedByDefault;          // ← 缺 run_code 分支
const compressSurfaceOn = input.shouldInject && compressReachable;
```

→ `compressSurfaceOn = false` → nudge 被抑制 → 日志 `nudge ARMED-SUPPRESSED`。实测 `bili.log` 全局 **23 条**、本会话 **4 条**。0.1.201 已改为 `… || declaredTools.has(RUN_CODE_TOOL_NAME) || …`，grep 命中。

### 2.2 自动更新修复（已完成）

**症状**：每 180s 一轮，`[update] dsh profile bundle is stale (0.1.198 → 0.1.200) — refreshing via dsh's plugin channel` 后必然失败：

```
[warn] bundle refresh to 0.1.201 failed: 'dsh' 不是内部或外部命令，也不是可运行的程序或批处理文件。
[warn] — manual fix: run `dsh plugin --profile web add billion-context@0.1.201` from a shell where `dsh` resolves (or point BILI_DSH_BIN at dsh's executable)
```

`~/.cache/billion-context/.install-backoff.json` 已累积 `owner:dsh-profile:0.1.200 count=2`、`owner:dsh-profile:0.1.201 count=1`。

**根因**：代理的 dsh owner-lane 需要调 `dsh` 可执行文件，而本机 DSH 是源码 checkout + 便携 node 启动，`dsh` 从未进 PATH。

**修法**（已执行，选的是官方兜底目录，不改系统环境变量）：`resolveDshBinary()` 的探测顺序是 `BILI_DSH_BIN` → `PATH`（按 PATHEXT）→ `[node 自身目录, %APPDATA%\npm, %LOCALAPPDATA%\pnpm]`。因此新建：

`C:\Users\HometownVoyager\AppData\Roaming\npm\dsh.cmd`

```bat
@echo off
REM dsh launcher for billion-context auto-update owner lane (2026-10-18)
"D:\Tools\DeepSeek Harness\Dependency\nodejs\node.exe" "D:\Tools\DeepSeek Harness\source\apps\cli\lib\bin.js" %*
```

验证：`cmd /c "dsh --version"` → `0.2.1-rc.2`；用 node 复刻 `resolveDshBinary` 逻辑返回该 `dsh.cmd` 路径。

**升级节奏提示**：0.1.200 起发现新版不再立即安装，而是在 **15min–48h** 窗口里随机抽一个时刻落盘 `~/.cache/billion-context/.update-stagger.json`，重启不重摇。想立刻升级就手动跑 `plugin add`（手动路径绕过错峰）。`autoRestartOnUpdate` 默认 false，所以装完仍需手动重启。

### 2.3 provider retryPolicy 覆盖丢失（account 侧已修，workbuddy 未解）

**现象**：当前实际 provider 是 **workbuddy**（`agent-default-model.provider = workbuddy`，会话 request/context 亦为 `provider: workbuddy`）。工具调用 JSON 抖断时，`MALFORMED_RESPONSE` 不在重试码表里 → 整轮失败不重试。

**两层原因**：

1. `dsh-connect-workbuddy/lib/index.js:557` 硬编码 `retryPolicy: resolveRetryPolicy(void 0, "dsh-connect-workbuddy retryPolicy")`，走默认码表（`source/packages/llm/llm/src/retry-policy.ts` 的 `DEFAULT_RETRYABLE_CODES` = EMPTY_RESPONSE / RATE_LIMIT / SERVER / TIMEOUT / TRANSPORT）。其 `lib/index.d.ts` 的 `Config` **没有 retryPolicy 字段**，无法配置透传；pi-ai 侧 `classifyPiAiError`（`source/packages/llm/llm-pi-ai/src/stream.ts:42-68`）也不会产出 `MALFORMED_RESPONSE`。
2. bili 的 #2605 补丁给 `llm-deepseek` 与 `llm-deepseek-account` 都加了 `MALFORMED_RESPONSE`，但 profile patch 的 `llm-deepseek-account` 段用 `modelOverrides` **整段替换** config（patch 语义不深合并），把 bundle 层补的 `retryPolicy` 冲掉了——`dump-default-config.yml` 有、组合配置没有。

**已修**（account 侧）：在 `~/.dsh/profiles/web/cordis.patch.yml` 的 `llm-deepseek-account` 块补回：

```yaml
- id: llm-deepseek-account
  name: "@deepseek-ai/dsh-llm-deepseek-account"
  config:
    retryPolicy:
      mode: normal
      retryableCodes: [EMPTY_RESPONSE, RATE_LIMIT, SERVER, TIMEOUT, TRANSPORT, MALFORMED_RESPONSE]
    modelOverrides:        # 原有内容保持不变
      …
```

`--dump-config` 复核：第 622-633 行已含 `retryPolicy`，`MALFORMED_RESPONSE` 计数 2。

**仍未解**：workbuddy 链路。要修只有两条路——(a) 给上游 `dsh-connect-workbuddy` 提 feature request 增加 `Config.retryPolicy`；(b) 直接改第三方包 `lib/index.js`（本次未动，避免升级时被覆盖）。

### 2.4 自建预设的 inject 缺口（未修，记录）

bili 的 `dsh.bundle.patch.yml` 只给 **4 个官方 Web 预设**（standard / ptc / minimal / cordis）加 `inject: [biliBasicCompactionPolicy]` 作为「加载期 overlay 就绪」的门。而组合配置里 **17 个预设各自都有 1 份内嵌 `compaction-basic`**，其中 13 个自建预设（game-design、genre-fiction、language-learning、novel-writing、official-docs、paper-writing、prompt-writing、science-learning、screenplay-writing、social-issues、vn-design、vn-staging、godot-dev）没有 inject 门。

`bili-native` 行在组合末尾（6445 行），而 `agent-preset-registry` 会 eagerly mount 预设，理论上 overlay 可能晚于这些预设的 `mountPreset`，导致其内嵌 `compaction-basic` 未被置 disabled。**未实测到实际发生**（本会话是 preset-ptc，不受影响）。

修法：在 `Plugins/dsh-user-presets/cordis.patch.yml` 的每个 `preset-*` 行加 `inject: [biliBasicCompactionPolicy]`。验证方法：在自建预设会话里观察是否出现 dsh 原生 compaction checkpoint。

