## 1. 总览：一切都是插件

DeepSeek Harness 构建在 **Cordis**（vendored 的插件框架）之上，架构原则是
**everything is a plugin**。工具、会话、LLM 适配器、压缩器、上下文注入……全部是插件，
由一份配置树（cordis 配置）决定哪些插件组成当前应用（profile）。

| 术语 | 含义 |
|---|---|
| 插件（Plugin） | 导出 `apply(ctx)` 的模块（或 `Service` 子类），是行为的最小单元 |
| 上下文（Context / `ctx`） | 服务的容器；一个服务占据一个稳定的 `ctx.<key>`（如 `ctx.tools`） |
| 服务（Service） | 插件向其他插件公开的命名能力（`tools`、`llm`、`agents`…） |
| 事件（Event） | 插件间松耦合通信，按模式分发（emit/bail/serial/waterfall/parallel） |
| Fiber | 每个被加载插件的运行时作用域，带状态机与自动清理 |
| profile | `$DSH_HOME/profiles/<name>` 下的可启动组合目录 |
| 组合包（bundle） | 带 `dsh.bundle` 声明的 npm 包 = 一个插件配置层 |

出处：`docs/architecture.md`、`docs/cordis-primer.zh.md`。

## 2. Cordis 核心概念（读这一节再动手）

出处：`docs/cordis-primer.zh.md`。

### 2.1 五个核心概念

1. **插件是实现 Service 的对象**：可以是带可选 `inject` 和 `apply(ctx)` 的函数，也可以是 `Service` 子类。
2. **上下文是服务的容器**：其他插件通过 key 查找服务（`ctx.tools`），而非导入具体实现。
3. **通过 `inject` 声明服务依赖**：插件等待所需服务就绪才启动；加载顺序由依赖表达，不靠手排启动序列。
4. **类型化事件用于通信**：事件名通过 TypeScript 声明合并注册，以 emit / waterfall / parallel / serial 分发。
5. **注册是可逆的副作用**：提示词片段、工具 schema、适配器、监听器通过 `ctx.effect()` / `ctx.on()` 安装，
   重载与卸载时自动撤销。

### 2.2 事件分发模式

| 模式 | 是否 await | 分发顺序 | 有返回值 |
|---|---|---|---|
| `emit` | 否 | 按注册顺序观察 | 否 |
| `waterfall` | 否（下游可异步） | 环绕中间件，依次包装 | 是 |
| `parallel` | 是 | 所有监听器并行 | 否 |
| `serial` | 是 | 按注册顺序 | 是 |

**Waterfall 语义**：监听器接收 `(...args, next)`；调用 `next()` 执行下游并把下游返回值拿回来包装；
不调用 `next()` 直接返回即**短路**（策略类监听器借此行使决策权，观察类监听器则必须调用 `next()`）。
仅当必须在常规注册之前运行时才用 `prepend: true`。

### 2.3 Loader 配置插值

`!!js` 表达式会被解析为表达式节点：插件行 `config` 在注入激活后按插件上下文插值，
`disabled` 字段在每次挂载决策时按 loader 上下文插值；其余条目元数据保持字面值。
需要“按环境选择插件”时使用 overlay（见装卸指南）。

## 3. 第一个插件

出处：`docs/user/develop/basic/index.md`。

插件就是一个导出 `apply` 的 TypeScript 模块：

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'hello-plugin'

export function apply(ctx: Context) {
  console.log('[hello-plugin] plugin loaded!')
}
```

加载方式之一——用 `--patch` overlay 注册本地插件（`scratch-plugin/cordis.yml`）：

```yaml
- insert:
    - id: hello
      name: '/absolute/path/to/hello-plugin/src/my-plugin.ts'
```

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml
```

> **本机注意**：Windows 下 `name` 不能写 `D:/...`（会被当成非法 URL 协议），
> 必须写成 `file:///D:/...` 形式的 URL；Linux/macOS 用 `/绝对路径/xxx.ts`。
> 详见 [插件装卸使用指南](插件装卸使用指南.md)。

### 3.1 插件的三种形态

```ts
// 函数形式（大多数场景够用）
export const name = 'my-plugin'
export const inject = ['tools']
export function apply(ctx: Context) { /* ... */ }

// 对象形式
export default {
  name: 'my-plugin',
  inject: ['tools'],
  apply(ctx: Context) { /* ... */ },
}

// 类形式（对外提供服务的插件用这个）
import { Service, type Context } from '@deepseek-ai/cordis'
export default class MyService extends Service {
  static inject = ['tools']
  constructor(ctx: Context) {
    super(ctx, 'myService')
  }
}
```

> **坑**：函数形态插件必须只用**命名导出**（`name`/`inject`/`Config`/`apply`），
> 不要同时混 default 导出，混用会让 Loader 丢弃函数插件的命名空间
> （上游 postmortem 0001 有记录）。

### 3.2 自动清理

通过 `ctx` 注册的一切（事件监听、工具注册、定时器）在插件卸载时自动撤销；
需要显式清理的资源用 `ctx.effect()`：

```ts
export function apply(ctx: Context) {
  ctx.effect(() => {
    const timer = setInterval(() => console.log('heartbeat'), 5000)
    return () => clearInterval(timer)   // 卸载时执行
  })
}
```

## 4. 插件配置

出处：`docs/user/develop/basic/config.zh.md`。

导出 `Config` 类型 + 同名 Schemastery schema（默认值写在 schema 里）：

```ts
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'

export const name = 'my-plugin'

export interface Config {
  greeting: string
  maxRetries: number
  verbose?: boolean
}

export const Config: Schema<Config> = Schema.object({
  greeting: Schema.string().default('Hello'),
  maxRetries: Schema.number().default(3),
  verbose: Schema.boolean().default(false),
})

export function apply(ctx: Context, config: Config) {
  console.log(config.greeting)   // 用户值或 schema 默认值
}
```

配置行：

```yaml
- insert:
    - id: hello
      name: './src/my-plugin.ts'
      config:
        greeting: 'Hi there'
        maxRetries: 5
```

要点：

- 加载时按 schema 校验，非法配置**加载失败并报错**（fail loud）。
- 不要导出普通对象当 `Config`（不满足 Standard Schema 接口）；严格校验用
  `Schema.string().required()`、`Schema.union(['fast','accurate'])` 等。
- **约定：无硬编码可调参数**——凡部署间可能不同的值都做成配置字段
  （检验标准：不改代码，能否在 cordis.yml 里改掉它？）。
- 配置变更触发插件热替换（HMR）：旧实例卸载（注册全部清理）、新实例加载。

## 5. 事件系统

出处：`docs/user/develop/framework/events.md`。

```ts
// 监听
ctx.on('event-name', (payload) => { /* ... */ })

// 广播（返回值被忽略）
ctx.emit('event-name', payload)

// 短路：第一个非 null/false/undefined 的返回值胜出
const result = ctx.bail('some-check', input)

// 顺序执行：按注册顺序，第一个有效返回值停止后续
await ctx.serial('setup-phase', ctxArg)

// 管道：必须调用 next()，否则短路
const output = await ctx.waterfall('transform', input, async () => input)
```

### 5.1 类型化事件（声明合并）

```ts
import '@deepseek-ai/cordis'

declare module '@deepseek-ai/cordis' {
  interface Events {
    'my-plugin/ready': (payload: { id: string }) => void
    'my-plugin/check': (input: string) => boolean | undefined
    'my-plugin/transform': (input: string, next: () => Promise<string>) => Promise<string>
  }
}
```

### 5.2 约定与区别

- Harness 事件用 `命名空间/动作` 命名（`agent/step`、`tools/result`、`session/event`…）。
- **同名陷阱**：`turn/*`、`step/*`、`tool/call`、`tool/result`、`compaction/*` 是**持久化会话事件**
  （写进 session log 的），不是同名的 Cordis 事件；要观察它们就监听 `session/event` 检查 `event.type`。
- 监听器是 effect：`ctx.on()` 注册的监听器随插件卸载自动移除。
- 所有监听器的失败都会被隔离（一个监听器抛错不影响其他监听器），所以事件监听器里不用担心把应用搞崩。

### 5.3 观察型插件示例

```ts
import type { Context } from '@deepseek-ai/cordis'
import type {} from '@deepseek-ai/dsh-tools'   // 引入声明合并，让事件有类型

export const name = 'tool-logger'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.on('tools/result', (exec, result) => {
    const text = result.content
      .map(block => (block.type === 'text' ? block.text : ''))
      .join('')
    console.log(`[tool-logger] ${exec.name} -> ${text}`)
  })
}
```

## 6. 服务与依赖

出处：`docs/user/develop/framework/service.zh.md`。

### 6.1 使用服务

```ts
export const inject = ['tools']     // 必需依赖：服务缺席时插件不加载
export function apply(ctx: Context) {
  ctx.tools.register(/* ... */)     // apply 执行时依赖一定已就绪
}

// 可选依赖：不写 inject，用 ctx.get() 现场查询
export function apply(ctx: Context) {
  const metrics = ctx.get('metrics')
  metrics?.record('plugin_loaded', 1)
}
```

> 约定：可选服务一律用 `ctx.get(name)`（保留 `ctx.<name>` 给声明过 inject 的服务；
> 属性代理是拓扑敏感的，`ctx.get` 读全局服务存储）。

依赖行为：必需服务消失（提供方被替换/卸载）→ 依赖它的插件自动 dispose；
服务恢复 → 自动重载。

### 6.2 提供服务（Service 基类）

```ts
import { Service, type Context } from '@deepseek-ai/cordis'

declare module '@deepseek-ai/cordis' {
  interface Context {
    metrics: MetricsService
  }
}

export default class MetricsService extends Service {
  static inject = ['llm']            // 服务本身也可以依赖其他服务
  constructor(ctx: Context) {
    super(ctx, 'metrics')            // 'metrics' 即服务名
  }
  record(event: string, value: number) { /* ... */ }
}
```

加载后其他插件即可 `ctx.metrics.record(...)`。

### 6.3 服务隔离

同一服务可以有多个实例，不同插件组看到不同实例（`isolate`）：

```yaml
- id: group-a
  name: '@deepseek-ai/cordis-plugin-group'
  group: true
  isolate: { shell: true }
  config:
    - name: '@deepseek-ai/dsh-bash-local'
      config: { timeoutMs: 5000 }
    - name: './src/plugin-a.ts'
```

### 6.4 Harness 内置服务

`tools`、`llm`、`agents`、`sessions`、`fs`、`shell`、`subagent`、`web`、`workflow`…
服务名、公开方法与源码位置由仓库自动生成在各**子系统页面**（`source/docs/subsystems/`）。
开发时以生成区块和 TypeScript 接口为准，不要手抄清单。

## 7. 开发一个工具

出处：`docs/user/develop/basic/tool.zh.md`、`docs/cordis-tutorial/07-into-the-harness.zh.md`。

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'greet-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet someone by name.',
    parameters: {
      name: { type: 'string', required: true, description: 'The name to greet' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      return `Hello, ${args.name}!`
    },
  }))
}
```

工作机制：

- `inject: ['tools']` 等待工具注册表就绪；
- `defineTool` 把 `parameters` 转成模型可见的 JSON Schema，推导 `args` 类型，
  并在 `execute` 前校验模型传参（非法参数走标准错误结果，不会打崩循环）；
- `execute` 返回 `output.schema` 声明的规范值；`output.render` 把规范值渲染成
  面向模型/可持久化的内容块（`[{ type: 'text', text }]`）。
- 注册自带 disposer：插件卸载时工具自动注销。

**驱动一次真实执行**（不用模型，直接走流水线）：

```ts
import { CallId } from '@deepseek-ai/dsh-llm'

const result = await ctx.tools.execute({
  callId: CallId('demo-1'),
  name: 'greet',
  arguments: { name: 'Cordis' },
  signal: new AbortController().signal,
})
```

更完整的工具编写（嵌套 schema、后台工作、策略钩子、Code Mode、UI 卡片）见
[cookbook/adding-a-tool](../source/docs/cookbook/adding-a-tool.md)。

## 8. 插件生命周期

出处：`docs/user/develop/framework/index.zh.md`。

### 8.1 Fiber 状态机

```
PENDING → LOADING → ACTIVE
                 ↘ FAILED
ACTIVE → UNLOADING → DISPOSED
```

| 状态 | 含义 |
|---|---|
| PENDING | 已声明，但所需依赖未就绪 |
| LOADING | 依赖就绪，正在执行 `apply` |
| ACTIVE | 运行中 |
| FAILED | `apply` 抛异常 |
| UNLOADING | 正在卸载并释放资源 |
| DISPOSED | 已完全卸载 |

### 8.2 关键语义

- **依赖驱动加载**：`inject` 不满足就一直是 PENDING，日志不报错也不执行。
- **嵌套上下文**：`ctx.plugin(childPlugin)` 创建子 Fiber，继承父上下文、独立生命周期、随父卸载。
- **dispose**：`await fiber.dispose()` 提前终止实例——移除其全部注册、递归卸载子插件、
  Promise 在所有异步清理完成后兑现。
- **自动清理**：`ctx.on` / `ctx.tools.register` / `ctx.llm.registerAdapter` / `ctx.effect` 全被追踪；
  卸载时按注册逆序开始调用 disposer，但多个异步 disposer 并发执行；
  **有顺序依赖的清理必须放进同一个 `ctx.effect()` 里串行等待**。
- **HMR**：配置变化或源码变化（配 `@deepseek-ai/cordis-plugin-hmr`）→ 卸载旧实例 → 加载新实例，
  不会残留旧注册。

## 9. 能力的三种角色（进阶模式）

出处：`docs/user/develop/practice/index.zh.md`。

当一项能力需要**可替换的提供方**（例如 Bash 执行）时，拆成三种角色：

| 角色 | 例子 | 职责 |
|---|---|---|
| Service Definition | `dsh-shell` | 定义 Cordis 服务 + 请求/结果类型 |
| Service Provider | `dsh-bash-local` | 提供实现（可替换） |
| Consumer | `dsh-tool-bash` | 把能力暴露为模型可调用的工具 |

```
dsh-shell(definition) ──▶ dsh-bash-local(provider)      dsh-tool-bash(consumer/tool)
     ▲                                                            │
     └────────────────────────────── inject: ['shell'] ◀──────────┘
```

- 换提供方时 Definition 和 Consumer 都不用改（在 cordis.yml 换一行包名即可）。
- Provider 依赖 Definition；Consumer 依赖 Definition；Provider 与 Consumer 互不依赖。
- **不要预防性拆分**：简单工具插件一个包就够了；角色需要独立演进时才分。
- Service Definition 拥有 Request/Result 类型；默认值用显式 `resolve(request): Spec`，
  不要藏在 `run()` 里写 `?? default`。
- 内置能力清单见 `source/docs/capability-seams.md`。

## 10. 打包与安装（bundle / profile）

出处：`docs/user/develop/basic/publish.zh.md`。（操作细节见装卸指南）

两个概念、两种 manifest：

- **组合包（bundle）**：附带一个配置层的 npm 包，`package.json` 声明 `dsh.bundle.patch`，
  回答“这个包贡献什么层”。
- **profile**：`$DSH_HOME/profiles/<name>` 下的可启动组合目录，`package.json` 声明
  `dsh.profile.bundles`（有序列表），回答“由哪些组合包按什么顺序组成”。

bundle 目录结构：

```
hello-plugin/
├── package.json       # 声明 dsh.bundle
├── cordis.patch.yml   # 配置层：按包名引用插件行
└── index.js           # 插件模块
```

```json
{
  "name": "dsh-hello-plugin",
  "version": "0.1.0",
  "type": "module",
  "main": "index.js",
  "files": ["index.js", "cordis.patch.yml"],
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

```yaml
# cordis.patch.yml —— 插件行按包名引用（Node 模块解析找到已安装代码）
- insert:
    - id: hello
      name: dsh-hello-plugin
```

安装进 profile：`dsh plugin --profile demo add ./hello-plugin`。

### 10.1 加载顺序（层优先级）

1. profile `dsh.profile.bundles` 里的各 bundle patch（按列表顺序）
2. profile 自己的 `cordis.patch.yml`
3. home 级 `$DSH_HOME/cordis.patch.yml`（所有 profile 共享）
4. 每个 `--patch <path>` overlay（按 argv 顺序）

后应用的层按行胜出；patch 会**整体替换**目标行的 `config`（不是深合并），
按 id 覆盖前层行时必须重述该行的每一个键。

### 10.2 从 GitHub 安装

`dsh plugin --profile demo add github:you/hello-plugin` 拉的是源码、不跑 build：

- **作者**要提供自包含的 `prepare` 构建脚本（git 安装后由 pnpm 运行）。
- **用户**要在 profile 的 `pnpm-workspace.yaml` 授权（pnpm ≥10 默认拒绝）：

  ```yaml
  allowBuilds:
    dsh-hello-plugin: true
  ```

- 该授权 = **允许对方代码在安装时于本机执行**，只对可信源码授权并锁定 commit。
- 不想让用户授权就分发构建产物：**发布 npm**（`pnpm publish` 前构建好 `lib/`）
  或 **tarball**（`pnpm pack` → `dsh plugin add ./xxx.tgz`）。

## 12. 本机环境差异（Windows 实操补充）

以下为本机（`D:\Tools\DeepSeek Harness`，Node 24）开发时的差异与坑，官方文档未覆盖：

1. **绝对路径必须用 file:// URL**：patch 行 `name` 写 `D:/x/y.ts` 会报
   `ERR_UNSUPPORTED_ESM_URL_SCHEME`（被当成协议 `d:`）；正确写法
   `file:///D:/x/y.ts`（空格要 `%20` 编码）。POSIX 下 `/abs/path.ts` 不受影响。
2. **`.ts` 插件直接可加载**：Node ≥ 22.19 原生类型剥离，`.ts` 文件无需构建；
   但只支持**可擦除语法**（无 enum/namespace/参数属性）。
3. **零依赖插件模式**：`import type { Context } from '@deepseek-ai/cordis'` 在
   类型剥离阶段被整体擦除，不产生运行时解析，因此本地插件可以只依赖 Node 内置模块。
4. **命名导出规则**：函数形态插件只写命名导出（`name`/`inject`/`Config`/`apply`），
   勿混 default 导出。
5. **`dsh plugin add` 的空格路径坑**：Windows 下带空格的目录路径会被
   拆成多个参数导致装错依赖，改用 npm 包名、无空格路径，或直接编辑 patch 行
   （详见[装卸指南](插件装卸使用指南.md)）。
6. **插件异常会被隔离**：事件监听器抛错不会打崩应用（Cordis 按监听器隔离）；
   想让进程真崩溃需要未捕获异常/`process.abort()` 之类的极端手段。
7. **验证命令**：`dsh web --dump-config` 打印组合后的完整配置树（含用户层）、
   `dsh web --dump-default-config` 只打印 bundle 层——装完插件先 dump 再启动。
