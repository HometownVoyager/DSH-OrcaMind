# DeepSeek Harness 插件装卸使用指南（本机版）

> 面向本机安装（`D:\Tools\DeepSeek Harness`，Windows，Node 24，DSH_HOME=`C:\Users\HometownVoyager\.dsh`）。
> 本文只讲**装 / 卸 / 启用 / 禁用 / 验证 / 排障**；插件怎么写请看
> [插件开发指南](插件开发指南.md)。
> 机制层面的官方依据：[打包与安装](../source/docs/user/develop/basic/publish.zh.md)。

## 1. 本机环境速览

| 项 | 值 |
|---|---|
| Harness 根目录 | `D:\Tools\DeepSeek Harness` |
| 源码 checkout | `D:\Tools\DeepSeek Harness\source` |
| DSH_HOME | `C:\Users\HometownVoyager\.dsh`（环境变量 `DSH_HOME` 已设置） |
| 正在用的 profile | `web`（目录 `C:\Users\HometownVoyager\.dsh\profiles\web`） |
| 启动方式 | `启动-Harness.bat` / `scripts/start-harness.sh` → `node source\apps\cli\lib\bin.js web --port 3080` |
| CLI 入口（`dsh` 不在 PATH） | `node "D:\Tools\DeepSeek Harness\source\apps\cli\lib\bin.js" ...` 或 `"D:\Tools\DeepSeek Harness\node_modules\.bin\dsh.cmd" ...` |
| pnpm | `%APPDATA%\npm\pnpm.CMD`（PowerShell 默认禁止运行 `pnpm.ps1`，用 `.CMD` 或 cmd） |
| Node | 24.x（原生类型剥离，`.ts` 插件直接加载） |

下文用 `dsh` 代表上面任一 CLI 入口，例如：

```powershell
# 本机实际写法（二选一）
node "D:\Tools\DeepSeek Harness\source\apps\cli\lib\bin.js" web --dump-config
& "D:\Tools\DeepSeek Harness\node_modules\.bin\dsh.cmd" web --dump-config
```

## 2. profile 长什么样

`web` profile 目录下有四个文件：

| 文件 | 作用 | 能改吗 |
|---|---|---|
| `cordis.yml` | 空配置根 `[]`，由补丁层逐层组合 | **不要改** |
| `cordis.patch.yml` | **你的用户补丁层**——本地插件主要装在这里 | ✅ 改这里 |
| `package.json` | `dsh.profile.bundles` 有序列表（官方 bundle 层）+ pnpm 依赖 | 一般由 `dsh plugin` 自动维护 |
| `pnpm-workspace.yaml` | pnpm 工作区配置（git 安装授权 `allowBuilds` 写这里） | 需要时改 |

**层叠顺序**（后写的赢）：

```
① bundles 各组合包 patch（package.json 列表顺序）
② profile 的 cordis.patch.yml        ← 你主要操作的一层
③ $DSH_HOME/cordis.patch.yml（全 profile 共享，本机未建）
④ --patch 覆盖层（一次性，按参数顺序）
```

规则：patch 按行 `id` 覆盖前层；覆盖 = **整体替换**该行（config 不深合并，重述时要写全所有键）。

## 3. 装法 A：patch 行直装（本地插件，推荐）

适用：插件源码在本机（比如放在 `Plugin Contain\` 里）。好处：**热生效**、无需 pnpm、随时可逆。

编辑 `C:\Users\HometownVoyager\.dsh\profiles\web\cordis.patch.yml`：

```yaml
- insert:
    - id: my-plugin                       # 稳定 id，之后装卸都用它
      name: 'file:///D:/Tools/DeepSeek%20Harness/Plugin%20Contain/MyPlugin/index.ts'
      # config: { ... }                  # 可选配置（见开发指南第 4 节）
      # disabled: true                   # 想装但不生效就加上这行
```

`name` 三种写法：

| 写法 | 示例 | 适用 |
|---|---|---|
| `file://` URL（Windows 必用） | `file:///D:/Tools/DeepSeek%20Harness/...` | 本机绝对路径，空格用 `%20` |
| 绝对路径（POSIX） | `/home/me/plugin/index.ts` | Linux/macOS |
| 包名（bare） | `@scope/package` 或 `dsh-plugin-x` | 已用 pnpm 装进 profile 的包 |

> **Windows 坑**：写 `D:/...` 会报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`（被当成协议 `d:`），必须 `file:///`。

**热生效**：运行中的 DSH 会监视 `cordis.patch.yml`——增删行、改 `disabled`、改 `config`
都会被**即时应用**（新增行即加载插件、删行即卸载、改配置即热替换），不用重启。
（`package.json` 的变化则必须重启 DSH 才生效。）

## 4. 装法 B：官方 bundle 流程（`dsh plugin add`）

适用：npm 包、git 仓库、或想用官方标准流程管理。参考生态样例
[dsh-routing-suite](https://github.com/yjh051108/dsh-routing-suite) 的安装链。

```powershell
dsh plugin --profile web add <npm包名 | 目录 | git 地址 | tarball>
```

本质：在 profile 目录里转发给 pnpm 执行；装上的包如果声明了 `dsh.bundle.patch`，
`dsh` 会自动把它追加进 `package.json` 的 `dsh.profile.bundles`（成为第 ① 层）。
**装完要重启 DSH 生效**。

```powershell
# npm 包
dsh plugin --profile web add some-dsh-plugin

# git 仓库（见下方 allowBuilds 授权）
dsh plugin --profile web add github:you/hello-plugin#<commit-sha>

# tarball
dsh plugin --profile web add ./hello-plugin-0.1.0.tgz

# 卸载（依赖和 bundle 层一起移除，需重启）
dsh plugin --profile web remove some-dsh-plugin
```

### 4.1 本机坑：路径带空格会装坏

实测 `dsh plugin add "D:\Tools\DeepSeek Harness\Plugin Contain\DSH-Crash"` 会被拆成
`DeepSeek`、`Harness\Plugin`、`Contain\DSH-Crash` 几个**错误依赖**写进 profile 的
`package.json`（CLI 在 Windows 下向 pnpm 转参数时空格转义失效）。规避方法：

1. **用不带空格的路径**（先复制/软链到 `C:\dsh-plugins\...` 再 add）；
2. **用 npm 包名 / git / tarball**（无空格问题）；
3. 本地插件干脆用**装法 A**（patch 行直装，官方教程同样支持，且热生效）；
4. 若已装坏：手动删掉 `profiles\web\package.json` 里的错误依赖、
   清理 `profiles\web\node_modules` 里的残留链接，再重试。

### 4.2 git 安装需要 build 授权

git 安装拉的是源码，靠作者包里的 `prepare` 脚本构建；pnpm ≥10 默认拒绝执行：

```yaml
# profiles\web\pnpm-workspace.yaml
allowBuilds:
  dsh-hello-plugin: true
```

> 授权 = 允许对方代码**在安装时于本机执行**。只对可信源码授权，并锁定 commit。

## 5. 装法 C：一次性覆盖层（不写入 profile）

```powershell
dsh web --patch ./my-patch.yml
```

只对本次启动生效，适合临时试插件。patch 文件格式与 `cordis.patch.yml` 相同
（`- insert: [...]`）。

## 6. 卸载与禁用

| 装的姿势 | 卸载 | 立即生效？ |
|---|---|---|
| A：patch 行 | 删掉 `cordis.patch.yml` 中对应行 | ✅ 热卸载 |
| B：`dsh plugin add` | `dsh plugin --profile web remove <包名>` | ❌ 重启后 |
| C：`--patch` | 不带该参数重启 | ✅ 重启即无 |

**只想暂时关掉（不删配置）**：给对应行加 `disabled: true`：

```yaml
- insert:
    - id: my-plugin
      name: 'file:///D:/.../index.ts'
      disabled: true        # 保留行、跳过加载；改回 false 即恢复
```

`disabled` 是行级开关，热切换，比删除更安全——想“先装好、暂不启用”就用它。

## 7. 验证与排障

### 7.1 先看配置树再启动

```powershell
dsh web --dump-config          # 组合后的完整树（含你的用户层）
dsh web --dump-default-config  # 只看 bundle 层（不含用户层）
```

装完插件先 dump，确认你的行在不在、`disabled` 对不对。其他 profile 用
`dsh --profile <name> --dump-config`。

### 7.2 插件装了但不跑

- **一直 PENDING（无报错）**：它 `inject` 的依赖服务没有提供方。检查 cordis.yml 里
  是否缺了对应服务提供方（如工具插件需要 `@deepseek-ai/dsh-tools` + system-prompt 提供方）。
- **`failed to load loader entry <id>`**：模块解析失败——`name` 写错（Windows 检查 `file:///`）、
  包没装进 profile 依赖、或 `.ts` 用了不可剥离语法。
- **`dsh plugin add` 后没生效**：bundle 层变化要**重启 DSH**。
- **配置改了没生效**：`cordis.patch.yml` 是热应用；`package.json` 不是。
- 看日志：启动终端会打印 `load / unload plugin <name>` 与失败原因。

### 7.3 命令速查

```powershell
# 看组合后配置
dsh web --dump-config

# 官方包管理（= pnpm 转发 + bundle 层对账）
dsh plugin --profile web add <pkg|dir|git|tgz>
dsh plugin --profile web remove <pkg>
dsh plugin --profile web update <pkg>

# 临时试插件
dsh web --patch ./my-patch.yml
```

## 8. 常见坑速查

1. Windows 绝对路径必须 `file:///D:/...`（空格 `%20`），不能写 `D:/...`。
2. `dsh plugin add` + 带空格路径 = 装坏依赖；用包名/tarball/无空格路径或 patch 行。
3. 函数形态插件只写命名导出（`name`/`inject`/`Config`/`apply`），勿混 default 导出。
4. patch 覆盖是整行替换，改别人 bundle 的行要重述全部键。
5. 改 `package.json`（bundle 层）必须重启；改 `cordis.patch.yml` 热生效。
6. PowerShell 里 pnpm 用 `pnpm.CMD`（`pnpm.ps1` 被执行策略禁掉）。
7. 装 git 插件前确认 `allowBuilds` 授权（= 对方代码在安装时执行）。
8. 插件监听器抛错不会搞崩应用（Cordis 隔离监听器失败）——想让应用崩溃是另一回事。
