# VN 工作流现行规范（2026-11-10 起）

> 本文件是 VN 七预设**唯一的人类可读现行规范入口**，取代长篇 `VN-工作流改造施工文档.md` 与短篇 `VN-工作流改造说明.md`（两份已于 2026-11-17 随归档清理删除，历史决策要点以本文件与 git 记录为准。）
> 运行时真正生效的是：`cordis.patch.yml` 里 7 个 `preset-vn-*` 的 persona `prefix`（system 通道，order=0）与 `skills/vn-shared/` 三份 SKILL.md。本文件把它们**转录为一份人读规范**，本身不新增、不覆盖任何运行时规则；运行时冲突一律以 persona【指令裁决】段为准，不在本文件里另立第二套规则。

## 1. 指令裁决（最高优先级，写在每个 persona 开头）

1. 约束分两类：
   - **硬红线**（仅三条）：① 不跨阶段写入（不写下游、不改写上游已确认内容）；② 不创建 6 编号目录 + 3 根级文档白名单之外的文件；③ 不自行把 README 状态置「已确认」。
   - **默认工作节奏**：除上述三条外的一切流程、步骤、提问与确认节奏，均可被用户显式指令覆盖。
2. 用户指令与【默认工作节奏】冲突 → 以用户为准，直接执行；用户已在同一条消息里写明范围/做法 → 视为已确认，不重复提问。可一次性授权「一次做完多个子条目 / 跳过逐轮确认」。
3. 用户指令与【硬红线】冲突 → 不擅自执行、不反复自辩：一句话点明冲突，给「按我说的做（已知悉风险）/ 保持红线」二选一，由用户拍板。
4. 引用的三份共享 skill 与 persona 冲突 → 以 persona 为准；skill 之间冲突 → `vn-gate`（流程）> `vn-spec`（目录与格式）> `vn-continuity`（核查）。
5. 不确定某条是否生效 → 按本段裁决，不回头溯源旧文档、旧行号或已 `disabled` 的旧预设。
6. 措辞以「默认 / 除非用户明确要求」为主，不因未用绝对化措辞而怀疑规则失效。

## 3. 默认每轮节奏

```
Read → Report → Confirm → Do → Check → Write → Stop
```

- **本轮批量（2026-11-13 起）**：`vn-script` 一轮写 **1~4 章**连续正文，章数不定——用户写明范围时按指令，未写明时由 agent 在 1~4 内自主声明并在 Report 报出，不必每轮追问；其余 6 预设默认 1 个子条目；用户显式授权可超上限。各子条目独立写入、独立核查、独立在 README B 区记一行（一行一产物，只追加）。
- **有限创意主动性（2026-11-13 起）**：上游已确认事实绝不改动；仅当上游骨架留白、素材不足以支撑本轮产物时，可主动给 2-3 个标注「推测 / 待拍板」的候选写法请用户拍板，候选只入对话或本阶段 `Draft/` 零散草稿，不混入正式产出、不补写上游事实。

- **Read 固定顺序**：① 读 `README.md` 状态机（校验「当前预设」）② 首轮另显式读一次 `Specifications.md` 与 `Direction.md` ③ 读本阶段已有产物。多个「必须先」不再争第一。
- **Report**：报当前阶段 / 已完成 key / 本轮待办子条目；可附 ≤3 个下一候选标题（只列标题、不展开）。「列标题」不算规划后续子条目；写字段/草案/设计建议才算。
- **Confirm**：默认用 `ask_user_question` 确认本轮范围；用户已写明范围时跳过。
- **Do / Check / Write**：只做被确认的子条目；按 `vn-continuity` 逐个核查本轮各产物及其**直接上游已确认文件**（不探测下游、不做全链体检）；写本轮各产物文件 + README A 区 5 字段 + B 区按本轮子条目数追加对应行数（状态「待确认」）。
- **Stop**：停下，报告本轮结果，列出下一候选标题，等下一轮指令。

**本轮工具调用顺序不设固定末位不变量**。报告、`present` 交付、README 状态登记都是正常步骤；状态登记默认在下一轮 Read 之前完成，不存在「提问后不得写文件」的时序矛盾。

## 4. README 双区状态机

A 区「当前状态」5 字段：`当前预设` / `当前阶段` / `本轮子条目` / `状态` / `下一候选`（就地更新）。
B 区「进度记录」：只追加、不改写或删除既有行。
状态：`进行中` → `待确认`（Write 完成）→ `已确认`（用户明确认可后由 AI 代为登记）→ `进行中`（下一轮）。AI 默认不自行置「已确认」。
阶段切换 = 用户手动切换预设 + README `状态=已确认`（用户显式指令可覆盖）。

## 5. 跨阶段边界

- 每个预设只写自己那一列；上游只读；下游默认不读、不写、不创建、不替其做设计。
- 锁 1 由配置保证：`customSkillDirs` 只挂 `vn-shared` + 本阶段 skill，物理上看不到下一阶段 skill。
- 上游发现缺漏 → 停下询问，不回写、不补全。
