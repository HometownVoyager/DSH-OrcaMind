# 资产清单（game-asset-list）

## 何时使用
- 项目处于资产清单阶段（阶段5），或需要按新设定补充、修订资产清单时。
- 用户询问「做这款游戏要多少美术/音频工作量」「先做哪些资产」时。

## asset-list.md 模板（05-资产/asset-list.md）
```markdown
# 资产清单

## 总表
| 编号 | 分类 | 名称 | 规格/说明 | 数量 | 优先级 | 依赖 | 服务需求（追溯） |
|------|------|------|-----------|------|--------|------|------------------|

## 工作量估算
| 分类 | 条目数 | 折算工作量（人日或相对单位） | 依据 | 备注 |

## 缺口与取舍
| 缺口 | 影响的玩法/内容 | 候选处置（补做/替代/砍掉） | 代价 | 用户裁决 |
|------|------------------|----------------------------|------|----------|

## 编制说明
- 估算口径：<人日折算方式或相对单位定义，是否含迭代与返工系数>
- 优先级依据：<为什么这些排 P0>
- 本次范围外：<明确不做的部分与原因>
```

## 分类明细（05-资产/notes/）
- model.md：模型——角色、单位、道具、场景物件；规格（面数区间/风格统一要求/是否需要绑定骨骼）。
- anim.md：动画——动作清单（移动/战斗/交互/表情）、数量、是否共用骨架、变体与差分需求。
- vfx.md：特效——技能与反馈特效清单、触发情境、表现强度分级。
- ui.md：界面——主菜单、HUD、对话框、背包与成长界面、数值展示与交互说明；标注哪些数值需要实时可视化（引用 01-系统/ 的字段）。
- audio.md：音频——音乐（曲目、情绪与场合、时长与循环点）与音效（列表、触发情境）分列。
- scene.md：场景——关卡与地点场景清单（来自 02-世界观/geography.md 与 03-大纲/），构图要点、规格、是否需要多状态（昼夜/破坏/阶段变化）。
- config.md：配置表——数值表、掉落表、任务表、文本表等数据结构与字段说明（与 01-系统/、03-大纲/ 的编号对应）。
- text.md：文本量——对白、旁白、界面文案、本地化的字数估算与语种清单（仅估量，不产出文本内容）。

## 优先级约定
- P0：主线必需资产（无则无法完成核心循环）。
- P1：重要旁支与常用变体（影响体验完整度）。
- P2：补充变体与点缀（有余量再制作）。

## 执行步骤
1. 依次盘点五个阶段的全部产出，把每个需求映射到资产条目；每条资产写明它服务哪个玩法系统或内容条目（可追溯）。
2. 按分类开列清单，逐项写明规格与数量；规格写到可直接交付制作或外包的程度（分辨率、面数区间、时长、交付格式）。
3. 编制工作量估算并写明口径；估算不含口径说明的条目视为未完成。
4. 与用户确认范围与预算取舍；超预算时列取舍方案（补做/替代/砍掉）逐项说明代价，请用户裁决。
5. 缺口回指：发现某需求在前四阶段没有对应设计时，回指对应阶段文档补设计，而不是在清单里自创设定。

## 注意事项
- 资产清单是对前四阶段一致性的最终检验：每条资产都能追溯到一个玩法或内容需求；追溯不到的条目列为候选并请用户裁决，不直接删除也不默认保留。
- 文本量只做估算与语种规划，不产出对白文本（红线见 persona）。
- 规格与数量避免伪精确：无法确证的给区间并标注「待确认」，不以单点数字充作已定。
- 用户已有团队资产规范（命名、规格、交付格式）时从其规范，并在 规范-游戏设计.md 的产出格式规范节登记引用。
