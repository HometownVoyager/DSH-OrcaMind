# 头脑风暴（game-brainstorm）

## 何时使用
- 项目处于 Brainstorm 阶段（阶段1），或用户要求回到创意原点重新讨论定位时。
- 已有零散创意（一个画面、一种情绪、一句玩法描述）需要整理成可推进的方向时。

## 本阶段边界
本阶段只回答「这是一款什么样的游戏、要让玩家获得什么体验」，不写系统规则、数值、关卡结构与具体剧情；发现这些想法时记入开放问题或候选方向，留给后续阶段。本阶段的产出是后续所有阶段的锚点，后续内容冲突时先回溯到这里。

## brainstorm.md 模板（00-创意/brainstorm.md）
```markdown
# Brainstorm：<暂定名>

## 核心创意
一句话说明玩法前提：玩家扮演谁、在什么处境里、反复做什么、为什么这件事值得做。

## 主题与立意
作品想探讨的核心主题，以及主题在玩法与体验上的落点（不是文案口号，而是玩家会亲身做出的选择）。

## 情绪基调
主基调（如紧张、治愈、壮阔、压抑、荒诞）与情绪变化范围。

## 目标体验
玩家体验目标（心流/成就感/探索欲/情感冲击/社交联结），对应的目标平台、单局或单次会话时长与预计总时长。

## 类型与品类融合
主类型与融合类型，每种类型各自提供的体验，以及融合的相容性判断（两类玩法的操作节奏与奖励预期是否冲突）。

## 核心卖点
与同类作品相比的差异化，以及目标受众的期待点；至少写出一条可被验证的差异（机制差异/题材差异/结构差异），不写「更精美」「更爽」类不可验证的卖点。

## 制作约束（已知）
团队规模、周期、预算与引擎条件的已知信息，标注来源（用户提供/待确认）。

## 开放问题
未决的创意缺口与候选方向。
```

## 执行步骤
1. 先请用户说出已有的想法，哪怕只是零散的关键词、画面、情绪或参考作品。
2. 按模板把素材组织成候选方向（通常给出 2-3 个有差异的方向供选择），每个方向点明它提供的体验、对应的品类与参考区间。
3. 每个方向写明代价与收益：操作复杂度、上手门槛、内容体量、长线可扩展性与制作成本，请用户裁决后再写入正式文档。
4. 方向选定后，与用户确认目标平台与体验目标——它们是后续系统与关卡设计的基准参数。

## 注意事项
- 用户未明示的创意缺口列进开放问题，不自行补全后直接写进正文。
- 类型惯例、市场表现与同类作品参考可用联网搜索（按 search-query-craft 构建检索词），必须注明来源，并区分事实信息与设计建议。
- 核心卖点不接受不可验证的表述：说不清「玩家因此会做出什么不同行为」的卖点，先列入开放问题。
- 本阶段不写玩法细节与数值：出现具体机制时，记录其所属阶段（核心玩法与系统设计），不在本阶段展开。
