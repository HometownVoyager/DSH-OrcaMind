# 内容大纲（game-content-outline）

## 何时使用
- 项目处于内容大纲阶段（阶段4）的总纲搭建，或需要修订、扩展已确认的章节结构与事件序列时。
- 需要把系统与世界观产出组织成一条可体验的内容线时。

## 与 game-level-design 的分工
本 skill 负责**总纲**：章节职能、事件序列、冲突升级、节奏曲线、关系变化、结局方向，以及结构表的维护；关卡与任务级细化（关卡目标与失败条件、任务目标链、单位投放）转 game-level-design。两者使用同一份 03-大纲/content-outline.md 的不同小节：本 skill 写总纲各节，game-level-design 续写关卡与任务各节。红线（不写台词与脚本实现）对两份内容一律适用。

## content-outline.md 模板（03-大纲/content-outline.md）
```markdown
# 内容大纲

## 一句话内容线
玩家从 <起始处境> 走到 <终点处境> 的主线一句话；说明驱动力（能力成长/内容开放/叙事推进/社交目标）。

## 章节结构
| 章节 | 职能（引入/铺垫/转折/高潮/收束） | 关键事件（抽象） | 涉及系统 | 节奏定位 | 预计时长 |

## 主要事件序列
按因果链排列的抽象事件节点，不写场景与台词；每个节点标注它推进的是主线、角色关系还是系统解锁。

## 冲突与难度升级
外部冲突与内部冲突（或玩家压力）的升级阶梯：压力如何逐级加大；每次升级的前置铺垫在哪个节点。

## 节奏与情绪曲线
情绪与强度的起伏曲线与转折点；张弛交替的位置与依据（引用 01-系统/progression.md 的阶段划分）。

## 关系与立场变化
主要关系与阵营立场的变化节点与方向。

## 结局方向
可能的结局与主题落点；分支或差异结局的触发条件所在层级（条件细化的落点在 01-系统/ 或关卡条目，不在此处写数值）。

## 系统解锁映射
内容节点与系统解锁点的对应表（节点编号 → 解锁项 → 引导责任所在关卡）。

## 开放问题
```

## structure.md —— 结构表（03-大纲/structure.md）
跨内容一致性的地基表，至少含四列：内容条目编号 / 节奏定位 / 涉及系统与解锁点 / 前置依赖。新增条目必须先在本表登记再写入大纲正文；结构表与大纲正文不一致时以结构表为准并修正正文（先经用户裁决）。

## 执行步骤
1. 先与用户确认结局方向与整体体量，再搭章节骨架。
2. 填事件序列，逐条检查因果链是否闭合、情绪曲线是否有起伏；因果断点与平坦段当场标出。
3. 复核与核心循环、系统规则、世界观设定的咬合，冲突先裁决。
4. 建立系统解锁映射，确认每个解锁点都有承担引导责任的内容节点（缺失即列出补设计清单）。
5. 在 03-大纲/structure.md 登记全部条目，并向用户报告本次新增与前置依赖关系，确认后落盘。

## 注意事项
- 触犯红线的段落必须改写为抽象表述后再写入文件；对白与脚本实现不由本预设承担。
- 大纲只回答「发生了什么、为什么、以什么节奏」，不回答「怎么演、怎么说」——具体演出与台词不属本代理的五个阶段。
- 内容条目编号一经确认即稳定，供关卡、资产与核查文档引用；需要改号时按影响面清单逐处更新并登记 04-修订/continuity-log.md。
- 时长预估给出区间并注明依据（目标总时长、单章节期望时长），不写无依据的精确值。
