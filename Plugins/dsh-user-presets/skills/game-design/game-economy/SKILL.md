# 数值与经济（game-economy）

## 何时使用
- 核心循环与玩法系统已确认，需要把机制落成可验算的数值时。
- 用户提出数值问题（成长太快/太慢、资源溢出、某阶段卡关、付费与产出失衡）需要定位与调整时。
- 关卡设计中需要判定期望战力区间、掉落配置或时长目标时（与 game-level-design 联动）。

## 本阶段边界
本 skill 负责**规则化的数值体系**：公式、曲线、区间、流转关系与验算方法。它不负责具体关卡里的一次性数值实例（放 03-大纲/ 引用本文件的口径），也不负责界面上的数值展示设计（放 05-资产/notes/ui.md）。

## 执行步骤
1. 先定口径与基准锚点（单位、取整、目标时长、参照区间）——没有基准的数字无法判断合理与否。
2. 用「最高等级 + 初始等级」两个端点数值确立曲线形态，再插入关键节点；每引入一条公式，立即用一组典型值试算，把结果写进验算记录。
3. 产出与消耗成对设计：每条产出通道都配一条消耗去向，核算期望净流；净流长期为正即标为通胀风险并给出回收口。
4. 与已确认系统逐条核对：每个数值都挂在某个系统规则上（写清对应系统编号），无所属的数值视为待裁决项。
5. 数值变更后重跑验算记录中受影响的行，并在 04-修订/continuity-log.md 登记影响面。

## 注意事项
- **无论据不给数字**：每个关键数值须写明推导依据或参照对象（目标时长、期望通关率、同类区间、试算结果）；无法确证的标注「待确认」，不得给一组看似精确却无依据的数字。
- **可验算**：公式的变量、单位、取整与边界齐全，他人代入数值应当得到同一结果；只给结果不给算法的数值表视为未完成。
- **单一事实源**：数值口径与公式只在 economy.md 维护，关卡与资产文档引用编号而不复制数值；发现两处不一致时以本文件为准并修正引用处（先经用户裁决）。
- **区间优于点值**：成长与掉落给出目标区间与容差，避免用单点精确值造成后续无法调整。
- 曲线形态的选择要说明代价：线性易控但后期乏味、指数有成长快感但易失控，取舍写进文档而不是留给实现端猜测。
