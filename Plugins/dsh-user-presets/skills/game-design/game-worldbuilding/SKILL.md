# 世界观与内容设定（game-worldbuilding）

## 何时使用
- 项目处于世界观与内容设定阶段（阶段3），或需要补充、修订已确认的世界观与角色细节时。
- 关卡设计中需要新增可交互单位、需要确认某单位的能力与行为时（与 game-level-design 联动）。

## world.md 模板（02-世界观/world.md）
```markdown
# 世界观：<世界名>

## 核心规则
世界运转的底层规则；特殊规则（超自然/科技/系统化设定）要写明机制、代价与边界。

## 历史
关键历史事件与因果链，事件之间如何连锁；与游戏内时间轴（timeline.md）的对应关系。

## 社会结构
制度、阶层、文化习俗与日常生活的质感；这些结构如何影响玩家的处境与选择。

## 玩法层关联
世界观规则如何转化为可玩的机制（哪些规则会在系统层被玩家直接操作），以及不转化的设定说明其存在意义。

## 与主题的关联
世界观规则如何服务主题与主线的因果。

## 开放问题
```

## factions.md —— 势力与组织（02-世界观/factions.md）
各势力的名称、定位、目标、资源、组织结构与相互冲突格局；与主要角色的隶属或对立关系；在玩法层的代表（阵营系统、声望、敌对关系表，若有）。与小说、剧本预设同粒度，便于下游直接引用。

## geography.md —— 地理与地点（02-世界观/geography.md）
主要地点列表：名称、位置关系、气候与风貌、功能；标注哪些地点会作为可玩场景（与 05-资产/notes/scene.md 对应），同一地点的空间布局保持一致（入口在哪、通路怎么连），供关卡与资产阶段引用。

## characters/ —— 叙事角色档案（02-世界观/characters/<角色名>.md）
```markdown
# <角色名>

## 档案
- 定位：主角 / 核心配角 / 反派 / 引导者
- 目标：长期目标与当前阶段目标
- 动机：驱动行为的深层原因（与世界观、经历挂钩）
- 性格：核心特质、表面与内在的反差、雷点与软肋
- 形象要点：标志性特征、服装与造型风格（供 05-资产/ 参考，不写美术实现）
- 成长弧线：从起点到终点的变化轨迹，以及在哪个阶段节点发生转折

## 人际关系
与其他角色的关系定位、冲突点与关系变化方向（与 relationships.md 一致）。

## 玩法职能
该角色在系统与内容中承担什么职能（引导者/任务发布/可招募/敌对），与 units.md 的对应条目互相引用。
```

## units.md —— 可交互单位规格（02-世界观/characters/units.md）
```markdown
| 单位 | 类型（NPC/敌人/可招募/中立） | 职能 | 能力与行为 | 弱点与反制 | 出现条件 | 关联关卡 | 数值区间（引用 01-系统/economy.md 编号） |
|------|------------------------------|------|------------|------------|----------|----------|----------------------------------|
```
每个单位另写一小节：行为逻辑（何时进攻、何时撤退、是否协同）、玩家应对方式、可读性设计要点（玩家如何一眼识别其威胁等级）。数值区间引用 01-系统/economy.md 的口径，不在此处另立一套。

## relationships.md（02-世界观/characters/relationships.md）
记录角色与势力间的关系网及变化方向，作为内容大纲与关卡设计的输入。

## 辅助文件
- timeline.md：历史年表，按时间顺序记录已确认事件（世界史与游戏内事件线分开或分栏标注）。
- glossary.md：专有名词表（地名、组织、术语、特殊规则名、单位名），新名词先登记再使用。

## 执行步骤
1. 从核心规则与历史出发搭建骨架，再补地理（geography.md）、社会结构与势力（factions.md）。
2. 逐条自检规则：同一规则在所有场合表现一致，代价与边界清晰。
3. 建立叙事角色档案：先写目标与动机，再写性格与形象要点，最后核对成长弧线是否与主线咬合。
4. 建立单位规格表：先定职能与行为，再写弱点与反制，最后挂上数值区间引用。
5. 与已确认的核心循环、系统规则、角色动机核对，发现冲突先提出裁决。

## 注意事项
- **世界观服务于玩法与叙事**：特殊规则要与系统机制或主线因果挂钩，不堆砌无用的设定；纯背景性设定允许存在，但需说明其存在意义。
- 叙事角色的目标与动机必须形成张力，动机空泛的角色先提出补充问题，不硬写；玩法职能与叙事定位冲突时（如设定为温和角色却要求其担任强敌），先请用户裁决。
- 单位规格中的数值一律引用 01-系统/economy.md 编号，本文件只维护能力与行为描述，避免数值两处各写一套。
- 新增规则或单位影响已确认内容时，先提出确认请求，不得直接改写旧设定。
- 需要事实考据（历史、民俗、军事、科技、行业实操等）时使用联网搜索（按 search-query-craft 构建检索词），注明来源并区分事实信息与设计建议。
