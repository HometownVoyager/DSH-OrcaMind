# 连续性管理（continuity）

## 何时使用
- 每次开始写作前（快速核查本章涉及的设定与上一章的衔接，先对 anchors.md 定向核对本章涉及的年龄/称谓/信物/空间）。
- 每完成一章后（登记新事件、更新伏笔追踪）。
- 每阶段产出落盘前（全量核查一次，锚点矩阵优先）。
- 修改设定后（检查对已写正文的影响）。
- 用户指出"前后矛盾"时（定位并修复）。

## 核查顺序（锚点矩阵优先，定向靶向核查）
从"全文模糊搜"升级为"锚点矩阵核验"：先对 `00-设定/anchors.md` 做**定向靶向核查**，再按需展开全文检索。顺序如下：
1. **锚点核验**：对照 anchors.md 四节，核查本次产出涉及的角色年龄与关键节点、称谓三层口径（叙述指称 / 主观认知称谓 / 对白呼告）、核心资产与体态状态（信物/道具/伤势/装扮）、空间拓扑与动线，逐项比对出现处上下文。
2. **关联基准核验**：对照 timeline.md、glossary.md 与设定集，核查事件日期序列、专有名词。
3. **全文模糊检索（兜底）**：仅在前两步无法定位矛盾时才用检索工具全局搜索关键名/术语，对比出现处的上下文。
4. 正文中出现的新事实反向补录进基准（涉及锚点变更的先请用户确认）。

## 检查清单
1. **锚点·年龄与生理时间轴矩阵**：各角色当前年龄与关键节点年龄是否符合 anchors.md 年龄矩阵；年月日、季节、昼夜、经过天数是否自洽（对照 timeline.md）；生日、成人礼、学段交替处重点核查——这是"16岁与18岁混淆"的高发区。
2. **锚点·称谓三层解耦网格**：叙述指称、主观认知称谓、对白呼告三者是否与 anchors.md 称谓网格一致——叙述称呼与口语称呼各归各层，不得混用或前后打架。
3. **锚点·核心资产与体态状态机**：重要信物与道具从哪来到哪去、当前持有者是谁、所处阶段（对应卷/章节点）是否与 anchors.md 状态机一致，别凭空消失、凭空出现或状态回跳；伤势的出现与痊愈节点、装扮更换是否符合记录；角色不可变体貌（发型/发色/瞳色）是否偏离体貌锚点。
4. **锚点·空间拓扑与动线模型**：上下楼方式（电梯/步梯）、房间位置、门窗朝向、视线与声音遮挡是否符合 anchors.md 空间拓扑；同一场景内的道具、服装、光线、桌面状态、门窗位置跨段一致。
5. 段落衔接：上一章结尾时的人物位置/状态/情绪，与本章开场是否一致（出场/退场、情绪、随身物品）。
6. 人物状态：伤势、能力边界、情绪基线、关系变化、金钱与势力关系。
7. 大纲与设定：行为是否符合人物卡与世界观规则，事件序列是否符合角色动机；章大纲是否只含抽象层级内容（无场景与台词级内容，见 novel-outlining 红线）。
8. 伏笔与多线：已埋伏笔是否有兑现计划与进度；并行线的交汇点是否按期发生、两线事实是否吻合。
9. 时间线与名词：新事件与专有名词以 timeline.md 与 glossary.md 为基准登记。

## 方法
- 每次核查先读 `00-设定/anchors.md`（基准事实层），再读本轮涉及的其他基准文件；锚点核验通过后，用检索工具做针对性抽查与兜底。
- 以 anchors.md、设定集与 timeline.md 为基准；正文中出现的新事实反向补录进基准（涉及锚点变更的先请用户确认）。
- 伏笔与多线交汇点统一在 continuity-log.md 的"追踪事项"小节登记跟踪（见下方模板）。

## 冲突处理
1. 正文与 anchors.md/设定集/大纲不一致、且该正文尚未经用户确认时，以 anchors.md 与设定集为基准修改正文，并在记录中说明；正文已经用户确认的冲突按第 2 条请用户裁决。
2. 冲突涉及 anchors.md 本身、已确认设定、关键剧情走向，或两种口径各有依据时，先指出冲突并说明双方口径的来源，请用户裁决，不得自行改写已确认内容与锚点。
3. 修复后必须在 continuity-log.md 记录：日期、冲突内容、裁决结果、修改了哪些文件；锚点变更必须额外记录"改了什么、为什么、何时"。
4. 批量改名/改设定时：先检索全部出现位置，再逐处替换，最后全局复查一遍。

## continuity-log.md 格式
```markdown
# 连续性记录
## <日期>
- 查证：<冲突内容，如第 12 章与 timeline 相差 3 天>
- 裁决：<以谁为准、为什么>
- 修改：<改动的文件清单>

## 追踪事项
- <伏笔内容> — 埋设：<章节> — 兑现计划：<章节> — 状态：待兑现/已兑现
- <多线交汇点> — 涉及线：<线名> — 状态
```
