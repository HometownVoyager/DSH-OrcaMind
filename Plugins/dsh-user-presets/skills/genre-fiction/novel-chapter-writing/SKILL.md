# 章节正文写作（novel-chapter-writing）

## 何时使用
- 每次撰写新章节正文时。
- 用户要求"写第 n 章""续写"时。

## 动笔前判定
- 先判定本段的文本类型（对白/叙述/内心独白）与文风基调（对照 00-设定/style.md 与 character-voices.md），依据判定选择对应写法。
- 判定所需信息不足时先向用户求证；素材不足以支撑本段内容时，先给候选方案讨论，用户拍板后再正式创作。
- 写新章节或关键场景前，先按本 skill 的「章节起飞检查卡」完成锚点核对，再下笔（见下）。

## 写作前（必做）
1. 读本章章大纲与分卷大纲（或 chapter-structure.md 中本章行）。
2. 读 style.md（文风/视角/禁忌）、pov-craft（视点配置系统与视角纪律）与相关人物卡、声音档案。
3. 读上一章结尾，保持衔接；检索前文关键信息（人名、地点、事件），确认无冲突。
4. 确认本章视点角色与叙事距离，按章头视点声明落盘（模式 2 需声明），全章遵守 POV 纪律与多心声禁令（视点不漂移、不泄漏视角外信息）。

## 章节起飞检查卡（Pre-flight Stamp）——动笔前强制执行

长篇写作中事实漂移的根源是上下文注意力稀释：在输出大篇幅正文前，先"打印并自检"一组关键实体元数据，注意力会被锚定在基准事实上，后续数千字极难产生幻觉与穿帮。

**每写一个新章节或关键场景前**，在规划阶段或草稿头部显式输出检查卡，逐项对照 `00-设定/anchors.md` 与 `规范-创作.md` 核对，核对无误后方可正式下笔：

```markdown
<!-- CHAPTER_PREFLIGHT_START -->
【章节起飞检查卡】
- 章节编号与时段：ch033 / 6月10日 - 6月11日
- 本章视点与叙事距离：庄游火（第三人称限知，不可读取他人内心）
- 物理空间与动线：12楼庄家卫生间与走廊（电梯房）
- 登场角色与年龄：庄游火（17岁末/成人前夕）、夏天风（17岁末/成人前夕）
- 核心称谓核对：叙述指称写"夏天风"，主角对白称"夏大掌柜"
- 关键资产状态：夏天风佩戴海玻璃新绳；微卷中长发挽在脑后（非短发）
- 本章情节功能与钩子：铺垫重逢 / 章末悬念"门后是谁"
<!-- CHAPTER_PREFLIGHT_END -->
```

检查卡字段与 anchors.md 四节一一对应：年龄与生理时间轴矩阵→登场角色与年龄，空间拓扑与动线模型→物理空间与动线，称谓三层解耦网格→核心称谓核对，核心资产与体态状态机→关键资产状态；另加情节功能与钩子一栏（对应 chapter-structure.md 章节功能表）。核对中发现矛盾先回 anchors.md 与用户裁决，不带病下笔。

## 场景与节拍
- 每章由 1–3 个场景组成；每个场景开写前先明确：场景目标（推进哪条线、揭示什么）、进出场（从哪开始、停在哪）、场景内张力曲线（蓄力→爆发→余波，或反之）、场景氛围基调与各角色的心情/唤醒度（低/中/高）。
- 场景内节拍交替：动作与对话交替、外部事件与内心反应交替，避免连续大段独白或连续大段描写。
- 场景切换点也是钩子位：在张力高点或悬念处切走（见 writing-craft 钩子设计）。

## 正文结构
- 开头：承接前文 + 尽快进入本场景（网文尤其忌慢热）。
- 中段：推进冲突或信息，动作与对话交替，避免大段独白。
- 结尾：网文必须留钩子（悬念/承诺/反转/情绪余韵）；实体书可收束场景但留张力。

## 字数
- 网文：每章 2000–4000 字，以用户目标为准（用户指定则从用户）。该区间与下面的节奏建议属**行业经验值，无国家标准或行业标准依据**，只为默认起点；平台或编辑另有要求时一律以其为准。
- 实体书/短篇：无硬性字数，服从场景需要。

## 技法要求
- 展示而非告知：用行动、对话、细节呈现情绪，少直接贴标签。
- 对话个性化：符合声音档案"说话方式"；有潜台词，问答不必对称（细节见 character-voice）。
- 内心独白：遵守角色的独白口径，与叙述有可辨识界线（见 character-voice 与 pov-craft）。
- 感官细节：视觉之外，声音、气味、触觉按需取样，不过度堆砌。
- 氛围与唤醒度：叙述与对白的语气随场景氛围与角色唤醒度起伏——高唤醒度短句快切、身体反应外显，低唤醒度句势放缓但仍有质感；严禁整章死水般的平静语气，平静只在判定必要时段落级使用，并写出平静之下的暗流（细则见 writing-craft）。
- 节奏控制：动作戏短句快切，抒情/内心戏放缓；叙事距离随情节强度切换（见 pov-craft）。
- 信息只写一遍：同一信息用对白、叙述、内心各重复一次是浪费，保留效果最好的那一处。
- 禁 info-dump：设定通过场景自然带出，不整段倾倒。

## 禁忌
- 视角跳变（一章内切换到他人内心）。
- 与设定集/时间线/前文矛盾（写入前自查）。
- 重复用词与句式（同一段内避免"他/她"开头连排）。
- 在正文里写作者注或括号说明。
- 明显注水：凑字数、车轱辘话。
- 翻译腔、处处金句（见 writing-craft）。
- 全章死水般的平静语气：无情绪起伏、无唤醒度变化（平静只在判定必要时段落级使用，见 writing-craft）。
- 密集裸半角波浪号 `~`（日期/天数/章号范围连接统一用 `-`，见「Markdown 范围连接符防灾」）。

## Markdown 范围连接符防灾
在 Markdown 渲染引擎（GFM、Obsidian、Web GUI 等）中，连续半角波浪号 `~` 常被误判为下标或贪婪匹配为删除线，导致文字中间出现划去线。小说正文与全部项目文档中：
- **日期范围**：写 `6月10日 - 6月11日` 或 `6月10日-6月11日`；
- **天数/章号/代号区间**：写 `Day 1 - Day 2`、`第1章 - 第3章`、`ch001 - ch005`；
- **文本禁忌**：严禁在正文排版中密集出现裸半角波浪号 `~`，统一采用半角减号配空格或短横线（`-`）代替。

## 交付
1. 正文写入 `02-正文/卷<n>/ch<三位编号>.md`（如 ch001.md；短篇无分卷时直接放 `02-正文/`）。
2. 更新 README.md 进度记录（按 README 模板列登记，章号与字数并入「完成内容」栏），并同步更新根目录 剧情精述.md 的本章条目与当前进度。
3. 本章新出现的设定/事件/角色：同步到设定集与 timeline.md（一句话即可，别漏）；新伏笔登记进 continuity-log.md 的"追踪事项"。
4. 向用户说明本章要点与下一章衔接，方便用户确认方向。
