# 结构与梗概（novel-structure）

## 何时使用
- 新作品在设定集初步成型后、写大纲之前（或用户要求先规划时）。
- 用户要求"理结构""排节拍""剧情太平/太散/多线收不拢"时。

## 工作顺序
1. logline（01-规划/logline.md）：主角 + 目标 + 障碍 + 代价，一句话。写不出 logline 就不进入下一层。
2. treatment（01-规划/treatment.md）：故事梗概，散文式叙述全篇情节，含结局方向；允许叙述具体情节，但不写死台词。
3. structure（01-规划/chapter-structure.md）：章节功能表与结构设计。
4. outline（01-规划/master-outline.md、volume-<n>.md）：交给 novel-outlining skill 执行，那里有抽象层级红线。

## 动笔前判定与拍板
- 动笔写结构前，先判定文本类型（本阶段产出为规划文档，不是正文）与文风基调（对照 00-设定/style.md），据此按本 skill 的模板正式创作。
- 现有素材不足以支撑结构设计（篇幅、卷章划分、多线走向没有思路）时，先给出 2–3 个候选方向与用户讨论，用户拍板后再写入文件；拍板前的推测标注「推测/待拍板」，不混入正式文档。

## logline.md 模板
```markdown
# 一句话故事
<主角> + <目标> + <障碍> + <代价>
- 卖点：<与同类作品的差异点>
- 目标读者：<一句话>
```

## treatment.md 模板
```markdown
# 故事梗概

## 全篇梗概
按因果顺序叙述主要情节与结局方向；允许具体情节，不写死台词。

## 主要人物弧光
每个主角从哪到哪。

## 主题落点
作品最终把主题落在哪个人物选择/哪个场景上。

## 开放问题
```

## 结构诊断（三幕/起承转合）
- 三幕逻辑：建置（主角常态、欲望、激励事件、不可逆转折点）→ 对抗（障碍升级、中点改变赌注、低谷）→ 高潮与解决（用第一幕建立的东西完成最后对抗）。
- 长篇以卷为单位重复该循环：每卷有自己的起承转合与卷末高潮，卷与卷之间用钩子衔接。
- 每章完成一个情感单位（一次完整的情绪起落），章末留钩子（节奏模型见 writing-craft）。

## chapter-structure.md 章节功能表
```markdown
| 章号 | 功能 | 关键事件 | 情感节奏 | 视点角色 | 伏笔/多线 |
|------|------|----------|----------|----------|-----------|
```
功能取值：引入/铺垫/转折/高潮/收束。每章都能回答「删掉它损失什么」；视点角色与 pov-craft 的「视点配置系统」对齐（章头视点声明）。

## 多线结构设计（多线作品）
- 明确主线与各副线（人物线/悬念线/情感线），每条线一句话目标与终点。
- 规划每条线的推进节奏：何时并进、何时收束；并行线的交汇点必须提前规划，登记进 chapter-structure.md 并在 continuity-log.md 的"追踪事项"跟踪。
- 避免重复覆盖：同一事件只由一条线承担"主视角"，其余线用结果、侧面或事后补述带过。
- 单线作品也要检查"隐含副线"：伏笔与悬念线是否与主线同期推进、如期兑现。

## 检查清单
- [ ] logline 一句话成立（主角 + 目标 + 障碍 + 代价）
- [ ] treatment 与设定集一致（年龄/称谓/空间常量对照 00-设定/anchors.md），结局方向明确
- [ ] 关键转折点改变故事方向（不只是时间推进）
- [ ] 中点/高潮改变赌注，且用到已建立的设定与关系（不靠天降）
- [ ] 每章有功能、每卷有职责、每条线有终点与交汇点

## 跨媒体改编附录
- 若作品未来可能改编为互动叙事/游戏（选项分支、多路线）：在 chapter-structure.md 预留分支节点标注（选项位置、后果差异、指向），本结构的章节功能与情感节奏设计可直接复用；正式改编以「剧本创作」预设为准。
