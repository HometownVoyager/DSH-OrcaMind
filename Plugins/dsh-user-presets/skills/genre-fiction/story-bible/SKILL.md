# 设定集维护（story-bible）

## 何时使用
- 新作品开工时填充 `00-设定/`。
- 每次正文写作引入新设定/新角色/新地点时，同步更新。
- 用户询问"某某设定是什么"时，先查设定集再回答。

## 基准事实优先（Anchors First）——本 skill 的第一原则
传统做法把出生年月散落在人物小传、住宅散落在世界观、称呼散落在对白，导致长篇写作必然出现事实漂移。本原则要求：**可被唯一确定的常量事实先集中进 `00-设定/anchors.md`，人物卡与世界观的展开以它为纲、只引用不复制。**

1. **写人物卡前先填锚点**：建立 characters/ 档案之前，先把该角色的出生/基准年龄、关键节点年龄与生理核心事实写进 anchors.md 第一节「年龄与生理时间轴矩阵」，把叙述指称与各视点角色对 TA 的称谓写进第三节「称谓三层解耦网格」。人物卡里的年龄、称呼字段一律引用锚点，不另行撰写第二套口径。
2. **写世界观/地理前先出空间拓扑**：编写 geography.md 与 world.md 之前，先把常驻空间写进 anchors.md 第二节「空间拓扑与动线模型」——建筑属性（楼层/电梯或步梯）、户型、动线连接与声光穿透法则。世界观的规则、历史写 world.md，但空间物理事实归锚点。
3. **信物/道具与体态进锚点**：重要信物与道具的来源、持有/流转与使用阶段、转赠去向写进 anchors.md 第四节「核心资产与体态状态机」；伤势的出现与痊愈节点、重要装扮的更换节点同样登记；角色不可变外貌特征（发型/发色/瞳色）写进「体貌锚点」。
4. **先锚点后正文**：凡正文将要用到的新事实（新角色年龄、新场景空间、新信物/道具），先在 anchors.md 补录并经用户确认，再写进正文。锚点未锁定的内容不进入正文。
5. **锚点是单一事实源**：人物卡、geography.md、timeline.md 与正文均不得与 anchors.md 冲突；发现冲突时先查 anchors，以锚点为基准修正其他文档（锚点本身要改则先请用户裁决，见 continuity skill）。timeline.md 里的事件日期序列是锚点年龄矩阵的展开，两者必须同源。

## 动笔前判定
- 写设定前先判定文本类型（本阶段产出为设定文档，非正文）与文风基调（对照 style.md），按本 skill 的模板正式撰写。
- 判定所需信息不足时先向用户求证；素材不足以支撑角色或世界观时，先给出 2–3 个候选方向讨论，用户拍板后再写入；拍板前的推测标注「推测/待拍板」，不混入正式文档。

## 文件与模板

### anchors.md —— 全局基准事实层（见 novel-project-bootstrap 的模板）
年龄与生理时间轴矩阵、空间拓扑与动线模型、称谓三层解耦网格、核心资产与体态状态机。设定集阶段内全量填写并经用户确认，此后正文只读不写。

### world.md —— 世界观
覆盖：世界概述（一句话）、规则体系（力量/科技/魔法等机制与代价）、历史与关键事件、社会结构、经济与职业、信仰与禁忌、常见冲突来源、与主题的关联（规则如何服务主线因果）。
- 规则必须写明"限制与代价"——没有代价的能力会破坏故事张力。
- 规则必须能服务剧情，不堆砌无用设定。
- 地理与势力分别写入 geography.md 与 factions.md，不再并入本文件；其中的空间物理事实（楼层/动线/门窗位置）先归 anchors.md 空间拓扑，本文件只引用。

### characters/<角色名>.md —— 人物卡
模板：
```markdown
# <角色名>
- 定位：主角 / 核心配角 / 反派
- 身份/地位：
- 年龄基准：<引用 anchors.md 年龄矩阵，不另写口径>
- 外貌与气质：
- 性格：核心欲望 / 恐惧 / 缺陷 / 价值观
- 目标：长期目标与当前阶段目标
- 动机：驱动行为的深层原因（与世界观、经历挂钩）
- 背景与经历：
- 能力与限制：
- 人物弧光：<出场时 → 结局时的变化>
- 与主线的关系：<如何承载主题、推动或阻碍主线>
- 关系：<与谁的关系、态度>
- 说话方式：<口头禅、句式、用词习惯>（详细声音档案见 character-voices.md）
- 出场记录：<章节、事件、状态变化>
```

### 人物塑造方法论（写人物卡前读）
- 欲望 / 恐惧 / 缺陷三角：欲望给方向，恐惧给阻力，缺陷给成长空间；三者缺一，角色就立不起来。每张人物卡必须能回答"他最想要什么、最怕什么、毛病在哪"。
- 动机与世界观挂钩：动机必须能从背景与经历推出，不凭空悬置；动机空泛的角色先向用户提出补充问题，不硬写。
- 功能位检查：主角、盟友、对手、导师、陪衬各有职责；删掉某个角色若主线不受影响，该角色可考虑合并。
- 关系网戏剧张力：角色间的目标、价值观或立场至少存在一组对抗或拉扯，纯友好或纯敌对的关系网没有戏（见 relationships.md）。

### relationships.md —— 人际关系网
记录角色间的关系定位、冲突点与关系变化方向，作为大纲与多线设计的输入。

### factions.md —— 势力
每个势力一段：目标、手段、结构、与其他势力的关系、主要成员（可链接到人物卡）。

### geography.md —— 地理
地点列表：名称、位置关系（相距多远、如何通行）、气候与风貌、功能、涉及章节。空间关系必须自洽（从 A 到 B 的距离前后一致）；常驻空间的动线细节归 anchors.md 空间拓扑，本文件引用其结论、补充氛围与风貌类信息。

### timeline.md —— 时间线
格式：`<年份/纪元> <月日?> <事件> <涉及章节>`，按时间正序排列。凡正文中给出明确时间的事件必须登记；季节、年龄、经过天数是冲突高发区。时间线以 anchors.md 年龄矩阵为纲（起点基准年龄、关键节点年龄必须一致），事件日期序列填实年龄矩阵的"阶段变化"列。

### glossary.md —— 术语表
条目：名称、定义、限制、首次出现的章节。名称一旦确定不得随意更换；必须更换时全书全局替换并在 continuity-log.md 记录。角色名的叙述指称与称谓口径以 anchors.md 第三节为准，本文件只收录非人名词条。

### style.md —— 文风与叙事规则
写明：人称与视角（如第三人称限知/第一人称/多视角，选定后与 pov-craft 对齐）、时态与叙事距离、每章篇幅习惯、基调与类型惯例、语言风格（古风/口语/冷峻）、禁忌（如"避免使用 XX 词"）、可参照的范例段落。正文写作前必读此文件。

### character-voices.md —— 角色声音档案
由 character-voice skill 维护：每个主要角色的词汇域、句式、口头禅、情绪表达与台词范例。

### inspirations.md —— 灵感与素材库
由 research-materials skill 维护：灵感、参考作品、待用桥段与考据记录。

## 维护规则
1. 设定先行：正文需要的新设定先写入设定集（哪怕一句话），再进正文；其中常量事实（年龄/空间/称谓/信物与道具/伤势/装扮）先写入 anchors.md 并经用户确认。
2. 修改设定必须：① 修改设定集（属锚点内容的先改 anchors.md 并经用户裁决）；② 检查已写正文是否有冲突（用检索工具搜相关词）；③ 在 `03-修订/continuity-log.md` 记录"改了什么、为什么、何时"。
3. 人物新增或下线要在出场记录中体现。
4. 用户在对话中口头确立的设定也要落到设定集，不能只存在于对话里。
5. 全角色复核：彼此的动机能否相互对抗或支撑，成长弧线是否与主线咬合；发现冲突先请用户裁决。
