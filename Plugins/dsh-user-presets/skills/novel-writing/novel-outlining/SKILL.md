# 小说大纲（novel-outlining）

## 何时使用
- 新作品在结构与梗概（logline/treatment）成型后。
- 用户要求"列大纲""规划剧情""理一理走向"时。

## 抽象层级红线（最高优先级）
本阶段只允许抽象层级的描述，严格禁止具体到场景与台词级正文的设计：
- 禁止写「某角色在某地点说出某句话」或任何台词级内容；
- 禁止写成段落式正文（开头、对白、感官细节都属于正文阶段）；
- 只提供情节节点、冲突升级、情感转折、人物关系变化、章节功能与节奏结构。

错误示例：「雨夜，凛在车站对遥说：『我一直都在找你。』」（场景+台词）
正确示例：「凛与遥在重逢节点确认彼此的目标冲突，推动凛重新评估自身动机。」（情节节点+关系变化）

## 三层结构

### 1. 总纲 master-outline.md
- 主题：作品想表达什么（一句话）。
- 一句话梗概：主角 + 目标 + 障碍 + 代价（与 logline.md 对齐）。
- 核心冲突：外部主冲突 / 内心冲突。
- 主要角色弧光：每个主角从哪到哪。
- 结局：先定结局再倒推，方向感才稳。
- 全书结构：分几卷、每卷一句话职责。
- 多线结构与交汇点：主线与副线各自终点、交汇位置（多线作品）。
- 伏笔预留：主要伏笔清单与兑现计划（细节跟踪在 continuity-log.md 追踪事项）。
- 开放问题：未决的创意缺口。

### 2. 分卷大纲 volume-<n>.md
每卷一个文件，包含：卷目标（本卷要完成什么转变）、卷内结构（起承转合或三幕，标出卷内高潮）、卷末钩子（网文必须）。
建议：先细化卷一与卷二，后面各卷写粗纲，边写边细化——避免过度规划导致写不下去。

### 3. 章大纲（写在 volume 文件内或 chapter-structure.md 章节表中）
每章：本章目标（推进哪条线）、场景与地点、视点角色（与 pov-craft 视点配置系统对齐）、发生的冲突、章末钩子/留白。一两句话即可，不要写成正文。

## 结构参考
- 网文：强钩子节奏——每章末留悬念；每 3–5 章一个小高潮；卷末大高潮。开篇三章必须给出主角的欲望与障碍。
- 实体书/文学向：重主题完整性与弧光；允许慢热，但开头仍需"承诺"——读者知道这书要讲什么。
- 通用：三幕或起承转合皆可，但必须能回答"主角想要什么、谁在阻止他、代价是什么"。节奏模型细节见 writing-craft。

## 检查清单（每层完成时自检）
- [ ] 主角的欲望与障碍明确
- [ ] 每条线的推进有因果链，不靠巧合硬推
- [ ] 节奏有张弛，不全是高潮也不全是铺垫
- [ ] 章末钩子与下一章开头能衔接，且钩子有兑现计划
- [ ] 多线交汇点明确，无重复覆盖
- [ ] 与设定集无冲突（时间、地点、能力；年龄/称谓/空间常量对照 00-设定/anchors.md，锚点矩阵优先核验）
- [ ] 无触犯抽象红线的场景与台词级内容

## 与正文的关系
大纲是活文档：写作中发现更优走向，可修改大纲，但修改属于重大决策，需先向用户说明理由并获确认。触犯红线的段落必须改写为抽象表述后再写入文件。
