# 小说项目搭建（novel-project-bootstrap）

本文件是家族母本（领域无关的通用写作流程与文档约定）：`skills/genre-fiction/novel-project-bootstrap/SKILL.md` 在其基础上派生，只增补本域内容（开题类型判定）；两者的共性部分以本文件为准，**改动共性部分须同时改两份**（派生版见 `skills/_SYNC-POLICY.md`），派生版独有的「开题类型判定」不回改本文件。

## 何时使用
- 用户提出创作一部新小说、且尚未建立项目目录时（收到新作品创意后先与用户确认类型/题材/篇幅，再执行本 skill）。
- 用户要求"开新坑""新建作品""搭建项目"时。
- 每轮对话开始检阅项目状态、每阶段结束时更新进度与确认记录。
- 接手已有作品但缺少 README.md、剧情精述.md 或 anchors.md 时：先按本 skill 模板补建（已有内容照实填入，不确定处标注待确认；缺 anchors 时按「只增不改」补建，内容从已确认设定照实汇总、不新造事实、补建前先请用户确认），再展开工作。

## 开工规范检查
- 每个项目第一步先检查工作区主目录的 `规范-创作.md` 与既有文档：
  - 存在结构/格式/文风规范且完整 → 直接采用，不再询问；此后每轮 Check 与落盘都以它为唯一规范事实源。
  - 没有、不全，或与默认规范冲突 → 停下询问，给三个方向由用户选：① 选默认集（本预设模板体系：00-设定/style.md 文风规则 + 本文件的标准目录与文档约定）；② 新放一份（用户自备规范文档，可等待用户放入工作区后继续）；③ 由 agent 当场起草一份（用 web_search 检索、用 web_fetch 打开原文核对），草稿经用户逐条确认后定稿。
- 选定后落盘 `规范-创作.md`（Markdown，统一四节骨架）：①来源记录（所选规范集名称、出处与定稿日期）②结构与目录约定（整体结构、各部分职能、项目目录与命名）③产出格式规范（标题层级、编号体系、引用/署名等要素格式）④红线与禁忌（明令禁止的做法）。选默认集时，该文档汇总引用既有模板（00-设定/style.md 与目录约定）而非复制全文。
- 自备规范不全时，在其基础上按默认集补全缺失部分，补全内容标注并请用户确认后并入规范文档。

## 阶段顺序与门控
阶段顺序为 创意与选题 → 设定集 → 结构与梗概 → 大纲 → 逐章正文 → 连续性检查与修改定稿。只有用户确认本阶段完成、或明确指示进入下一阶段后才推进，并在 README 阶段确认记录中登记该确认。网文连载等需要快速推进的项目，可由用户一次性授权跳过门控、按章推进，该授权同样登记进 README。anchors.md 在设定集阶段内全量填写并锁定（见「全局基准事实层」）。

## 标准目录结构
每个作品一个目录，位于当前工作目录（或用户指定的目录）下，命名为作品名（用户确认的暂定名即可）。结构如下：

```
<作品名>/
├── README.md                    # 作品总览、当前阶段与阶段确认记录（最先创建，每轮先读）
├── 剧情精述.md                  # 当前写作进度 + 全部已有剧情的逐章精述（比 README 详细）
├── 00-设定/
│   ├── anchors.md              # 全局基准事实层（Anchors Layer）：年龄与生理时间轴矩阵/空间拓扑与动线模型/称谓三层解耦网格/核心资产与体态状态机（最先落盘，先于正文，连续性核查第一基准）
│   ├── world.md                 # 世界观（规则/历史）
│   ├── characters/              # 人物卡，每人一个文件
│   │   └── <角色名>.md
│   ├── relationships.md         # 人际关系网与变化方向
│   ├── factions.md              # 势力与组织
│   ├── geography.md             # 地理与地点
│   ├── timeline.md              # 时间线
│   ├── glossary.md              # 术语/物品/力量体系
│   ├── style.md                 # 文风与叙事规则（基调/类型惯例/禁忌/范例）
│   ├── character-voices.md      # 角色声音档案（见 character-voice skill）
│   └── inspirations.md          # 灵感与素材库（考据来源/参考作品/待用桥段）
├── 01-规划/
│   ├── logline.md               # 一句话故事与卖点
│   ├── treatment.md             # 故事梗概（含结局方向）
│   ├── master-outline.md        # 总纲
│   ├── chapter-structure.md     # 章节功能表（章号/功能/关键事件/情感节奏/视点角色/伏笔）
│   └── volume-<n>.md            # 分卷大纲（每卷一个文件）
├── 02-正文/
│   └── 卷<n>/
│       └── ch<编号>.md          # 每章一个文件，三位编号如 ch001.md
└── 03-修订/
    ├── continuity-log.md        # 连续性查证与修改记录（含伏笔与多线追踪）
    └── revision-log.md          # 修改轮次记录与复盘
```

说明：
- 目录名带数字前缀是为了排序稳定；正文文件名用半角三位编号（ch001.md）。
- 短篇可不建分卷目录，正文直接放 `02-正文/`；logline 与 treatment 可合并为一份短文档。
- 全部文件使用 Markdown、UTF-8 编码，标题层级从 `#` 开始。

## 全局基准事实层（anchors.md）——脚手架最优先落盘的文件

`00-设定/anchors.md` 是本作品**不可变基准事实层**：把最易发生"事实漂移"的常量（年龄、空间、称谓、信物/道具/伤势/装扮）集中成单一事实源，编写与确认**优先于任何章节正文**，此后一切连续性核查以它为第一基准。它在设定集阶段随各文档逐步填实，但在动笔写正文前必须全量确认并锁定。

### 搭建纪律
1. 创建目录骨架时**立即**生成 `00-设定/anchors.md`，用下方四节模板搭好结构，已确认的事实照实填入，未确认处标注「待确认」。
2. 设定集阶段结束（进入结构与梗概之前）必须完成 anchors.md 全量填写并经用户确认；此后视为**基准事实**，正文只读不写。
3. 正文写作中发现需要改锚点的（如改年龄、改空间），必须先请用户裁决，再改 anchors.md，并在 `03-修订/continuity-log.md` 记录"改了什么、为什么、何时"，最后排查已写正文（见 continuity skill）。
4. 正文中将要用到的新事实（新角色年龄、新场景空间、新信物/道具），先在 anchors.md 补录并经用户确认，再写进正文；锚点未锁定的内容不进入正文。

### anchors.md 模板（四节缺一不可）
```markdown

> 任何修改必须先经用户裁决，并同步登记 03-修订/continuity-log.md。

## 一、年龄与生理时间轴矩阵（Age & Chronology Matrix）

| :--- | :--- | :--- | :--- | :--- |
| <主角> | <出生年月日（起点年龄）> | <如 高考结束待升学> | <生日节点与届时年龄> | <生理/寿命关键事实> |

- **体貌锚点**：<每位主要角色的不可变外貌特征，如发型发色瞳色，写"绝非XX"类负向锚点>
- **信物/道具流转状态机**：<每件重要信物或道具一条：来源 → 持有与使用阶段（含具体卷/章节点） → 转赠去向，杜绝凭空消失、凭空出现或状态回跳>
```

## 剧情精述.md（写作进度与既有剧情精述）
README 的进度栏只记状态，本文件记录细节，是每轮动笔前回顾全部既有剧情的主要依据：
- **当前写作进度**：写到第几章/第几卷、最近一次修订轮次、正在处理的段落（比 README 具体，如「第 12 章第 3 节初稿完成，对白待补」）。
- **逐章剧情精述**：每章一条（按章号排列），用复合句完整概括该章发生了什么、角色状态与关系如何变化、揭示与埋设了哪些信息；篇幅约为该章正文的 2%–5%，可独立读懂，不引用台词原文。
- **待兑现伏笔**：未回收的伏笔与多线交汇点清单，与 `03-修订/continuity-log.md` 的追踪事项保持一致。

更新纪律：每写完一章或完成一次修订，立即追加或更新对应章条目与进度状态；回溯修改正文时同步改写受影响章的精述。精述与正文或已确认内容不一致时，以正文与已确认内容为准并当场修正精述。

## README.md 模板
```markdown

- 类型：<网文/实体书/短篇等>
- 题材：<一句话>
- 目标篇幅：<字数/卷数/章数>
- 更新节奏：<日更/周更/不限>
- 当前阶段：<创意与选题 / 设定集 / 结构与梗概 / 大纲 / 逐章正文 / 连续性检查与修改定稿>

```

## 执行步骤
1. 与用户确认作品名（暂定即可）、类型、题材、目标篇幅、更新节奏与文风偏好（基调与可参照作品）——不确认就动手属于重大决策未征求同意；这些也是此后各阶段判定文风的依据。
2. 执行开工规范检查（见「开工规范检查」），按结果落盘或采用 `规范-创作.md`。
3. 创建目录骨架与 README.md、剧情精述.md 两份根文档，**并立即生成 `00-设定/anchors.md`（四节模板，已确认事实照实填入）**；其余骨架文件写入占位标题与简短说明（如 world.md 写"待补充"），按阶段推进逐份补全。
4. 接手已有作品补建时，README、剧情精述与 anchors 按现有正文与设定照实填写；缺 `00-设定/anchors.md` 时按「只增不改」原则补建——内容从已确认设定照实汇总、不新造事实，补建前先请用户确认。无法确认的条目标注「待确认」并列入下一待确认事项，不凭空补写。
5. 提示用户下一步：通常是从 logline 与设定集开始（novel-structure 的 logline、story-bible），两者可并行推进；设定集阶段内完成 anchors.md 全量填写并经用户确认。
6. 搭建完成后，把新作品目录的路径与结构告诉用户。

## 注意事项
- 不要在没有项目目录的情况下把正文写进零散文件——后续一致性检查与进度管理都依赖这个结构。
- 每轮工作以 README.md 与剧情精述.md 为入口：有则先读再干活，无则先建再干活；anchors.md 每次连续性核查必读（见 continuity skill）。
- **动笔写正文的前置条件**：anchors.md 已全量填写并确认（基准事实先行），否则先停下补锚点，不带着未锁定的年龄/空间/称谓事实下笔。
- 每阶段产出落盘前按 continuity skill 执行一次一致性核查；查出的冲突先请用户裁决，并记入 03-修订/continuity-log.md。
- 用户要求跳转或回溯时照办，但要在 README 与对话中说明跳转对前后阶段可能产生的影响（如先写正文会导致大纲未定而返工）。
- 用户已有自己的目录习惯时尊重用户结构，但至少保证 README、剧情精述、设定集、规划与正文五部分可被找到。
