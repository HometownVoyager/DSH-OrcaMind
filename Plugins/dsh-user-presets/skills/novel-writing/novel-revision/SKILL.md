# 修改与润色（novel-revision）

## 何时使用
- 用户要求"改稿""润色""修改这一章/这一卷"时。
- 完成一卷或全书初稿后主动提出修改方案时（先给方案，经确认后执行）。

## 修改轮次（每轮只做一件事）
1. 结构轮：logline/treatment/大纲与成稿是否一致、情节漏洞、因果断裂、节奏失衡、虎头蛇尾、多线收束是否成立。允许大改。
2. 一致性轮：调用 continuity skill 全量核查，先对 `00-设定/anchors.md` 做锚点核验（年龄与生理时间轴矩阵/称谓三层解耦网格/核心资产与体态状态机/空间拓扑与动线模型），再查设定/时间/人物/物件/伏笔/多线。
3. 视角轮：调用 pov-craft 核查视点配置（章头视点声明与 `规范-创作.md` 声明的模式是否一致、动态特权与限制转移、多心声禁令）与 POV 纪律、叙事距离与独白口径（视角是否漂移、是否有视角外信息泄漏）。
4. 文笔轮：用词重复、句式单调、弱动词、废话与注水、句子级节奏。
5. 对白轮：调用 character-voice 核对对白是否符合人物声音、是否有潜台词、是否推进情节；叙述指称与称呼对照 anchors.md 称谓网格三层口径。
6. 定稿轮：全角标点统一、排版规范、错别字；对照 anchors.md 逐章核对年龄、称谓、核心资产与体态状态、空间拓扑与动线；检查范围连接符是否用了 `~`（统一改为 `-` 或 `- `，见 novel-chapter-writing 连接符防灾）。

## 具体技法
- 删减优先：删掉不推进情节、不揭示人物的段落，比添加更有效。
- 替换重复：与其硬换同义词，不如重写句子结构。
- 弱动词升级：把"走""说""看"在关键处换成有具体意象的动词（别过度，忌堆砌）。
- 拉近视角：抽象叙述改写成具体场景（一个动作、一个细节）。
- 节奏调整：拖沓处砍细节，仓促处补一个感官锚点。

## 反馈与执行
- 用户给方向（"更紧张些""这个角色太扁平"）→ 转化为 3–5 条具体修改点，执行后说明改了什么、为什么。
- 大改前备份：将被改稿复制为 `<原名>-before-<日期>.md`，或依赖版本控制。
- 大改（改主线、改结局、动人物命运、删支线）必须先给用户方案并获得确认。
- 每次修改后同步更新设定集与追踪事项，防止"改过的正文"和"没改的设定"打架。

## 修改记录与复盘
每轮结束在 revision-log.md 记录：
```markdown
## <日期> <轮次> · <范围>
- 删/改/新增：<具体条目>
- 理由：<一句话>
- 遗留：<待决问题>
```
每完成一卷或全书修订后追加一段复盘：这轮解决了什么、暴露出什么新问题、下一轮的目标与优先级。
