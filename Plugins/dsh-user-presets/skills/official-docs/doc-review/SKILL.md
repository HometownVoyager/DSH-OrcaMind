# 逐项校对与定稿判定（doc-review）

## 何时使用
- 项目「逐项校对」阶段：对草稿按所选规范逐项核对。
- 「审校定稿」阶段：校对全部通过后做定稿前最后判定，归档 01-定稿/。
- 用户要求「校对一下」「检查格式」「定稿」时。

## 校对表制作
- 每份文书建一份校对表，落 `04-校对记录/<文种>-<主题>-校对表-v<n>.md`，对应草稿版本号；重新起草后新版本另起一表，旧表只增不改。
- 校对表结构：维度 | 校对项 | 依据（规范-公文.md 对应小节或 spec skill 条目）| 结果（通过/不通过/待确认）| 处置。
- 校对项从所选规范的要素清单逐条生成，不凭记忆抽查：党政公文按 18 要素与版面分区逐项过，企业文书按四要素与四级序号体系（「一、」「（一）」「1.」「（1）」）过，法律函件按首部-五要素-尾部过。

## 六个校对维度
1. **格式要素齐全性**：标题三要素（机关+事由+文种）、发文字号格式（六角括号年份、顺序号无「第」字不编虚位）、签发人（上行文）、主送、落款、成文日期、版面分区落位；企业文书标题/主送/落款/日期四要素。
2. **口径与依据回溯**：正文每个数字、日期、政策引用都能回溯 03-依据材料/ 的对应条目；引用政策文件为现行有效版本且文号正确；数据注明统计口径。
3. **称谓**：机关/单位用全称或规范化简称，全文统一；无「我局领导」「咱们」类表述；法律函件当事人简称首次出现括注、后文统一。
4. **数字与计量**：按 GB/T 15835（数字用法）与 GB/T 15834（标点符号）执行；金额、日期、数量准确；法律函件金额大写小写一致、日期公历全写。
5. **法律措辞**（法律函件）：法条引用格式《法律名称》第 X 条第 X 款精确；要求事项语义封闭（「限于…日内」「应当」）；无威胁侮辱性措辞、无超出证据范围的指控；争议点标注「待律师确认」。
6. **文种与内容一致性**：标题、正文、结语文种前后一致；请示一文一事、报告无夹带请示；结语惯用语与文种匹配（「特此通知」「妥否，请批示」「此复」等）。

## 内容自查（与措辞纪律同源，校对表单列一组）
- 无口号代实质：「高度重视」「深入贯彻」类语句仅作衔接，工作部署落到具体动作、责任主体与时限；「加强」「完善」「进一步」不单独充当措施。
- 措施三问：做什么、谁来做、何时完成——逐条可核验。
- 影响面：涉及利益调整的文书，起草前的利益相关方/上下游/执行端检视已完成，未考虑处已标注「待确认」。

## 校对闭环
- 每轮校对输出校对表 + 不通过项清单；不通过项逐条给出修改建议，经用户确认后改稿再校。
- 同一问题在两个版本中重复出现的，在校对表中标注「复发」，提示检查修改流程是否遗漏该维度。

## 定稿判定（全部满足才归档）
1. 校对表全部条目「通过」或经用户确认接受「待确认」项的处置说明；
2. 依据回溯无缺口（正文数字/日期/引用与 03-依据材料/ 一一对应）；
3. 法律函件：法条引用全部与现行有效版本核对通过，「起草稿性质」声明在位；
4. 用户明确确认定稿。
- 判定通过后：草稿终版复制归档 01-定稿/（版本命名），README 文种登记表状态更新为「已定稿」，进度与确认记录同步。

## 注意事项
- 校对以 规范-公文.md 为唯一规范事实源；规范本身需要修改时先经用户拍板，不在校对中静默改口径。
- 校对发现与已确认口径冲突时，指出冲突请用户裁决，不自行改写已确认内容。
- 校对不是润色：措辞与结构修改仍按起草阶段的规范执行，校对只核对符合性并记录结果。
