# 文种选择与解构（doc-types）

## 何时使用
- 项目「文种与受文对象」阶段：判定文种、主送/致送对象与行文方向。
- 起草前：按文种解构结构、列出要素清单，作为逐项落位的底稿。
- 用户提出的名称不是标准文种时（如「申请」「汇报」），按本 skill 改判并说明理由。

## 党政机关 15 种法定文种（《党政机关公文处理工作条例》）
| 文种 | 适用 |
|------|------|
| 决议 | 会议讨论通过的重大决策事项 |
| 决定 | 重要事项决策部署、奖惩、变更或撤销 |
| 命令（令） | 公布行政法规规章、宣布重大强制措施、批准授予晋升衔级、嘉奖 |
| 公报 | 公布重要决定或重大事项 |
| 公告 | 向国内外宣布重要或法定事项 |
| 通告 | 一定范围内公布应当遵守或周知的事项 |
| 意见 | 对重要问题提出见解和处理办法 |
| 通知 | 发布、传达、执行、周知事项；批转转发公文 |
| 通报 | 表彰先进、批评错误、传达精神、告知情况 |
| 报告 | 向上级汇报工作、反映情况、回复询问 |
| 请示 | 向上级请求指示、批准 |
| 批复 | 答复下级请示 |
| 议案 | 政府按法律程序向人大提请审议事项 |
| 函 | 不相隶属机关之间商洽工作、询问答复、请求批准 |
| 纪要 | 记载会议主要情况和议定事项 |

## 行文规则（判定时逐条过）
- **行文方向**：上行（请示/报告/议案）、下行（批复/通知/通报等）、平行（函）；方向由发文机关与受文对象的隶属关系决定，不由习惯决定。议案是人民政府按法律程序向同级人民代表大会或其常务委员会提请审议，《党政机关公文处理工作条例》未规定其行文方向，此处按实务惯例归入上行，登记时在备注注明依据。
  - 三值（上行/下行/平行）只适用于存在隶属或相隶属关系的行文：决议、公报、公告、通告、纪要属会议决议或面向社会的公布，律师函/催告函/告知函/复函属当事人之间，登记表「行文方向」栏一律填「不适用」并在备注写明依据。
- **一文一事**：一份请示只请求一件事；报告中不得夹带请示事项——需要批准的事另发请示。
- **主送规则**：上行文原则上主送一个上级机关；一般不得越级行文；受双重领导的机关向一个上级主送时抄送另一个。
- **联合行文**：用主办机关的发文字号；涉及多部门职权的事项须协商一致后方可行文。
- **文种不得自造**：「申请」「汇报」「情况说明」不是法定文种，按受文对象与隶属关系改判（如向不相隶属机关请求批准事项用函）。

## 企业行政/商务文书常用文种
- **通知**（内部传达/布置工作）、**请示**（向上级公司/主管部门请求批准）、**报告**（工作汇报/情况反映）、**会议纪要**（记载议定事项）、**函**（平级或无隶属关系的商务单位之间商洽事务）；其他常用体：工作方案、工作总结、简报。
- 语气与权限随层级关系把握：企业内部用「请遵照执行」级别而非党政强制语气；对外函件必须以公司名义落款。

## 法律函件类别
- 常用类别：律师函、催告函、告知函、复函；先确认委托关系（受谁委托、就何事宜）再定类别与措辞强度。
- 一份函件只处理一项争议事由；要求事项必须明确、可执行、可核查。

## 结构解构（起草前逐项落位清单）
- **党政公文主体三段**：缘由（依据/目的）→ 事项（分条列项，落到做什么/谁做/何时）→ 结语（文种惯用语：「特此通知」「妥否，请批示」「此复」等，与文种一致）。
- **要素清单**（按所选规范核对齐全性，见 spec-govt-gbt9704 的 18 要素与版面分区）。
- **企业文书四段**：标题（事由+文种，可冠单位名）→ 主送对象 → 正文（缘由→事项→结语）→ 落款（单位署名+成文日期）；会议纪要可用纪要式（会议概况 → 议定事项分条注责任方与时限 → 其他事项）。
- **法律函件三段**：首部（标题+编号、致送对象全称）→ 正文五要素（委托关系声明 → 事实陈述 → 法律依据 → 要求事项 → 期限与后果）→ 尾部（律所全称+律师姓名+执业证号+联系方式+出函日期）。

## 判定流程
1. 问清三件事：谁发给谁（隶属关系）、要达到什么目的、受文对象需要做什么。
2. 按行文方向与目的对照文种表初判；初判结果与用户确认后登记进 README 文种登记表。
3. 起草前按结构解构列出本份文书的要素清单，作为解构起草与后续校对的底稿。

## 注意事项
- 文种判定拿不准时给用户 2-3 个候选文种并说明各自适用条件与后果差异，由用户拍板。
- 结构解构只是骨架：具体要素格式（发文字号、签发人、成文日期等）以 规范-公文.md 所选规范集为准。
- 用户单位若有内部行文惯例（如自有文种体系），在规范检查阶段登记进 规范-公文.md 后按其执行。
