# 企业行政/商务文书规范（spec-corporate-admin，定稿版 2026-09-10）

> 用途：开工规范检查选默认集「企业行政·商务文书」时，本 skill 是 `规范-公文.md` 的内容母本（四节骨架、写法通则与执行要求的纳入方式见 spec-common；落盘时记录来源为「本预设默认集·企业行政·商务文书（2026-09-10 定稿）」）；企业文书起草与校对阶段随时对照执行。

## ① 来源记录
- 无单项强制性国家标准；体例参照《党政机关公文处理工作条例》与《GB/T 9704-2012》的通用格式惯例（条例第 40 条明确「其他机关和单位的公文处理工作，可以参照本条例执行」），结合企业行政文书通行实务整理；
- 定稿时间：2026-09-10（据检索摘要提炼，用户直接定稿）。

## ② 结构与目录约定
- 常用文种：**通知**（内部传达/布置工作）、**请示**（向上级公司/主管部门请求批准）、**报告**（工作汇报/情况反映）、**会议纪要**（记载议定事项）、**函**（平级或无隶属关系的商务单位之间商洽事务）、其他常用体（工作方案、工作总结、简报）。文种选择细则见 doc-types。
- 单份文书结构：标题（事由 + 文种，可冠单位名）→ 主送对象 → 正文（缘由 → 事项 → 结语）→ 落款（单位署名 + 成文日期，加盖公章者注明）；会议纪要可用「纪要式」：会议概况 → 议定事项（分条，注责任方与时限）→ 其他事项。
- 项目目录沿用「文种档案制」：01-定稿/ 02-草稿/ 03-依据材料/ 04-校对记录/

## ③ 产出格式规范
- 正文以现代汉语书面语行文，分条列项用「一、」「（一）」「1.」「（1）」四级序号体系（GB/T 9704-2012 的层次序数写法：第三层为阿拉伯数字加下脚点「1.」，不用「1、」）。
- 涉及金额、日期、数量处须准确无误，重要数据注明出处或口径；时限表述用具体日期，避免「尽快」「近期」单独充当承诺。
- 收发文要素齐全：标题、主送、落款、日期四项缺一不可；对内通知需注明执行部门与生效时间。
- 会议纪要须与会议记录核对：议定事项逐条可追溯（谁、做什么、何时完成）。

## ④ 红线与禁忌
- 禁止照搬党政机关口吻与强制性行政命令措辞（企业内部用「请遵照执行」而非「必须贯彻执行」级别的党政语气，按公司层级关系把握）。
- 禁止越权行文：不得以个人名义代替部门/公司作出承诺或决定；对外函件必须以公司名义落款。
- 禁止模糊责任表述：议定事项不写「相关部门」「有关人员」，须落到具体部门或岗位。
- 禁止口语化、网络用语与夸张修辞；同一文书内文种前后一致（标题写「请示」，结语不得写「报告完毕」）。

## 执行要求（写入 规范-公文.md 时随结构节一并纳入）
- 涉及金额、日期、数量与数据口径的条目，起草前先在 03-依据材料/ 登记出处，经用户确认后写入正文；逐项校对时逐条回溯。
- 逐项校对按 doc-review 执行，重点核查：四要素齐全（标题/主送/落款/日期）、责任主体具体化、时限具体日期化、语气与公司层级关系匹配、文种一致性。
