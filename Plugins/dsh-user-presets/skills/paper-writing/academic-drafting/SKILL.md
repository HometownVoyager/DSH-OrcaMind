# 学术语体与分节起草（academic-drafting）

## 何时使用
- 项目处于「分节初稿」阶段，按 02-提纲/ 的已确认结构起草正文各节时。
- 某一节初稿完成后进入下一节，或对既有节做实质改写时。
- 英文论文的英文正文起草（persona 默认中文交流；正文稿语言按所选规范）。

## 执行顺序
1. **起草前置检查**：提纲已确认（02-提纲/）、规范已落盘（`规范-论文.md`）、所选 spec skill 已加载；对应节的证据映射条目（文献库 L 编号、图表数据条目）就绪。前置不满足时先补前置，不得凭空起草。**不得用编造内容填补缺口**：事实不齐时先把待确认事项整理成一则简洁提问（同一轮合并提出、问题具体、各附可选项），用户未答复前，该处一律用占位符标注（见「占位符与内容边界」）。
2. **分节顺序**：先写证据与方法密集的节（方法/结果/分析章），再写引言与讨论，最后写摘要与结论——摘要是全文写完后的提炼，不是开头凑数的任务；各节独立文件落 03-正文/（一节一文件，如 `03-正文/引言.md`、`03-正文/01-引言.md、03-正文/03-方法.md`）。
3. **各节写法基准**：
   - **摘要**：独立短文，含目的、方法、结果、结论，重点在结果与结论；学位论文按 GB/T 7713.1（中文 300–600 字、第三人称、不用图表与非公知符号、关键词 3–8 个）；期刊与英文论文按所选规范与目标要求。摘要不得写成目录式罗列。
   - **引言**：漏斗结构——领域背景 → 具体问题 → 研究缺口（引文献库条目）→ 本研究做什么与贡献；不与摘要重复，不复述综述全文。
   - **方法/研究设计**：写到足以复现的程度——数据来源与口径、样本、分析路径、工具；数据与口径对照 04-图表数据/ 的记录。
   - **结果**：只报告发现，配图表编号；不夹带解释与评价（英文 IMRaD 严格要求，中文论文按规范执行）。
   - **讨论/分析**：解释结果与既有研究的关系（对照文献库笔记的「支持/对话/冲突」标注）、意义、局限性、未来方向；不重复罗列结果数字。
   - **结论**：回答研究问题，落在证据支持的力度内；不得是各节小结的简单拼接。
4. **引用落地纪律**：每个非原创论断随文标注（按所选规范的文中标注体系），引用内容与文献库笔记的定位（页码/章节）一致；改写他人观点仍须标注；拿不准的表述标注「待核实」不进定稿。
5. **数据一致性**：正文数字与 04-图表数据/ 的数据表逐条对应；图表随文出现、先见文后见图表、编号连续；统计表述符合所选规范（如 p 值三位小数、统计量斜体）。
6. **节完成即核**：每节初稿完成后立即对照 spec skill 的红线节自查一遍，再交下一节；全部节完成后统一进入 paper-revision 的修改与查重自查。用户要求投稿前检查时，转 paper-revision 的对抗性自审（五维，逐问标通过/需修订/需补证据）；该自审也可在写作前期作为自查清单使用，不必等全部完稿。

## 段落体检（段落级可执行判据）
起草与返写时逐段过以下五条判据，不通过就改，不靠语感：
1. **单一消息**：这段只承载一个消息。出现两个并列消息就拆段；拆不动说明论证层次没想清，回到提纲。
2. **主题句在位**：首句点明本段要做什么。判据是「只读全文各段首句，能否读出本节论证」——读不出就是主题句缺失。
3. **术语自足**：段内关键术语都可独立读懂，不依赖读者记得前文未交代的背景；新术语先定义再使用，同一概念不中途换叫法。
4. **句间关系显式**：每句与上一句的关系是因果关系、对比转折、递进补充、条件限定、例证、时序之一，且从字面可辨。关系只存在于作者脑中的，用过渡词显化或调整句序。
5. **主张—证据绑定**：段内每个主张能指到具体支撑（见「证据类型与效力核验」）。指不到的句子不许留在段里当修饰。

## 反提纲（整节体检）
段落体检用于逐段，反提纲用于整节，顺序不能颠倒——主题句没写清时做句级润色是白工：
1. 写下本节核心主张（一句话）。
2. 抄出本节每段的主题句。
3. 列出每段内部的论据与解释要点。
4. 做映射核对：每条主题句能否挂到核心主张；每条论据能否挂到它所属的主题句。
5. 调序或补句，使映射链条完整、无跳跃。
6. 映射不上的段落列入「待拍板清单」，由用户裁决定去留；**不得自行删除或整段重写**。
反提纲写得顺，说明结构成立；写得卡，说明核心主张或主题句不清，先修这两处。

## 过渡词纪律
过渡按关系类型选用，同类词不堆叠，一段内不出现两个以上同类转折：
- **因果**：因此、因而、由此、从而、基于此
- **对比**：然而、但是、相比之下、与此不同、反之
- **递进**：此外、而且、进一步、更重要的是
- **条件限定**：在……前提下、就……而言、当……时、限于
- **例证**：例如、以……为例、具体而言、具体到
- **时序**：首先、随后、继而、最终、在此期间
- **总括**：综上、总体而言、概括地说
过渡词只标记关系，不能替代内容本身的连贯：若每句都要靠过渡词才连得起来，问题出在内容顺序，应重排句序与段序，而不是加词。

## 摘要骨架（三套，按研究形态选一套）
摘要先回答四个问题再动笔：研究的问题是什么、既有工作为何没有解决、本文的贡献是什么、为什么这样做能解决问题。
- **骨架一（挑战—贡献）**：① 研究对象与问题（一句话）→ ② 既有方法遇到的困难（含技术或论证上的原因）→ ③ 本文的贡献（一至两句，点到名称与机制即可，不铺陈每一步）→ ④ 该贡献带来的效果 → ⑤ 结果概述。
- **骨架二（挑战—洞见—贡献）**：① 对象与问题 → ② 既有方法的困难 → ③ 本文的关键洞见（一句）→ ④ 实现该洞见的设计（一至两句）→ ⑤ 效果 → ⑥ 结果概述。
- **骨架三（多贡献并列）**：① 对象与问题 → ② 与既有工作的一句对比（需要时）→ ③④⑤ 每项贡献一句，句内带上该项贡献的效果 → ⑥ 结果概述。
写作要求：③④ 处只出现读者能一眼看懂的贡献名称，不出现未交代过的术语；一句不塞两个消息；不写「首次」「填补空白」这类无法由证据兑现的措辞。骨架与 persona「学术语体纪律」及所选 spec 的字数、人称要求叠加使用，规范优先。

## 引言：开篇策略与挑战链
开篇按读者对研究对象的熟悉程度三选一（学位论文可在绪论后另设文献综述章，此处只解决引言开篇）：
- **不熟悉 → 先定义后价值**：一句给出研究对象（由什么输入得到什么输出，或研究什么问题），必要时一句界定范围，再用两三个代表性场景说明价值。
- **已熟悉 → 直接进价值**：跳过定义，首句讲清该问题的重要性，可接一句目标要求（精度、效率、稳健性、解释力等）。
- **由宽到窄 → 逐级收窄**：从大领域的重要性起笔，收到本文的具体设定，再点明这一设定的边界与判断标准。
开篇最常见的失手是背景空转：连写数段行业重要性却迟迟不出现本文要解决的问题。可接受的做法是首段就把问题亮出来——重要性一句、既有做法一句、其失效之处一句。

挑战链从既有工作通向本文解决的问题，按情形三选一：
- **通路一（既有方法失效）**：本问题的总体难点 → 早期做法及其不足 → 近年做法及其不足（**须给出原因**，不能只说效果差）→ 仍未解决的挑战，且这条挑战正是本文所解决的。
- **通路二（经典洞见不足）**：主流做法及其不足 → 指出某条早期研究路线已含有与本文相近的思路 → 说明该路线为何仍不够 → 回到近期做法，给出其未解决的原因 → 接入本文。
- **通路三（问题分解）**：说明本研究的目标，指出难点在于若干处（如「其难点有三」）→ 用「其一/其二/最后」把相互独立的难点逐条说清，每条都给出可观察的现象与背后原因 → 收束到本文的做法。
每条通路都必须让「最后一条未解决的挑战」与本文的贡献严丝合缝；对不上说明引言的挑战被写大了或写偏了，以贡献为准回改挑战。

贡献句写法（引言末段，与「创新点表述」配合）：
- 逐条列出「做了什么 + 与既有工作的技术差异 + 为什么这样设计能解决问题」；不建议只写「本文提出了……」而不给差异与机理。
- 单项贡献且优势多，用分层写法：先总述做法与关键差异，再用「具体而言」逐条展开，最后以「与既有做法相比」收束。
- 多项贡献用并列写法：每条贡献独立成句并带上其效果；模块或环节之间存在未解决的遗留问题时，可先点出该问题，再引出下一项贡献。
- **禁止写法一**：先描述一个朴素方案，再讲本文在其上做了什么改进。即便工作本身是增量的，也不这样写——这把研究写成了补丁，并替读者省掉了「为什么要这样做」的追问。
- **禁止写法二**：掩盖具体设计，只用抽象洞见和一堆新术语让平凡方案显得新颖。这是新颖性幻觉，评审会判为浅薄，也与本预设的诚信要求相悖。具体机理与步骤必须交代清楚。

## 方法章（三个元素）
每个方法单元、分析环节或研究设计要素，都写足三个元素，缺一即不可复现：
1. **设计本身**：对象与结构如何界定，过程如何在执行顺序上逐步展开（输入 → 第一步 → 第二步 → 输出），输出如何被后续使用。顺序错乱会让读者无法判断因果，必须按实际执行次序写。
2. **设计动因**：为什么需要这一环节。用问题驱动句式：存在某问题，因此设计某环节；既有做法在何种情形下失效，因此需要此处的处理。每句话都要让读者知道它为什么必须在这里。
3. **相对优势**：与替代做法相比的优势何在，尽量落到可核验的表现（精度、效率、覆盖面、可解释性、样本适用范围等），而不是形容词。
先写「设计本身」把骨架立起来，再补动因与优势，避免一路写动因却没有具体做法。实现与操作细节（参数、口径、预处理、软件与版本）集中放在方法章末或独立小节。

跨学科映射（避免把某一领域的写法当成通用规则）：技术类论文的「模块」对应社科与人文的「研究设计要素」；「模块设计」对应分析框架与操作化步骤；「消融实验」对应稳健性检验与替代设定的比较；「基线」对应既有研究中最有解释力的竞争性解释。写作要求一致：每个设计要素都交代它做什么、为什么需要、相对既有做法好在哪。

方法可读性三层自检：
1. **逻辑层**：写完把本章的推演顺序用几句话复述一遍，读得顺即为合格；读不顺说明环节顺序或动因缺失。
2. **段落层**：每段首句让读者立刻知道本段讲什么；一段一个消息。
3. **句子层**：每句的必要性可辨（删掉它是否损失信息）、与上句的关系明确、关键术语前后一致。

## 证据类型与效力核验
核验按证据类型分别进行，不套用单一标准：
- **实验或调查数据**：可回溯到 04-图表数据/ 的数据表与统计口径；
- **文献证据**：可回溯到 01-文献/ 的 L 编号，且获取状态允许引用（仅摘要、待获取、待核实者不得承重）；
- **理论推演**：前提明确、推理链完整、结论不超出前提；
- **政策与法规文本**：引到具体条款并注明版本与生效时间；
- **案例与田野材料**：交代选取理由与代表性边界。
处理规则：
- 主张有了上述任一类支撑即为有支撑，不得因「没有实验数据」就判定人文社科的理论或规范论断不成立。
- 确实找不到支撑的主张，降档为弱表述（见「证据强度与措辞分级」）并列入待拍板清单。
- **不得自行删改用户已确认的论点与贡献表述**；需要删、需要改的，说明理由与替代方案，交用户裁决。

## 创新点表述
- 贡献类型先分清：研究问题或对象的重新界定、数据处理与测量口径的改进、分析框架或设计的新组合、机制或因果解释的推进、新的经验发现、对既有结论边界的澄清。同一篇论文的贡献点宜落在两三类之内，通篇口径一致。
- 写法格式：「本文在……上的推进是……；与既有研究相比，其差异在于……；该差异使……成为可能」。
- 措辞强度与证据强度匹配（见「证据强度与措辞分级」）：证据不足时用「尝试」「提供了一个可能的解释」，不用「揭示」「突破」。
- 禁用「首次」「填补空白」「开创性」这类无法由证据兑现或无法穷尽检索验证的表述；确需说明「既有研究尚未涉及」时，须以检索范围与检索策略为限定条件，写成「就本文检索所及」。
- 贡献点讲不清时先自问一句：这项工作给读者的新知识是什么。若一句话答不出，说明贡献还没想清，此时应回提纲或与用户确认，不要用措辞补救。
贡献与证据的对应关系在摘要或引言末以一张小表随稿给出，状态栏沿用提纲「证据状态」的四档，另加「已降档」表示该项已按弱表述处理后暂不再补：

| 贡献表述 | 支撑位置（章节/图表/文献编号） | 证据状态 |
|----------|--------------------------------|----------|
| <一句话贡献> | <如 3.2 节 + 图 2；L007；表 3> | 充分 / 待补 / 待核实 / 不充足 / 已降档 |

## 证据强度与措辞分级
| 证据状况 | 可用的措辞 | 禁用的措辞 |
|----------|------------|------------|
| 强：多来源一致、统计显著、机制清楚 | 表明、证实、说明、可判定为 | —— |
| 中：单一来源、样本有限、或有竞争性解释 | 提示、倾向于支持、与……一致 | 证明、证实、必然 |
| 弱：仅个案、仅一次观察、口径存疑 | 可能、初步显示、有待检验 | 表明、说明 |
| 无支撑且已降档 | 本文仅就此提出问题、有待进一步研究 | 任何肯定性判断 |
不得把相关写成因果，不得把单案例写成普遍规律，不得把政策文本的应然陈述写成本文已证实的实然结论。

## 结论与局限
结论按四步收束：重述所解决的问题与核心思路 → 给出最有力的证据（指向具体结果而非罗列数字）→ 说明理论或实践意义 → 交代局限并给出下一步方向。结论不是各节小结的拼接，也不得引入正文未出现的新论断。
局限写作的伦理边界：局限按范围边界表述，可写数据覆盖的区间、依赖的假设、适用的场景与人群、方法本身的适用前提；**但若某项缺陷会影响结论的成立，必须如实披露，明确写出它影响的是什么，不得用「范围局限」「有待扩展」这类措辞掩盖实证或论证上的实质问题**。性质上属可修补的操作瑕疵而不影响结论成立的，不必写进局限。

## 请求类型路由（输出形态与规模）
| 请求形态 | 做法 | 输出 |
|----------|------|------|
| 单句改写（「这句不通顺」） | 只改该句，保持原意与主张强度 | 改写后的句子 + 一句改动理由 |
| 单段润色（「这段通顺吗」） | 按「段落体检」五条判据走一遍 | 修订后的段落 + 两至三行说明（改了什么、为什么） |
| 整节重写 | 按分节顺序完整执行，先反提纲再逐段写 | 整节稿件 + 反提纲记录 + 贡献证据对应表 |
| 结构方案（「结构怎么搭」） | 给 2-3 个候选结构供拍板 | 每条候选 3-7 条的 mini-outline（只到论点与证据层级）+ 依据、代价与收益 |
| 图表问题 | 按所选 spec 的图表条款与「图表可读性」处理 | 图表修订建议 + 正文引述句的补写 |
| 投稿前自审 | 转 paper-revision 的对抗性自审 | 按风险排序的问题清单 + 处置建议 |

**体量缩放**：单段润色与单句改写只给修订文本加简短说明，不必给出完整的检阅摘要、问题清单与逐条核验表；请求本身是结构性问题或证据缺失时，直接指出问题，不做表面润色。**项目状态检阅与根文档读取不适用缩放**：核对项目进度、读取 README 与各阶段产物、判断阶段是否可推进，仍按完整粒度执行。
**范围边界**：改写不得顺手重构未在请求范围内的段落。确有必要时在说明中单独列出，交用户决定是否执行。

## 占位符与内容边界
- 数据、引用、样本量、口径、时间范围等事实一律不编造。需要用户补的，写明确占位符：`[待补数据：指标口径与来源]`、`[待引用：文献库编号]`、`[待核实：表述与原文对照]`。
- 占位符必须在交付时逐条汇总在文末「待补清单」，同时说明影响哪些节。占位符未落实前，相关表述按降档规则处理。
- 留空与降档都不能用于掩盖信息缺失；用户要求成稿时，如实说明哪些部分尚不成立。

## 改写时的保全与编辑策略
- 改写**不得破坏**引用标记、交叉引用、图表编号、公式编号及其在正文中的指向关系。修订前后须核对：引用数量与编号未变、图表编号连续、公式编号与正文指代一致。
- 确需调整上述编号或标记时，先说明理由并在修订记录中登记影响范围，不静默改动。
- 编辑策略以本预设为准：**只增不改**，重大改版另存新文件（见 paper-revision）；重写与删除段落须经用户裁决。
- 交付前扫一遍修订文本是否混入排版命令或英文套语：Markdown 与 Word 流程的正文中不出现 LaTeX 命令，英文骨架句不直接搬进中文正文（见「常见英文术语对照」条末说明）。

## 论证与语体基准（与 persona「学术语体纪律」一致）
- 论证三层自检：每段回答「依据是什么（文献/数据/理论/政策文本/案例）、机制是什么（因果链条或推理步骤）、对结论的贡献是什么」；空泛的立场句与口号式表态不算论证。
- 复合句为主、逻辑连接词明确（因为/然而/相比之下/这表明）；禁口语化、网络用语、营销化形容词。列表只在确实属于并列结构时使用（变量清单、检索式、条款目录），连续三个以上列表项之后应回到连贯段落做解释，不把正文写成大片条目。
- 结论措辞分级见「证据强度与措辞分级」；不得把相关性写成因果、把单案例写成普遍规律。
- 领域用词纪律：不得把某一学科的术语当作通用词汇。涉及流程示意、对照示意、方案整体框架时写「研究框架/分析路径/技术路线/研究设计示意」，不写 pipeline figure、teaser figure；涉及做法对比时写「比较方案/参照组/竞争性解释」，不写 baseline、SOTA、benchmark；涉及分组检验与稳健性时写「稳健性检验/替代设定/分样本检验」，不写 ablation、module。确属某一学科约定俗成且用户所在领域通用时，首次出现以中文表述加英文括注的方式交代，此后沿用中文。
- 英文正文的时态与数字惯例按 spec-paper-en 执行（Methods/Results 过去时、普遍事实现在时、significant 专指统计显著）。
- 中文正文的标点与混排：中文语境用全角标点，英文术语、文献著录、数值与单位按半角处理；中英文之间不额外加空格；引用他人原句用引号并随句标注出处；破折号与连接号分工明确（行文中用破折号，数值区间与复合词用连接号），全文体例统一。

## 常见英文术语对照（中文正文一律用中文，英文仅作括注或用于英文稿）
- paragraph flow → 段落衔接与推进
- reverse outline → 反提纲（用主题句回推结构）
- topic sentence → 主题句
- transition → 衔接过渡
- research gap → 研究缺口
- contribution → 贡献（不用「卖点」「亮点」）
- limitation → 局限
- ablation study → 消融实验（社科场景对应稳健性或替代设定检验）
- baseline → 基线方法（社科场景对应比较方案或参照组）
- qualitative / quantitative → 质性 / 量化
- 英文骨架句与英文过渡词只用于英文稿（spec-paper-en）。中文正文套用英文句式会产出译文腔，须按中文行文重组：先立主语与判断，再给依据与限定，避免「被广泛认为」「进行了……的研究」这类直译结构。

## 常见坑
- 摘要先写后改——全文定稿后摘要必须重写一遍，保证与正文一致。
- 摘要写成空洞开场——首句全是背景重要性，读完还不知道本文做了什么；摘要首句应尽快落到对象与问题。
- 引言文献堆砌——引言只引直接相关的缺口文献，详细综述放综述节/章。
- 引言挑战与贡献对不上——引言末点出的挑战不是本文真正解决的问题，评审会据此判为「问题与方案不匹配」；以贡献为准回改挑战链。
- 用抽象洞见掩盖平凡做法——不写具体设计与机理，只用新术语制造新颖观感；这是新颖性幻觉，既过不了评审也违背诚信要求。
- 方法写不清数据从哪来——数据来源、口径、时间范围缺一不可，与 04-图表数据/ 对照。
- 方法只写做法不写动因——读者不知道这一环节为何必须存在；每个设计要素补齐设计、动因、相对优势三个元素。
- 结果节夹叙夹议——解释性语句全部挪到讨论；校对时逐句过滤「这说明/意味着」。
- 讨论复述结果——讨论写关系、解释、局限，不再报数字。
- 图表与正文两张皮——正文必须引述每个图表的关键信息，不能「见表 3」完事。
- 范围局限当万能挡箭牌——把会影响结论成立的实质缺陷写成「有待扩展」，属于不实陈述；按「结论与局限」的伦理边界处理。
- 术语跨领域误用——把某一学科的行话当通用词汇写进人文社科稿，读者读不懂，审稿人会质疑作者是否理解自己的方法。
- 占位符留在稿里不汇总——`[待补…]` 散在正文各处且交付时未列出清单，用户无法判断哪些部分尚不成立。
- 顺手重构越界——用户只要改一段，却把邻近段落一并重写；超出请求范围的改动交用户决定。
