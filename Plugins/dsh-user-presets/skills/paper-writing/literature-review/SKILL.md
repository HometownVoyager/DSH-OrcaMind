# 文献检索与综述（literature-review）

## 何时使用
- 项目处于「文献综述」阶段，需要构建检索策略、整理文献库与笔记、撰写综述时。
- 提纲或正文写作中发现证据不足、需要补检索时。
- 接手已有项目需要核对文献库与笔记的完整性和覆盖面时。

## 文献检索深度边界（预设 persona「学术诚信与辅助边界」的执行细则）
- **检索与笔记（默认服务范围）**：广泛检索并整理题录、摘要要点与阅读笔记；笔记中注明信息来自全文还是摘要/题录。
- **全文可读处代读**：对开放获取、预印本、官方机构公开等可合法获取的全文，可代为精读并提炼笔记；笔记档注明「据全文」。
- **付费墙内文献**：由用户提供全文；未获取前只能基于题录与公开摘要记录「仅摘要」，不得声称已读全文，不得替用户判读未见原文的结论。
- 正文引用每篇文献前提示用户核对原文；文献库中「待获取」状态的文献不进入正式引用。

## 执行顺序
1. **检索策略**：围绕研究问题按 search-query-craft 的「搜索词联想构建」多维展开（事实经过/机制链条/各方立场/数据与政策原文/已有研究与综述）；来源覆盖学术数据库、政策与统计机构、高被引综述的参考文献追溯；检索词组与来源记入 文献综述进度.md 的检索策略栏。
2. **题录入库**：命中文献逐条写入 01-文献/文献库.md——编号、著录信息（按 `规范-论文.md` 所选规范著录）、来源链接、获取状态（据全文/据检索摘要/待获取）、一句话相关度说明；**只录入经核验真实存在的文献，存疑条目标注「待核实」且不得引用**。
3. **阅读笔记**：按优先级逐篇精读（与研究问题直接相关的先读；全文可读处代读适用本步），每篇一档落 01-文献/笔记/——研究问题与方法、核心发现、可引用的具体结论（注页码/章节定位）、与本课题的关系、可疑或待核对点。
4. **覆盖面与进度**：每轮更新 文献综述进度.md——综述脉络表（主题/代表文献/核心发现与分歧/状态）与缺口；明显缺口的检索方向列入下一步检索计划。
5. **综述写作**：按主题脉络与论证关系组织——每段回答「这个主题下已知什么、分歧在哪、对本研究的意义」；结尾指向本研究填补的缺口（与 research-question.md 呼应）；综述本身也是可单独交付的草稿，落 03-正文/ 对应分节文件。

## 文献库.md 格式
```markdown
# 文献库

> 著录格式：<所选规范（如 GB/T 7714 顺序编码制）>

| 编号 | 著录条目 | 来源链接 | 获取状态 | 相关度说明 |
|------|----------|----------|----------|------------|
| L001 | <按规范著录> | <URL/DOI> | 据全文/据检索摘要/待获取/待核实 | <一句话> |
```

## 笔记档格式（每篇一档）
```markdown
# L<编号> <文献题名>

- 获取状态：<已读全文（来源：开放获取/用户提供）/仅摘要>
- 研究问题与方法：<作者研究什么、用什么数据与方法>
- 核心发现：<可引用的具体结论，注明页码/章节定位>
- 与本课题的关系：<支持/对话/冲突/背景>
- 可疑或待核对点：<如有>
```

## 综述写作纪律
- 按主题组织，不按文献罗列：同主题文献的共识、分歧与演进脉络放在一起讲清联系，杜绝「A 说了什么、B 说了什么」的流水账。
- **主题分组**（相关工作节或综述的一小节、学位论文综述章的一节，均按此设计）：分 2-4 个聚焦主题，每个主题都对应本研究要解决的问题；**按主题切分，不按发表年份堆叠**。常见的三个主题位是：本研究对象所在问题域的主流做法、与本研究核心思路最接近的一路研究、本研究在方法或数据上借助的相邻领域研究。主题数超过 4 个说明综述试图面面俱到，应收并或下放到学位论文综述章的分节。
- 每组主题落笔前先确定顺序：最直接的竞争者与最新成果先写，再扩到背景性主题——读者要的是「本文相对谁有新意」，不是按时间编年。
- **主题段四句模板**（一段一主题，四句各司其职，句子数可增但职能不可缺）：
  1. **界定范围**：这个主题研究的是什么问题、在什么条件下成立；
  2. **代表工作**：一句话概括该路研究的常见做法与主要结论，代表文献随句标注文献库编号；
  3. **缺口落点**：该路做法在什么情形下失效或解释不到，并**把这一缺口与本研究的挑战精确对上**；
  4. **接入本研究**：说明本研究在该点上如何取径不同，自然过渡到下一主题或本文。
- 主题内的分歧须逐条落地：共识与分歧分开写，**分歧要呈现双方依据**（数据、样本、口径、时期差异），不能只写「存在争议」而不交代争议在哪。
- **技术语言纪律**：比较用技术语言而非营销语言。说清方法、假设、数据口径与失效机理的差异，不写「效果更好」「性能优越」「创新性强」这类无信息量的评价；确需评优劣，须给出可比的条件（同等数据、同等口径、同等任务设定）。
- 不得回避或淡化最强的竞争性研究与反面证据：最接近本研究的工作必须正面出现并写清差异，漏掉或被轻描淡写会直接变成评审的攻击点。
- 每个重要论断注明文献库编号（正文中按所选规范的文中标注体系呈现）；区分「文献的结论」与「作者（用户）的推断」。
- 覆盖面诚实：没读的、读不懂的、结论可疑的如实标注，不装作已周全。
- 综述不是终点：结尾必须落到「所以本研究要回答什么」，与 00-选题/research-question.md 一致；不一致时先请用户裁决。
- 跨学科用词：涉及研究对象所在领域的既有方案对比时，用「既有研究的主流做法」「比较方案」「参照研究」这类表述；不把某一学科的行话（如 pipeline、baseline、ablation、SOTA）当通用词汇写进人文社科稿，确需使用时以中文表述加英文括注交代一次。

## 常见坑
- 只检索单一数据库或单一角度——按多维检索词跨源检索，英文文献与中文文献都查（视论文语言）。
- 只引支持自己观点的文献——刻意检索反面证据与批评意见，综述中呈现并回应。
- 笔记写感想不写定位——可引用的结论必须带页码/章节，否则回稿时无法核对。
- 综述与提纲脱节——综述的缺口结论直接服务提纲的论证结构，两者交叉核对。
- 待获取文献被正式引用——文献库获取状态是引用的前置闸门，Check 阶段逐条核对。
- 主题分组失焦——分了六七个主题，每个主题都只碰到本研究的一角；收敛到 2-4 个与本研究挑战直接相关的主题最有效。
- 主题段缺第三句——只有「这个主题做了什么」没有「它缺什么、这个缺口与本文什么关系」，综述读起来就成了资料汇编；四句模板中第三句是承重句。
- 比较用营销语言——写「A 方法性能优越」而不写它在何种设定与口径下胜过谁，等于没比较；技术语言纪律要求把条件与机理说清。
- 回避最强对手——最接近本研究的工作被一句带过甚至不提，评审一旦发现，整节可信度受损；正面写清差异才是安全做法。

## 注意事项
- 检索与笔记工作量大，按「与主问题直接相关 > 方法与数据 > 背景补充」的优先级推进，进度在 文献综述进度.md 里如实反映。
- 文献综述阶段完成的判定：覆盖面达到检索计划的主要方向、笔记与文献库一致、综述草稿经用户确认；确认记录写进 README。
- 任何阶段发现文献库条目有误（错引、误读、不存在），立即修正并同步检查正文引用处，向用户说明影响。
