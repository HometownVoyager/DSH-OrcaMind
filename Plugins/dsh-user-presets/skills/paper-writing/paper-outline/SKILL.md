# 提纲与论证结构（paper-outline）

## 何时使用
- 项目处于「提纲与论证结构」阶段，需要在 02-提纲/ 落盘章节提纲时。
- 正文写到一半发现结构失衡、论证断链，需要调整提纲时。
- 用户对初稿结构不满意、需要给出结构方案供拍板时。

## 执行顺序
1. **结构基准确认**：先读 `规范-论文.md` 的结构节——所选规范集（spec-thesis-cn / spec-journal-cn / spec-paper-en）对章节结构的规定是提纲的骨架底线；目标期刊/院校的明确要求优先于默认结构。
2. **论点链设计**：从研究问题出发逐层展开——主论点 → 分论点 → 每节的论证任务；每一节回答「解决什么问题、结论是什么」，节与节之间有明确的推进关系（问题→方法→证据→解释→意义），不得出现与论证无关的章节。
3. **证据映射**：每节标注支撑它的文献库条目（L 编号）与 04-图表数据/ 中的数据/图表条目；映射不上的节意味着证据不足——要么补检索、要么补实验或补分析、要么降级或删除该节，如实向用户报告。
   - 除来源条目外，还须写清**支撑实验或图表**：该节的哪个论点由哪个图、哪张表或哪段分析结果直接支撑。只写「本节有数据」不算映射，要能指到具体图表编号；一个论点没有任何图表或分析结果承担，说明它目前只是说法。
   - **证据状态**按四档填写，与「证据类型与效力核验」配套使用：
     - **充分**：证据已就绪，可回溯到具体条目（已读全文的文献、已定稿的图表数据），可以支撑现有力度的表述；
     - **待补**：需要的实验、分析或检索尚未做，标注补什么、由谁补（补检索或补分析由 agent 提出方案，需用户确认）；
     - **待核实**：条目存在但口径、出处或数值尚未核对，引用前必须落实；
     - **不充足**：现有证据不足以支撑该论点，须降档为弱表述或调整论点，不得按原力度写。
   - 证据类型不必限于实验数据：实测或调查数据、文献证据、理论推演、政策与法规文本、案例与田野材料，各自都可以支撑主张；判断依据是该证据能否承担该论点的力度，而不是它属于哪一类。
   - 证据状态为待补、待核实、不充足的条目，一律汇总进提纲的「待拍板事项」，由用户决定补、降档还是删；**agent 不得自行删改用户已确认的论点**。
4. **信息流安排**：确定各节职能与内容分配（摘要/引言/文献综述/方法/结果/讨论/结论或各章），避免内容重复落位（如摘要与引言互相复制、结果与讨论混写）；学位论文按章排布并给出各章预计篇幅配比。
5. **一致性核对**：提纲与研究问题（00-选题/）、综述缺口（文献综述进度.md）三方交叉核对——每一节都应能回溯到「回答研究问题」的主线；核对结果记入提纲文件。
6. **落盘与拍板**：提纲写入 02-提纲/，作为影响全局的关键决策请用户确认后再进入分节初稿；拍板记录写进 README 阶段确认记录。

## 提纲文件格式
```markdown
# 提纲：<论文题目（暂定）>

> 依据：规范集 <名称>；研究问题 <RQ 引用>；版本与日期

## 结构总览
<按所选规范列章节骨架，每节一句话职能>

## 论点链与证据映射
| 节 | 论证任务 | 核心论点 | 证据（文献库/图表数据） | 支撑实验或图表 | 证据状态 | 备注 |
|----|----------|----------|--------------------------|----------------|----------|------|

> 「证据」栏写来源条目（如 L003/L012、04-图表数据/xxx.xlsx）；「支撑实验或图表」栏写该论点由哪个图、表或分析结果直接支撑（如 图 3、表 2、3.2 节回归结果、访谈编号 A05-A12），未定编号时写图表暂定名与数据源；「证据状态」栏按下表四档之一填写。

| 证据状态 | 含义 | 处置 |
|----------|------|------|
| 充分 | 证据已就绪、可回溯到具体条目，能支撑现有力度的表述 | 按现有力度写 |
| 待补 | 需要的实验、分析或检索尚未做 | 列入待拍板事项，写明补什么 |
| 待核实 | 条目存在但口径、出处或数值尚未核对 | 引用前落实，未落实不得承重 |
| 不充足 | 现有证据不足以支撑该论点 | 降档为弱表述或调整论点 |

## 各节要点
### <节名>
- 要解决的问题：
- 论证路径：
- 预计篇幅/占比：

## 一致性核对记录
- 与研究问题：<核对结论>
- 与综述缺口：<核对结论>

## 待拍板事项
<结构方案如有多个候选，逐一列出依据、代价与收益；证据状态为待补/待核实/不充足的条目，逐条写明补、降档还是改论点的处置方案>
```

## 抽象层级红线
- 提纲只到「节/论点/证据」层级：写论证任务与论点关系，**不写具体段落文字，不写「某处引用某句话怎么措辞」**。
- 允许写「本节用 L003/L012 的实证结果支撑论点 X」；不允许写正文句子的草稿——那是分节初稿阶段的事。
- 图表在提纲中的正确位置：标注「本节配图 <编号>／表 <编号>（数据源：04-图表数据/…）」并写清它支撑哪个论点（即「支撑实验或图表」栏），不在此设计图表的具体呈现细节与配色。
- 提纲阶段只写暂定名（图/表 + 内容指称），正式编号在正文成稿时统一编定；学位论文可按章编（图 3-1）或全文连续编（图 1），选定后全文一致并在 `规范-论文.md` 登记。

## 常见坑
- 结构与规范脱节——先查 规范-论文.md 再动笔；英文论文漏掉 IMRaD 的职能边界（Results 只报发现、解释归 Discussion）是高频错误。
- 论点链断链——节与节之间缺少推进关系，读起来像并列的材料堆；用「这一节的结论为下一节提供什么」逐节自检。
- 证据映射装样子——映射列了但文献库条目实际不存在或未读；Check 阶段逐条回溯。「支撑实验或图表」栏填不出具体图表编号的论点，多数也撑不住。
- 证据状态一路填「充分」——四档形同虚设，待补与待核实项被掩盖到初稿阶段才暴露；填表时按条目实际状态如实标注，宁可多写「待补」。
- 头重脚轻——文献综述占 60%、分析占 10%；按论文类型调整配比并说明理由。
- 提纲定了正文乱改——正文阶段确需调整结构时，先改提纲并经用户确认，再改正文，保持两者同步。

## 注意事项
- 结构方案存在多种可行写法时（方法导向 vs 问题导向、章数取舍），给 2-3 个候选供用户拍板，不擅自定案。
- 提纲经用户确认后进入分节初稿；后续修改提纲同样须先拍板，并同步检查已写正文受影响的节。
- 与 literature-review 联动：证据映射中的每个 L 编号都必须在文献库中存在且获取状态允许引用。
