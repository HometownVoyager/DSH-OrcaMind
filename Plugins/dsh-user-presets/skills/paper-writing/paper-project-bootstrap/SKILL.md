# 论文项目搭建（paper-project-bootstrap）

## 何时使用
- 用户提出新的论文研究与写作需求、且尚未建立项目目录时（先与用户确认论文类型与研究问题，再执行本 skill）。
- 用户要求「开新项目」「建论文项目」「写学位论文/期刊论文/英文论文」时。
- 每轮对话开始检阅项目状态、每阶段结束时更新进度与确认记录。
- 接手已有项目但缺 README.md 或 文献综述进度.md 时：先按本 skill 模板补建（已有内容照实填入，不确定处标注待确认），再展开工作。

## 执行顺序（本 skill 是每个项目第一步）
1. **开工规范检查**（先于目录搭建或同步进行）：检查工作区主目录的 `规范-论文.md`——
   - 存在用户提供的结构/格式规范且完整 → 直接采用，不再询问；
   - 没有、不全，或与默认规范冲突 → 停下询问，给三个方向由用户选：① 选默认集（中文学位论文 spec-thesis-cn / 中文期刊论文 spec-journal-cn / 英文论文 spec-paper-en）；② 新放一份（用户自备规范文档或院校/期刊模板，可等待放入工作区后继续）；③ 由 agent 当场起草（用 web_search 检索、用 web_fetch 打开原文核对），草稿经用户逐条确认后定稿。
   - 选定后落盘 `规范-论文.md`（统一四节骨架）：①来源记录（规范集名称、出处与定稿日期）②结构与目录约定 ③产出格式规范（标题层级、编号体系、图表/引用/摘要格式）④红线与禁忌。选默认集时汇总引用对应 spec skill 的定稿要点，不复制全文。
   - 引用格式随规范一并确定：学位论文按 GB/T 7714；期刊论文以目标期刊投稿须知为最高优先级；英文论文无指定期刊时理工科默认 IEEE、社科默认 APA，向用户确认。
   - 自备规范不全时，在其基础上按所选默认集补全，补全内容标注并经用户确认后并入。
2. **论文登记**：与用户确认本项目收哪些论文；每篇登记编号、题目（或暂定题）、类型（学位/期刊/英文）、写作语言与拟用规范集，写入 README 论文登记表。研究问题未收敛时，登记后先走 research-question 阶段。
3. **目录搭建**（结构如下）。
4. **提示下一步**：每篇论文从「选题与研究问题」阶段开始（research-question），随后进入规范确定（如尚未落盘 规范-论文.md）与文献综述。

## 标准目录结构
每个项目一个目录，位于当前工作目录（或用户指定的目录）下，命名为项目名（用户确认的暂定名即可）：

```
<项目名>/
├── README.md                    # 项目总览：论文登记表、当前阶段、确认记录（最先创建，每轮先读）
├── 文献综述进度.md              # 第二根文档：综述覆盖面与进度（每轮先读）
├── 00-选题/
│   └── research-question.md     # 研究背景、研究缺口、研究问题与假设、可行性初判
├── 01-文献/
│   ├── 文献库.md                # 题录表，按所选规范著录格式，注明获取状态与来源
│   └── 笔记/                    # 每篇文献一档，摘录要点与页码定位
├── 02-提纲/                     # 章节提纲、论点链与证据映射
├── 03-正文/                     # 分节文件（题录/摘要/引言/方法/结果/讨论/各章，一节一文件）
├── 04-图表数据/                 # 数据表、图源与口径说明（数据由用户提供，脚本草稿注明用途与口径）
└── 05-修改记录/                 # 查重自查清单、逐项格式化核查表、逐轮修改记录
```

说明：
- 目录名带数字前缀是为了排序稳定；工作流按 选题（00）→ 文献（01）→ 提纲（02）→ 正文（03）→ 修改（05）→ 定稿 单向推进，分节文件与版本只增不改（重大改版另存新文件）。
- 03-正文/ 分节文件命名规则：前置部分用裸名（如 `摘要.md`、`引言.md`），主体各章用 `ch<编号>-<节名>.md`（如 `ch03-方法.md`）；同一项目内不得两套混用。
- 双根文档：README.md 管项目与阶段；文献综述进度.md 管综述覆盖面与进度，两者每轮都要先读。
- 04-图表数据/ 的每份数据注明来源、统计口径与日期；agent 编写的脚本草稿注明用途与运行方式。
- 全部文件使用 Markdown、UTF-8 编码，标题层级从 `#` 开始。

## README.md 模板
```markdown
# <项目名>

- 项目说明：<一句话，本项目收哪些论文>
- 规范集：<规范-论文.md 所选规范集名称与引用格式>（见工作区 规范-论文.md）
- 当前阶段：<选题与研究问题 / 规范确定 / 文献综述 / 提纲与论证结构 / 分节初稿 / 修改与查重自查 / 格式化与引用定稿>
- 当前状态：<一段话说明各篇论文推进到什么程度>
- 下一待确认事项：

## 论文登记表
| 编号 | 题目（暂定） | 类型 | 写作语言 | 拟用规范集 | 状态 | 备注 |
|------|--------------|------|----------|------------|------|------|

## 阶段确认记录
| 日期 | 论文 | 阶段 | 确认内容 | 用户裁决 |
|------|------|------|----------|----------|

## 进度记录
| 日期 | 完成内容 | 文件 |
|------|----------|------|
```

## 文献综述进度.md 模板
```markdown
# 文献综述进度

- 研究问题：<当前研究问题一句话，随选题阶段演进更新>
- 检索策略：<数据库/来源 + 检索词组概要（详见 01-文献/ 检索记录）>
- 覆盖面：<已覆盖的主题脉络与来源类型；明显缺口如实列出>
- 下一步检索计划：

## 综述脉络（按主题组织）
| 主题 | 代表文献 | 核心发现/分歧 | 笔记档 | 状态 |
|------|----------|----------------|--------|------|

## 更新记录
| 日期 | 新增/更新内容 |
|------|----------------|
```

## 执行步骤
1. 与用户确认项目名（暂定即可）、论文清单、各篇类型与用途（学位/期刊/课程/会议）；不确定先求证，不凭空假设。
2. 执行开工规范检查并落盘 `规范-论文.md`（见上）。
3. 创建目录与骨架文件：README.md 与 文献综述进度.md 最先创建并填写已知信息；子目录创建后可各放一个索引文件说明用途。
4. 接手已有项目补建时，README、登记表与综述进度按现有内容照实填写，无法确认的条目标注「待确认」并列入下一待确认事项，不凭空补写。
5. 搭建完成后，把项目目录路径与结构告诉用户，并说明下一步（逐篇论文从选题与研究问题开始）。

## 注意事项
- 不要在没有项目目录的情况下把提纲或正文写进零散文件——后续引用核查、进度与阶段管理都依赖这个结构。
- 每轮工作以双根文档为入口：有则先读再干活，无则先建再干活。
- 同一项目多篇论文时，每篇独立走完七个阶段；不同论文的正文与修改记录在文件名上区分（编号前缀），不混放。
- 用户已有自己的目录习惯时尊重用户结构，但至少保证 README、文献综述进度.md 与六个子目录可被找到。
- 规范-论文.md 是唯一规范事实源：修改规范须先经用户拍板并同步更新该文档。
