# 修改与定稿（paper-revision）

## 何时使用
- 项目处于「修改与查重自查」阶段，各节初稿完成后逐轮修改时。
- 项目处于「格式化与引用定稿」阶段，需要按所选规范逐项格式化核查与定稿判定时。
- 用户要求「改一遍」「检查格式」「准备定稿/投稿」时；「投稿前检查」「以审稿人视角看一遍」走第 2 步对抗性自审。

## 执行顺序

### 1. 逐轮修改（每轮一轮记录）
- **一致性**：术语、符号、缩略词全文统一；正文数字与 04-图表数据/ 逐条对应；引用与文献库条目一一对应；与已确认的研究问题、提纲、口径不冲突。
- **连贯性**：节内段落衔接、节间过渡；每节开头与上节结论呼应；论证链无断点。段落级判定用 academic-drafting 的「段落体检」五条判据逐段过一遍，整节判定用「反提纲」。
- **论证完整性**：每个论点有证据、每条证据可回溯、结论不超出数据支持力度；规范性与实证性内容分开或明确标注。
- 每轮修改落 `05-修改记录/修订-<论文编号>-<轮次>.md`（改了什么、为什么、影响哪些节）；重大结构修改先回 paper-outline 经用户确认。
- **编辑权限边界**：agent 的职责是指出结构问题与证据问题，而不是把问题段落粉饰过去；但段落的删除与重写须经用户裁决。发现某段无证据、论点不成立或位置错误时，写入修订记录的「遗留待确认」并列出处置方案（补证据 / 改论点 / 降档 / 删除），由用户拍板后执行；**不得自行删改用户已确认的论点、结论与贡献表述**。

### 2. 投稿前对抗性自审（以审稿人视角通读全稿）
把自己当成最挑剔的审稿人，逐维检查并给出证据，然后按风险排序修订。每一问都标注处置结论：`通过` / `需修订` / `需补证据`。
1. **贡献**：本文给读者的新知识是什么；解决的是有意义的问题还是顺手可做的小问题；思路是否超出既有做法的常规延伸；结论是意料之中还是有信息量；贡献类型（问题界定、数据与口径、分析框架、机制解释、经验发现、边界澄清）至少有一项明确成立。
2. **表达清晰**：同行读者能否据本文复现研究过程；关键环节的细节是否足够；每个设计要素的动因是否交代且与要解决的问题相连；术语与符号是否全文一致；每段是否只有一个消息且衔接顺。
3. **证据强度**：支撑核心论点的证据是否足够有力，而非仅达到勉强可用；结论的绝对水平是否站得住；不同数据、样本、时期或口径下结论是否稳定；正反两面的结果是否都如实报告。
4. **证据完整性**：每一项关键设计选择是否都有对应的检验或比较；最强的竞争性解释与相关研究是否都在场且比较条件公平；测量与口径是否恰当；材料或样本是否足以支撑结论所声称的适用范围；比较与检验的过程记录是否清楚。
5. **研究设计可靠性**：设定是否贴近真实情形；是否存在未言明的假设或推演漏洞；结论是否依赖逐案调参或事后筛选才能成立（若是，属于设计问题而非写作问题）；新增的复杂度与其代价是否相称；审稿人是否有理由判定本文的净收益为负。
自审结果落 `05-修改记录/` 对应文件，输出一张按风险排序的清单：会导致退稿或拒收的问题在前，表达清晰问题在中，文字润色在后；每条给出**具体的修改建议**，不能只列问题不给方案。

### 3. 占位符纪律
- 数据、引用、样本量、口径、时间范围不编造。需要用户补的一律写明确占位符：`[待补数据：指标口径与来源]`、`[待引用：文献库编号]`、`[待核实：表述与原文对照]`。
- 交付时把全部占位符汇总成「待补清单」，逐条说明它影响哪些节与哪些结论；占位符未落实前，相关表述按证据强度与措辞分级规则降档处理，不得按原力度保留。
- 占位符不得用于掩盖信息缺失，也不得在用户要求成稿时无声保留；`[待核实]`、`[待补]` 一类的标记在定稿前必须清零或转入明确的待办。

### 4. 查重自查（自查清单，非查重承诺）
- 直接引用：逐条核对是否标注引号/出处、篇幅是否必要；改写（paraphrase）处逐条核对是否标注来源。
- 自引与凑数引用：与自己论点无关的文献删除；强制自引剔除。
- 数据与表述复用：与他人已发表成果的重复表述重写；不得在正文与图表中重复展示同一数据。
- 自查结果落 `05-修改记录/查重自查-<论文编号>.md`；明确声明这是引用与改写纪律自查，不承诺通过任何查重系统检测。

### 5. 逐项格式化核查（按 `规范-论文.md` 所选规范集）
- 按对应 spec skill（spec-thesis-cn / spec-journal-cn / spec-paper-en）的格式条款逐项过表：结构完整性、标题层级与编号体系、摘要与关键词规格、图表格式（编号/图题表题位置/三线表/自明性）、公式编号与转行、术语与计量单位统一、文中标注与参考文献表一一对应、著录格式与类型标识。
- 核查结果逐项落 `05-修改记录/格式化核查表-<论文编号>.md`（条款/结果/处置）；未通过项修复后复核。
- **参考文献表生成**：把文献库 L 编号映射为目标规范要求的引用序号（顺序编码制按正文出现顺序、著者-出版年制按著录字母序、IEEE 按出现顺序编号），映射对照表随本轮记录落 `05-修改记录/`；正文标注与文献库条目一一对应后方可定稿。

### 6. 交付前校验（报告完成之前必须过一遍）
1. **交付物齐全**：约定的分节文件、图表文件、参考文献列表、修订记录与自查文档都在，路径与文件名与 README 登记表一致。
2. **无残留占位符**：全文检索 `[待补`、`[待引用`、`[待核实`、`TODO`、`XX` 一类标记，命中项要么已落实，要么列入待补清单并说明影响范围；不得直接报「已完成」。
3. **编号与指向关系**：图表编号连续、正文引述与图表一一对应；引用标记与参考文献表双向对得上（无列而不引、无引而不列）；交叉引用无失效指向。
4. **体例统一**：文中标注体例全文一致（不混用顺序编码制与著者-出版年制）；中英文标点与全半角统一；术语、单位、缩略词统一。
5. **格式可交付**：文件能正常打开，页数与篇幅符合所选规范或目标要求；图表在正文中按「先见文后见图表」出现。
6. **向用户报告结果**：交付路径、篇幅、仍待用户处理的事项（未落实的占位符、待拍板的处置方案、需要用户核对的引用）。**报告以实际核查结果为准，不因流程走完就声称通过。**

### 7. 定稿判定（四条件，全部满足才可定稿）
1. 逐项格式化核查表全部通过；
2. 查重自查完成且发现的问题已处置；
3. 正文每个数字、每条引用可回溯 01-文献/ 与 04-图表数据/ 的对应条目；
4. 用户确认内容与结构无异议。
- 定稿后归档：定稿版文件在 03-正文/ 分节文件基础上汇出定稿版（定稿文件加「定稿-v<n>」后缀，03-正文/ 分节文件保留不删），README 登记表状态更新为定稿，阶段确认记录记录用户裁决；定稿后修改视为新修订轮次，先经用户拍板。
- 第 3 条的判定依据同时看提纲的「证据状态」栏：仍存在「待补」「待核实」「不充足」的条目，说明对应论点尚无支撑，不得进入定稿。

## 修订记录格式
```markdown
# 修订-<论文编号>-<轮次>（<日期>）

- 触发原因：<用户意见/自查发现/对抗性自审/格式核查>
- 修改内容：<逐条列出，注明节与位置>
- 影响范围：<受影响的节/图表/文献引用>
- 自审处置：<五维自审中标为需修订/需补证据的条目及处置结论>
- 遗留待确认：<如有；含待拍板的删除与重写方案>
- 待补清单：<未落实的占位符及其影响范围>
```

## 定稿判定四条件之外的红线
- 未经用户确认的「待核实」「推测/待拍板」内容残留 → 不得定稿。
- 参考文献表与文中标注不一一对应（列而不引/引而不列）→ 不得定稿。
- 以「范围局限」「有待扩展」一类措辞掩盖会影响结论成立的缺陷 → 不得定稿；此类问题必须如实披露，或由用户裁决是否调整结论的适用范围。
- 对抗性自审中标记为「需补证据」的条目未处置（未补证据、未降档、未由用户裁决）→ 不得定稿。
- agent 产出的内容始终是协助性草稿：定稿前提醒用户通读确认，学术责任在作者本人。

## 常见坑
- 只改文字不改结构问题——论证断链的问题文字改不好，回到提纲。
- 自审走过场——五维问题全填「通过」而不给证据，等于没审；每问都要指到稿中的具体位置与具体证据。
- 只列问题不给方案——自审清单写成批评信，用户拿到后无从下手；每条都要附具体修改建议。
- 占位符留在稿里不汇总——`[待补…]` 散落各处，交付时未列清单，用户误以为稿子已完整。
- 查重自查走过场——逐条过清单，发现的每处都写处置结果。
- 格式核查凭印象——逐项对照 spec skill 条款打勾，不通过项写明处置。
- 越权删改——发现段落无证据就直接删掉或改写用户已确认的论点；正确做法是列入待拍板清单请用户裁决。
- 定稿后又随手改——定稿后的任何修改走新修订轮次并经用户拍板，保持版本可追溯。

## 注意事项
- 修改顺序建议：先结构（对照提纲）、后段落（连贯与论证）、再自审（五维风险）、最后格式（逐项核查表）——格式改在结构问题解决之前是白工。
- 每轮修改更新 README 进度与阶段确认记录；定稿状态在 README 登记表中唯一可信。
- 投稿前自审可在写作前期就作为自查清单使用，不必等到全部完稿；早期发现「需补证据」的条目，比定稿前返工代价小得多。
