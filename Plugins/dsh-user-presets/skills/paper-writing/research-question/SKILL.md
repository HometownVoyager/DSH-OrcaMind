# 选题与研究问题（research-question）

## 何时使用
- 项目处于「选题与研究问题」阶段、需要在 00-选题/ 落盘 research-question.md 时。
- 用户只有一个模糊方向（如「想写数字化转型相关的论文」）需要收敛为研究问题时。
- 研究问题范围过大、无法回答或资料不可得，需要重新界定边界时。
- 开题报告、开题答辩准备需要陈述研究问题时。

## 执行顺序
1. **研究背景与动机**：梳理问题的现实背景与理论/实践动机——为什么现在值得研究、谁会关心研究结果；说明性内容以完整复合句陈述因果链条。
2. **研究缺口界定**：检索已有研究（配合 search-query-craft 构建检索词，literature-review 落库），归纳已有工作的共识与分歧，指出「已有研究没有回答/回答得不好」的具体缺口；没有检索支撑的「缺口」不得写进 research-question.md（标注「推测/待检索核实」）。
3. **研究问题收敛**：把方向收敛为明确、可回答、有边界的研究问题，逐一检验——
   - **明确**：一句话能说清问的是什么（对象 + 现象/关系 + 语境）；
   - **可回答**：存在可行的数据/文献/方法路径回答它，而不是纯价值判断；
   - **有边界**：时间、范围、对象界定清楚，写明「不研究什么」。
   - 学位论文可附研究假设或子问题分解；英文论文（IMRaD）在此阶段同步考虑研究假设的表述。
4. **可行性与资料可得性初判**：数据来源是否存在且可得（付费墙内文献与数据按预设辅助边界，由用户提供）、方法是否在用户能力与时间内可行、伦理与合规风险；不可得项如实标注并列待确认清单。
5. **落盘与登记**：写入 00-选题/research-question.md，登记进 README 论文登记表；研究问题经用户确认后才进入文献综述与提纲阶段。

## research-question.md 模板
```markdown
# 研究问题：<一句话>

## 研究背景与动机
<现实背景 + 理论/实践动机，因果链条完整>

## 研究缺口
- 已有研究的共识与分歧：<条目化，注明文献库条目>
- 本研究的缺口：<具体到「什么问题没有被回答/回答得不好」>

## 研究问题（与假设）
- 主问题：<RQ1>
- 子问题/假设：<RQ1a / H1 …（如有）>

## 边界界定
- 研究范围：<对象、时间、地域、行业等>
- 不研究：<明确排除项>

## 可行性初判
- 数据/文献可得性：<来源与获取状态；不可得项标注待确认>
- 方法可行性：<初判方法路径>
- 风险与伦理：<如涉及>

## 待确认清单
<列出需用户拍板的问题>
```

## 常见坑
- 题目过大（「论中国数字经济」）——收敛方法：限定对象/时间/机制/数据可得的一个切面。
- 把主题当问题（「研究中小企业融资」没有问号）——改写为可回答的问句或可检验的关系陈述。
- 缺口靠感觉——没有检索记录支撑的缺口一律不得作为立论前提。
- 一题多问——一篇论文回答一个主问题，子问题必须服务于主问题；多余的拆出去。
- 价值判断冒充研究问题（「应当如何提升企业社会责任」）——改写为可实证的问题（现状如何、机制是什么、效果如何），规范性结论留到讨论节。

## 注意事项
- 研究问题的确定是影响全局的关键决策：必须经用户拍板后才进入下一阶段，拍板记录写进 README 阶段确认记录。
- 后续阶段发现研究问题需要调整时，先向用户说明影响（提纲、已读文献、正文哪些部分要返工），经确认后同步更新 research-question.md 与 README。
- 与 01-文献/ 联动：缺口表述引用文献库条目编号，保证可回溯。
