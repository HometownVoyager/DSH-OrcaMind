# 默认规范集共用底座（spec-common）

> 用途：本 skill 是各预设 spec-* 规范集的**共用底座**，凡加载任一 spec-* 都必须与之同时加载。规范集的**本域内容**（来源记录条目、结构、要素格式、红线与该域执行要求）在各 spec-* 文件里；**四节骨架的定义、来源记录的写法、执行要求的性质与纳入方式**以本文件为准，各 spec-* 不重复这些部分。

## 何时使用
- 开工规范检查选定默认规范集后，加载对应 spec-* skill 时一并加载（缺一不可）。
- 落盘 `规范-<域>.md` 时，以及此后每轮 Check、产出校对对照规范文档时。

## 四节骨架（写入 规范-<域>.md 时逐节对应）
1. **①来源记录**：所选规范集的名称、出处与定稿日期；规范集自带的标准条款（标准号、标准名、发布与实施日期、可核验链接）逐条列出。
2. **②结构与目录约定**：整体结构、各部分职能、项目目录与命名。
3. **③产出格式规范**：标题层级、编号体系与要素格式（图表、引用、摘要等按域而定）。
4. **④红线与禁忌**：不可逾越的底线与常见错误。

## 写法通则
- **汇总引用而非复制全文**：选默认集时，`规范-<域>.md` 汇总引用对应 spec-* 的定稿要点，不整篇复制。
- **来源记录只留可核验项**：只写标准号、标准名、发布与实施日期、可核验链接与定稿日期；不留内部工作编号与检索过程记录。用户自备规范时，记录其名称与提供方式。
- **唯一规范事实源**：规范文档落盘后，每轮校对与产出都以它为准；修改规范须先经用户拍板并同步更新该文档。
- **执行要求节**：各 spec-* 末尾的「执行要求（写入 规范-<域>.md 时随结构节一并纳入）」是该规范集特有的执行细则，落盘时随对应结构节一并纳入规范文档，不另立一节堆在文末。

## 注意事项
- 本文件只写跨域共用的部分；凡具体领域的判据、要素、格式与红线一律写在对应的 spec-* 文件里。
- 多个 spec-* 之间出现冲突时，以开工规范检查选定的那一套为准；用户提供规范时，以用户规范为最高优先级。
