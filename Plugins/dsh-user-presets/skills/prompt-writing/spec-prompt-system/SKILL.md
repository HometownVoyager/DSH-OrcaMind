# 复杂系统型提示词规范（spec-prompt-system，定稿版 2026-09-10）

> 用途：开工规范检查选默认集「复杂系统型」时，本 skill 是 `规范-提示词.md` 的内容母本（四节骨架、写法通则与执行要求的纳入方式见 spec-common；落盘时记录来源为「本预设默认集·复杂系统型（2026-09-10 定稿）」）；系统提示词的设计、起草与测试阶段随时对照执行。目标平台有官方系统提示词指南且要求更具体时，以其为最高优先级。

## ① 来源记录
- 系统提示词工程最佳实践（角色/边界/工作流/示例/输出契约分层结构，社区系统提示词模式与主流模型行为特性综合整理）；
- 定稿时间：2026-09-10（据检索摘要提炼，用户确认定稿）。

## ② 结构与目录约定
- 分层结构（自上而下）：①**系统身份与使命**（角色、服务对象、核心目标）→ ②**能力与边界**（明确「不做什么」，越界时的应答策略）→ ③**工作流**（分步指令：输入分类 → 分支处理 → 收尾校验；每步有明确触发条件）→ ④**规则与约束**（风格、格式、安全、优先级仲裁规则——规则冲突时谁覆盖谁）→ ⑤**示例**（few-shot：至少一正例一边界例，覆盖典型与易错输入）→ ⑥**输出契约**（格式模板 + 异常/降级输出格式）。
- 配套测试基线：04-测试/用例集.md 固化边界用例（正常/越界/对抗/空输入），每版改动跑基线后交付。
- 项目目录按「版本与测试档案制」（prompt-project-bootstrap）；历史版本只增不改。

## ③ 产出格式规范
- Markdown 分节标题 + 编号；规则条目可被单独引用（引用格式「规则 3.2」），便于测试记录回溯。
- 版本管理：提示词文件头部含版本号、变更摘要、日期；重大变更在新版本文件中，不改写旧版。
- 交付物三件套：提示词正文 + 用例集 + 测试记录（逐版追加，含未通过项与处置）。

## ④ 红线与禁忌
- 禁止示例与规则冲突（示例是隐含规则，冲突时模型行为不可预期）；禁止正反例只给正例。
- 禁止指令稀释：与核心任务无关的规则不入系统提示词；总长度与规则数控制在可维护范围。
- 禁止无测试即交付：任何修改必须过用例集基线；禁止在历史版本文件上覆盖修改。
- 禁止把用户数据假设写死（模型/上下文长度/可用工具须作为需求澄清项记录在 01-需求/，不臆测）。

## 执行要求（写入 规范-提示词.md 时随结构节一并纳入）
- 起草前需求契约与结构设计未经确认的，不得进入草稿；六层结构逐层落点，工作流每步有触发条件，规则区必须含优先级仲裁（规则冲突时谁覆盖谁）。
- 测试与迭代阶段按 prompt-testing 执行完整基线：正常/越界/对抗/空输入四类用例全过才算本轮通过；未通过项的修改重跑基线并留痕测试记录。
- 交付阶段按 prompt-revision 核查：六层齐全、规则可引用、示例含正例与边界例、三件套齐全、历史版本未覆盖。
