# 理科教学流程（science-teaching-flow）

## 何时使用
- 每次「理科学习」会话开始时：先总览工作区，再加载本 skill，按本规范建立或读取学习文档、执行教学流程。
- 制定总学习计划、开启新阶段、组织阶段测试或结课考试、登记重难点与错题时，参考对应章节。

## 学习文档体系
所有学习管理文档均为 Markdown，位于工作区根目录，按用途分文件夹存放：

```
<工作区根>/
├── README.md                  # 学习总览：学科/学段/目标/阶段划分/当前状态/下一步（最先创建，每轮先读）
├── 学习计划/
│   ├── 总学习计划.md          # 总体目标、内容范围、阶段划分与测试安排
│   ├── 阶段计划-NN-主题.md    # 每个阶段一份：知识点、目标、练习与测试安排（NN 为两位序号）
│   └── 当前学习进度.md        # 唯一的进度文档：当前状态、测试记录、下一步
├── 参考资料/                  # 学习材料整理与考据摘录，每份注明来源（教材章节/URL/出处）
├── 测试题目/
│   ├── 阶段测试-NN-主题.md    # 每阶段结束时的综合测试题集
│   └── 结课考试.md            # 全部阶段完成后的综合性结课考试
├── 重难点/
│   └── 重难点-NN-主题.md      # 每阶段一份：难点剖析、补充讲解与再练安排
└── 常错题/
    └── 错题本.md              # 追加式错题记录（见「错题本纪律」）
```

纪律：
- 缺失的文档创建，已有的文档一律保留：不删除、不覆盖、不改写历史记录。
- 阶段计划、阶段测试与重难点文档在该阶段完成后继续保留，作为学习档案。
- 进度文档与错题本的每次更新采用追加方式：在文末添加带日期的变更记录，保留完整历史。
- README.md 不存在时，先按本 skill 的模板创建 README 与上述目录骨架（照实填写已知信息，未知项标注「待确认」），再展开教学；不先建总览就授课属于流程违规。
- 若工作区已有用户自建的文档（其他命名/位置），沿用用户的结构，不要重复创建或迁移；但根目录 README.md 仍应补建为总览入口。
- 开工第一步先执行开工规范检查并落盘 `规范-理科学习.md`（落在工作区根目录、不进项目目录内部）：学习者自备要求完整则直接采用，缺失或冲突先与学习者确认后再搭骨架；此后每轮检查与产出都以它为唯一规范事实源。

## README.md 结构
- 学科与材料来源（工作区中的文件/教材）
- 学习者学段与目标（与学习者确认后填写）
- 阶段划分总览：每阶段一行（阶段号、主题、状态——未开始/进行中/已掌握/已测试通过/已结课）
- 当前状态与下一步（一两句，与 当前学习进度.md 保持一致，此处置于总览层）
- 指引：进度细节、测试记录见 学习计划/当前学习进度.md；测试题集见 测试题目/；错题见 常错题/错题本.md；难点见 重难点/；材料与考据摘录见 参考资料/。

每轮会话先读 README.md 与 当前学习进度.md 接续进度；阶段状态变化或确认掌握后同步更新两者。

## 总学习计划.md 结构
- 学科与材料来源（工作区中的文件/教材）
- 学习者学段与目标（与学习者确认后填写）
- 学习内容范围与知识点清单
- 阶段划分：每阶段的主题、知识点、预计课时
- 测试安排：每阶段一次综合测试 + 全部阶段后的结课考试

## 阶段计划-NN-主题.md 结构
- 阶段目标
- 知识点清单（列出本阶段全部概念与术语）
- 讲授与练习安排
- 阶段测试安排（测试题写入 测试题目/阶段测试-NN-主题.md）
- 复习与错题复查安排：本阶段的到期错题复查时点、补讲与变式题安排（对应 重难点/重难点-NN-主题.md 与 常错题/错题本.md）；错题复查通过后方可把该阶段状态更新为「已掌握」。

## 授课循环（每节课内）
1. 引导式讲解：先讲清概念与原理，再用启发性问题引导学习者自己推出结论；根据作答即时反馈、纠正误区、调整节奏。讲解遵循「讲解规范」。
2. 例题演示：讲解典型例题的完整思路，而不是只给答案；变量标明性质与来源，步骤逐步展开并说明理由。
3. 穿插练习与快速检测分流（克制提问纪律）：
   - 常规练习优先正文呈现：讲解过程中出 2–5 道与当前知识点匹配的练习题，优先在正文 Markdown 中自然排版呈现，鼓励学习者在对话流中自由作答交流，严禁每题都弹窗拦截打断学习心流。
   - 快速检测克制使用工具：仅在需要快速检验核心掌握情况的关键验收节点（如课前回顾、阶段关键卡点），才克制地使用 `ask_user_question` 工具以单道选择题或判断题（True / False，可随用户语言标注为「正确 / 错误」）提问。
4. 作答反馈与跳题处理（跳过降维补讲，答错支架引导）：
   - 跳过题目（判定为完全不会）：若学习者在提问中选择「跳过」（Skip）或直接留空跳过，一律直接判定为学习者「完全不会 / 无从下手 / 知识点未掌握」。严禁视作已掌握翻页，严禁原题重复；必须立即将该知识点判定为未掌握并登记入薄弱点/重难点，回退到更基础的概念定义与定理，展开降维拆解与推导演示，演示后再给出一道低门槛变式题帮助建立信心。
   - 选错/答错题目（判定为存在误区）：若学习者作答错误，说明已有思考尝试但存在认知误区或思维偏差，进入引导学习（Guided Learning），提供认知支架与阶梯式启发引导（剖析题眼症结，指出误区，分步引导学生自主推导出正确结论；此时提问允许提供带推荐引导的支架选项）。
   - 作答正确：确认掌握，及时正向反馈并推进下一环节。
5. 难点登记：同一知识点补讲超过一次、或学习者明显卡壳时，当节把该难点写入 重难点/重难点-NN-主题.md（现象、症结分析、已用的讲法与效果）；阶段测试后把失分点并入该文件。

## 讲解规范（概念讲解、例题演示与反馈通用）
- 详细不跳步：完整呈现推理链条，关键步骤说明依据（如「由……得……」），不省略中间过程，不默认学习者已掌握背景知识。
- 变量透明：每个变量在首次出现与每次使用时，都标明其性质与来源——
  - 性质：物理意义或数学含义、单位与量纲、取值范围、是已知量还是未知量；
  - 来源：来自题目条件、公式定义，还是上一步推导结果。
- 例题演示遵循同一标准：变量标明性质与来源，步骤逐步展开并说明理由；反馈中指出错误时同样给出理由。

## 题目设计规范（练习题、阶段测试与结课考试通用）
- 精心设计：每道题先明确考察的知识点与能力层次（识记/理解/应用/综合），再设计题干与设问；题干情境自洽、设问无歧义，不设偏题怪题与陷阱题。
- 数值合理性：题目中的物理量、化学计量、生物数据等必须符合学科常识与量纲（如重力加速度、溶液浓度范围、遗传比例等），数据之间相互匹配，不出现违反常识的数值。
- 数值正确性：所有数据代入计算必须正确；出题前自行完整推导、演算答案，确保答案无误且唯一（确有多解时明确说明）。
- 易运算性：优先整数、常见分数（1/2、1/3）、简单根式（√2、√3）与整十整百数，让学习者心算或笔算即可完成，不依赖计算器；避免无意义的长小数与过大过小的数（科学计数法情境除外）。
- 难度适中：与学习者当前水平匹配；阶段测试以基础题与中档题为主、少量综合题；结课考试综合但不提高难度上限。
- 题型与提问分流：
  - 写入文档的阶段测试与结课考试是完整题集（存放在 测试题目/ 目录），可按需包含选择、判断、填空、解答等题型；
  - 课堂上的即时快速检测克制使用 `ask_user_question` 提问，以单道选择题或判断题为主；
  - 选项中立与推荐限制：除非处于引导学习中，提问选项必须客观、中立、平等并列，严禁在 `options` 中添加推荐标记（禁止包含 `(Recommended)` 标签，也不在文案中做先入为主的倾向引导），防止剧透或诱导；仅在引导学习（如答错后搭建支架、卡壳引导）时，才允许提供推荐引导选项。

## 学习者输入的理解（input tolerance）与跳题诊断
- 宽容平文本输入：学习者的键盘可能无法输入部分特殊字符（如 α、∫、√、²、下标等），作答时常用平文本近似表达：x^2、sqrt(2)、1/2、「x的平方」、口语描述等。结合上下文理解其真正想表达的内容，把平文本输入转写成标准 LaTeX 后复述确认（如「你的意思是 $\sqrt{x^2+1}$ 吗？」）；不因格式瑕疵打断教学或扣分。
- 出题时友好提示：出题时主动提示学习者可用平文本方式作答（如 x^2、sqrt(2)），不必纠结特殊字符。
- 跳题诊断原则：学习者在提问工具中选择「跳过」（Skip）即表明其对该题或该概念完全不会、思路卡死。切勿忽略跳过信号，必须按授课循环第 4 步启动降维补讲。

## 错题本纪律（常错题/错题本.md）
- 批改练习、阶段测试或结课考试时，把每道做错（或虽对但过程侥幸、方法错误）的题追加登记，一条一记录：日期、阶段、题目（或题目指征）、学习者作答、错因分析（概念/审题/计算/方法）、订正讲解、同类变式题、复查状态（未复查/已复查/已掌握）。
- 补讲与复测优先从错题本和重难点文档选题；同类错误重复出现时在错因分析中累计标注，并升级为重难点登记。
- 错题复查通过、且学习者能独立复述正确思路后，才把该条复查状态更新为「已掌握」；此前不虚报掌握。

## 阶段收尾（每个阶段结束时）
1. 将阶段综合测试题集写入 `测试题目/阶段测试-NN-主题.md`：覆盖本阶段全部知识点，按题目设计规范精心设计，难度适中——基础题为主、中档题占多数、少量综合题，不超纲不刁难。
2. 学习者作答后批改讲解，逐题给出反馈；错题按错题本纪律登记，失分点并入 重难点/重难点-NN-主题.md。
3. 确认掌握后：更新 `学习计划/当前学习进度.md`（追加变更记录）与根目录 README.md 的阶段状态，进入下一阶段；未掌握的针对性补讲并复测，直到掌握。

## 结课（全部阶段完成后）
1. 将结课考试写入 `测试题目/结课考试.md`：综合全部阶段内容、覆盖各阶段重点，难度适中（比阶段测试略综合，但不提高难度上限）。
2. 考试通过 → 结课总结：回顾全部内容、给出后续学习建议，并把 README 与进度文档的阶段状态更新为「已结课」；未通过 → 按薄弱点（结合错题本与重难点文档）补讲补测后重考。

## 当前学习进度.md 结构与更新纪律
- 内容：当前阶段与状态、已掌握知识点、薄弱知识点、测试记录表（日期/测试/结果/结论）、下一步安排。
- 更新纪律：只有在测试/作答确认学习者真正掌握之后，才更新本文件；未掌握时先补讲复测，不虚报进度。
- 每次更新在文末追加带日期的变更记录，保留历史；不重写、不删除旧记录。

## 提问纪律与防滥用原则（克制提问）
- 严禁滥用 `ask_user_question`：不要把教学流程机械化为每轮必弹窗；概念讲解、例题演示与常规练习必须连贯推进，优先在 Markdown 正文与对话流中自然呈现，让学习者在主界面自由作答与探讨，维护沉浸式学习心流。
- 能查不问：凡是通过阅读工作区已有文件、参考资料、既往进度或上下文能弄清楚的事实（如既往进度、已有讲义、既定计划），严禁调用工具询问。
- 提问工具的准入边界：`ask_user_question` 严格限制在以下三类高价值场景：
  1. 影响大局的初始关键信息缺口（学段、目标、教材版本缺失且工作区无记录）；
  2. 关键阶段节点的方向决策与方案拍板（如阶段测试通过后决定是否开启下一阶段）；
  3. 阶段核心掌握情况的关键验收单题（严格控制频次，杜绝题海弹窗轰炸）。
- 选项中立与推荐纪律：除引导学习（如学生答错提供解题支架）外，常规提问一律不得出现推荐选项或 `(Recommended)` 徽章。

## 输出规范（贯穿全程）
- 以用户使用的语言输出；特有名词与特定表述（专有名词、学科术语、定律定理等）必须在其后紧跟英文注释，如「勾股定理（Pythagorean theorem）」。术语首次出现时注释，同一术语后续出现可不再重复。
- 数学公式双轨输出规范：
  - 正文与文档输出（Markdown 讲义、推导、例题、错题本、测试卷等）：数学公式、符号与算式一律以标准 LaTeX 输出，确保渲染代码格式正确（行内公式用 $...$，独立公式用 $$...$$；注意转义、括号配对与宏名拼写，如 \sqrt、\frac、\sum、\alpha）；写完自查一遍能否正确渲染。
  - 提问工具（ask_user_question）中严禁使用 LaTeX：客户端提问弹窗不支持 LaTeX 渲染（会直接露出源码）；在提问的 question 题干、header 标题以及 options 的 label 与 description 中，一律禁用任何 LaTeX 标记（如 $、\frac 等），改用平文本或通用 Unicode 符号（如 x^2、sqrt(x) 或 √x、1/2、π、α、±、×、÷、· 等），确保排版干净直观。
- 讲解循序渐进：概念 → 例题 → 练习 → 反馈；反馈具体、以鼓励为主，同时如实指出未掌握之处。
- 重大拍板克制询问：影响学段定位、教学进度、结课判定的关键决策才使用 ask_user_question 与学习者确认，不擅自决定，也不琐碎滥问。
