# 设定集维护（story-bible）

## 何时使用
- 新作品开工时填充 `00-设定/`。
- 每次剧本写作引入新设定/新角色/新场景时，同步更新。
- 用户询问"某某设定是什么"时，先查设定集再回答。

## 基准事实优先（Anchors First）——本 skill 的第一原则
传统做法把出生年月散落在角色小传、住宅散落在世界观、称呼散落在对白，导致长篇写作必然出现事实漂移。本原则要求：**可被唯一确定的常量事实先集中进 `00-设定/anchors.md`，角色档案与世界观的展开以它为纲、只引用不复制。**

1. **写角色档案前先填锚点**：建立 characters/ 档案之前，先把该角色的出生/基准年龄、关键节点年龄与生理核心事实写进 anchors.md 第一节「年龄与生理时间轴矩阵」，把系统 Speaker ID 与各视角对 TA 的称谓写进第三节「称谓三层解耦网格」。角色档案里的年龄、称呼字段一律引用锚点，不另行撰写第二套口径。
2. **写世界观/地理前先出空间拓扑**：编写 geography.md 与 world.md 之前，先把常驻空间写进 anchors.md 第二节「空间拓扑与动线模型」——建筑属性（楼层/电梯或步梯）、户型、动线连接与声光穿透法则。世界观的规则、历史写 world.md，但空间物理事实归锚点。
3. **信物与体态进锚点**：重要信物的来源、佩戴/持有阶段与转赠去向写进 anchors.md 第四节「核心资产与体态状态机」；角色不可变外貌特征（发型/发色/瞳色）写进「体貌锚点」。
4. **先锚点后正文**：凡正文将要用到的新事实（新角色年龄、新场景空间、新信物），先在 anchors.md 补录并经用户确认，再写进正文。锚点未锁定的内容不进入正文。
5. **锚点是单一事实源**：角色档案、geography.md、timeline.md 与正文均不得与 anchors.md 冲突；发现冲突时以锚点为基准修正其他文档（锚点本身要改则先请用户裁决，见 continuity skill）。timeline.md 里的事件日期序列是锚点年龄矩阵的展开，两者必须同源。

## 文件与模板

### anchors.md —— 全局基准事实层（见 vn-script-project-bootstrap 的模板）
年龄与生理时间轴矩阵、空间拓扑与动线模型、称谓三层解耦网格、核心资产与体态状态机。设定集阶段内全量填写并经用户确认，此后正文只读不写。

### world.md —— 世界观
覆盖：世界概述（一句话）、核心规则（力量/科技/魔法等机制，写明代价与边界——没有代价的能力会破坏故事张力）、历史与关键事件、社会结构（制度、阶层、文化习俗）、与主题的关联（世界观规则如何服务主题与主线因果）。地理与势力分别写入 geography.md 与 factions.md，不再并入本文件；其中的空间物理事实（楼层/动线/门窗位置）先归 anchors.md 空间拓扑，本文件只引用。
规则必须能服务剧情，不堆砌无用设定。

### factions.md —— 势力与组织
各势力的名称、定位、目标、资源与冲突格局；与主要角色的隶属或对立关系。与小说预设同粒度，便于跨项目引用。

### geography.md —— 地理与地点
地点列表：名称、位置关系、气候与风貌、功能、出现章节；同一地点跨场景的空间布局一致性——门在哪、桌在哪，供背景与 CG 参考。常驻空间的动线细节归 anchors.md 空间拓扑，本文件引用其结论、补充氛围与风貌类信息。

### characters/<角色名>.md —— 角色档案
模板：
```markdown
# <角色名>
- 定位：主角 / 可攻略角色 / 核心配角 / 反派
- 身份/地位：
- 年龄基准：<引用 anchors.md 年龄矩阵，不另写口径>
- 外貌与气质：
- 性格：核心欲望 / 恐惧 / 缺陷 / 价值观
- 目标：长期目标与当前阶段目标
- 动机：驱动行为的深层原因（与世界观、经历挂钩）
- 背景与经历：
- 能力与限制：
- 成长弧线：从出场到结局的变化轨迹
- 与主线的关系：如何承载主题、推动或阻碍主线
- 关系：<与谁的关系、态度>
- 说话方式：<口头禅、句式、用词习惯>
- 出场记录：<章节、事件、状态变化>
```

### relationships.md —— 人际关系网
记录角色间的关系定位、冲突点与关系变化方向，作为剧情大纲与路线/分支设计的输入。

### timeline.md —— 时间线
格式：`<年份/纪元> <月日?> <事件> <涉及章节>`，按时间正序排列。凡剧本中给出明确时间的事件必须登记；季节、昼夜、经过天数、年龄是冲突高发区。时间线以 anchors.md 年龄矩阵为纲（起点基准年龄、关键节点年龄必须一致），事件日期序列填实年龄矩阵的"阶段变化"列。

### glossary.md —— 术语表
条目：名称、定义、限制、首次出现的章节。名称一旦确定不得随意更换；必须更换时全局替换并在 continuity-log 记录。角色名的系统层写法（Speaker ID）与称谓口径以 anchors.md 第三节为准，本文件只收录非人名词条。

### style.md —— 剧本文风
写明：基调（冷峻/温情/黑色幽默等）、类型惯例（如悬疑的规则、喜剧的节奏）、篇幅习惯、禁忌（如"避免 X 类桥段"）、可参照的范例段落。写正文前必读此文件。

## 维护规则
1. 设定先行：剧本需要的新设定先写入设定集（哪怕一句话），再进正文；其中常量事实（年龄/空间/称谓/信物）先写入 anchors.md 并经用户确认。
2. 每个角色的目标与动机必须形成戏剧张力；动机空泛的角色先向用户提出补充问题，不硬写。
3. 全角色复核：彼此的动机能否相互对抗或支撑，成长弧线是否与主线咬合。
4. 修改设定必须：① 修改设定集（属锚点内容的先改 anchors.md 并经用户裁决）；② 检查已写正文是否有冲突（用检索工具搜相关词）；③ 在 `03-修订/continuity-log.md` 记录"改了什么、为什么、何时"。
5. 人物新增或下线要在出场记录中体现。
6. 用户在对话中口头确立的设定也要落到设定集，不能只存在于对话里。
7. 写正文前先判定文本类型与文风基调，以 style.md 与 character-voices.md 校准后再正式创作；判定不清时先向用户求证，素材不足时先给候选方案并请用户拍板。
8. 接手 vn-design 项目时，若 `00-设定/characters/<角色名>.md` 已存在，把本模板要求而 vn 模板没有的字段（身份与地位、背景与经历、能力与限制、出场记录、说话方式）补写进同一文件，不新建第二份档案，vn 原有字段一律保留；缺 `00-设定/anchors.md` 时按「只增不改」补建，内容从已确认设定照实汇总。
