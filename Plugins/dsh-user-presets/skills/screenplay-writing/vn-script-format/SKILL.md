# 剧本格式（vn-script-format）

## 何时使用
- 每次撰写或改写剧本正文（02-剧本/）时。

## 动笔前判定
- 每次写正文前，先判定本段的文本类型（对白/叙述/内心独白/画外/演出指令/选项）与文风基调（对照 00-设定/style.md 与 01-规划/character-voices.md），并确定本场景的氛围基调与各出场角色的心情/唤醒度（低/中/高），依据判定选择本 skill 的对应写法。
- 判定所需信息不足时先向用户求证；素材不足以支撑本段内容时，先给候选方案讨论，用户拍板后再正式创作。
- 写新章节或关键场景前，先按本 skill 的「场景起飞检查卡」完成锚点核对，再下笔（见下）。

## 三级视点模式（POV Configuration System）

本项目在 `规范-剧本.md` 中声明**全局默认视点模式**；单场戏可通过场景头显式交接视点。绝不使用"绝对禁止他人内心/绝对单一视角"之类一刀切死规则——视点纪律是**动态模式配置**，事实严密与艺术自由并重。

### 模式 1：单主角强沉浸模式（Strict Single POV）
- 定位：传统男主单重视角、悬疑探秘、纯主观恋爱体验。
- 规则：全剧严格绑定单一主角；他人内心完全不可见；视线死角受人体物理法则约束（背后动静只能靠听觉、触感或他人事后转述感知）。
- 场景头无需逐场标注视点（默认继承全局主视点）。

### 模式 2：场段交替轮换模式（Switching POV）
- 定位：双主角对等叙事、双向暗恋心声交锋、群像多线推进。
- 规则：允许按章节或场景切换主导视点；视点归属于谁，谁即获得第一人称叙述与内心独白特权。
- 每次交接必须在场景头显式声明 `【视点：角色】`。

### 模式 3：电影化群像/上帝剪辑模式（Cinematic / Multi-Angle）
- 定位：多势力智斗、宏观灾难、过场动画（Interlude / Meanwhile）。
- 规则：允许客观镜头描写空镜、全知叙述与幕间发生之事。
- 客观过场用 `【幕间 / 客观视点】` 声明：无第一人称主角，采用摄影机客观镜头白描。

### 动态特权与限制转移（视点一旦交接，立即生效）
1. **特权转移**：声明 `【视点：夏天风】` 后，`夏天风（内心）：……` 立即合法且优先；旁白叙述中的第一人称"我"自动转指夏天风；心理活动、嗅觉、触觉等全部感官以夏天风的身心感受为准。
2. **限制转移**：此时原主视点角色退行为外部观察对象，**严禁书写其内心独白**（如 `庄游火（内心）：……`）；其心情只能通过外在动作（挠头、移开视线、喉结微动）被当前视点角色观察。
3. **多心声禁令（No Simultaneous Mind-reading）**：**绝对禁止在同一个场景段落中同时出现两个角色的无声内心独白**，杜绝"神游视角漂移"。一个场景段落内，内心特权只有一份。

## 场景头视点声明语法
- 基础场景头：`## 场景 N · 地点 — 昼/夜/晨/昏`（如 `## 场景 3 · 老宅客厅 — 夜`）。同地点连续推进不重复写。
- 模式 2 交接视点：`## 场景 2 · 旧书店后廊 — 昼 【视点：夏天风】`（显式交接：本场主导视点移交给夏天风）。
- 模式 3 客观过场：`## 场景 3 · 老街尽头公用电话亭 — 夜 【幕间 / 客观视点】`。
- 未显式声明时，默认继承全局默认主视点（由 规范-剧本.md 声明）。

## 场景起飞检查卡（Pre-flight Stamp）——动笔前强制执行

长篇写作中事实漂移的根源是上下文注意力稀释：在输出大篇幅正文前，先"打印并自检"一组关键实体元数据，注意力会被锚定在基准事实上，后续数千字极难产生幻觉与穿帮。

**每写一个新章节或关键场景前**，在 Plan（规划）阶段或草稿头部显式输出检查卡，逐项对照 `00-设定/anchors.md` 与 `规范-剧本.md` 核对，核对无误后方可正式下笔：

```markdown
<!-- SCENE_PREFLIGHT_START -->
【场景起飞检查卡】
- 场景编号与时段：ch033-xtf / Day 78 晨
- 场段主导视点：庄游火（严格物理听视死角，不可读取他人内心）
- 物理空间与动线：12楼庄家卫生间与走廊（电梯房）
- 登场角色与年龄：庄游火（17岁末/成人前夕）、夏天风（17岁末/成人前夕）
- 核心称谓核对：说话人标签写"夏天风："，男主对白称"夏大掌柜"
- 关键资产状态：夏天风佩戴海玻璃新绳；微卷中长发挽在脑后（非短发）
<!-- SCENE_PREFLIGHT_END -->
```

检查卡字段与 anchors.md 四节一一对应：年龄矩阵→登场角色与年龄，空间拓扑→物理空间与动线，称谓网格→核心称谓核对，核心资产与体态状态机→关键资产状态。核对中发现矛盾先回 anchors.md 与用户裁决，不带病下笔。

## 剧本结构
- 按章分文件（ch001.md、ch002.md …，三位编号保证排序稳定）；分支段落用后缀区分（ch001-2a、ch001-2b），跳转关系在选项处注明。
- 章内按段落推进；每个段落是一次"文本推进"的单位，一般 1-3 个短句。

## 通用版面
- 场景头：每进入一个新场景单独一行（语法见上「场景头视点声明语法」）。
- 旁白与叙述：不加前缀的段落。
- 对白：`角色名：台词`，每行一位角色，对白不加引号；长对白分段写。说话人标签与旁白/对白中的称呼按 anchors.md 称谓网格三层解耦，互不混淆。
- 内心独白：`角色名（内心）：……`，与对白区分开；旁白式独白可用不加前缀的段落并以「（她的心声）」类标注起头。内心独白受视点模式约束（见「动态特权与限制转移」）。
- 画外音/回忆声：`角色名（画外）：……`，与当前场景对白区分。

## 演出指令
演出指令单独成行，用【】标出，只写需求、不写引擎实现（除非用户要求按引擎语法写）：
- 【背景：老宅客厅】
- 【立绘：遥·微笑】
- 【BGM：曲名】
- 【音效：开门声】
- 【特效：画面震动】
- 【转场：淡出→淡入】

若用户已有系统设计（如 02-系统/systems.md）或引擎规范，以其中定义的指令语法为准。

## 选项与分支
```
【选项】
1. 选项文本 → 跳转 ch001-2a
2. 选项文本 → 跳转 ch001-2b
```
- 选项文本默认写成玩家视角；若需要体现主角口吻，先与用户确认口径。
- 有系统设计时，选项处标注变量变化，如 `→ FLAG：遥好感+1，跳转 ch001-2a`。

## FLAG 与变量标注
- 剧情需要的标记在选项或段落末尾标注：`FLAG：xxx=1`。
- 每个 FLAG 在 outline.md 的分支节点预留或系统设计中登记；正文只引用，不新造。

## 文本量基准
- 中文阅读按约 250-300 字/分钟估算；1 万字正文 ≈ 35-45 分钟游戏时长（无语音）。据此与用户对齐章节字数与总篇幅。该换算属**经验估算值，无标准依据**（有语音、动画与演出停顿会显著拉长时长），只作起始估算，实际以试玩或用户目标为准。
- 一次文本推进控制在 1-3 个短句；单人对白超过约 5 行就要考虑拆分或删减。

## Markdown 范围连接符防灾
在 Markdown 渲染引擎（GFM、Obsidian、Web GUI 等）中，连续半角波浪号 `~` 常被误判为下标或贪婪匹配为删除线，导致文字中间出现划去线。剧本正文与全部项目文档中：
- **日期范围**：写 `6月10日 - 6月11日` 或 `6月10日-6月11日`；
- **天数/编号区间**：写 `Day 1 - Day 2`、`Day 1-2`、`ch001 - ch005`；
- **文本禁忌**：严禁在正文排版中密集出现裸半角波浪号 `~`，统一采用半角减号配空格或短横线（`-`）代替。

## 写作要求
- 叙述只写可见可闻、且可被演出表达的内容；不写角色内心活动（内心交给独白或演出表达）。可见可闻的范围受当前场段视点的物理法则约束。
- 动作与状态用具体行为表达：「她攥紧衣角，指节发白」而不是「她很紧张」。
- 演出指令克制：只在画面、声音、情绪确实需要变化时标注；不需要时让文本说话。
- 角色首次出场可加一句年龄/特征，后续不加；年龄特征以 anchors.md 年龄矩阵与体貌锚点为准。
- 氛围与唤醒度：对白、旁白、独白与演出指令（BGM/音效/立绘表情/特效）必须与场景氛围及角色唤醒度一致并随其变化——高唤醒度短促激烈，低唤醒度放缓克制但仍有质感。
- 严禁全场死水般的平静语气：全部角色与段落不得始终同一平静声调；平静只在判定必要时段落级使用，并借行为细节、演出反差或潜台词暗示平静之下的暗流（细则见 writing-craft）。

## 交付
- 正文按章写入 `02-剧本/draft-vN/`。
- 每写完一批段落，更新 scene-list.md 段落/场景表。
- 新场景/新地点同步到设定集（story-bible 的 world.md / geography.md）；其空间物理事实先补录 anchors.md 空间拓扑（经用户确认）再写正文。
