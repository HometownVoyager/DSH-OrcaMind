# 剧情大纲（vn-script-outline）

## 何时使用
- 项目处于剧情大纲阶段，或需要修订、扩展已确认的大纲时。

## 红线（最高优先级）
本阶段只允许抽象层级的描述，严格禁止具体到场景、台词与演出指令的设计：
- 禁止写「某角色在某地点说出某句话」或任何台词级内容；
- 禁止写具体的背景切换、立绘表情、镜头或演出指令；
- 只提供情节节点、冲突升级、情感转折、人物关系变化、章节功能与节奏结构。

错误示例：「雨夜，凛在车站对遥说：『我一直都在找你。』」（场景+台词）
正确示例：「凛与遥在重逢节点确认彼此的目标冲突，推动凛重新评估自身动机。」（情节节点+关系变化）

## outline.md 模板（01-规划/outline.md）
```markdown
# 剧情大纲

## 一句话故事
## 章节结构
每章一句话：章节功能（引入/铺垫/转折/高潮/收束）与节奏定位。
## 主要事件序列
按因果链排列的抽象事件节点，不写场景与台词。
## 冲突升级
外部冲突与内心冲突的升级阶梯：压力如何逐级加大。
## 情感节奏
情感曲线与转折点：读者/玩家的情绪在何处上扬或下坠。
## 人物关系变化
各主要关系的变化节点与方向。
## 结局方向
可能的结局与主题落点。
## 分支节点预留
选项位置、后果差异与指向的抽象标注（FLAG 与变量留给系统设计或正文标注）。
## 开放问题
```

## 执行步骤
1. 先与用户确认结局方向与整体篇幅，再搭章节骨架；现有素材不足以支撑大纲时，先给出 2-3 个候选方向与用户讨论，拍板后再正式撰写，拍板前的推测标注「推测/待拍板」、不混入正式大纲。
2. 填事件序列，逐条检查因果链是否闭合、情感曲线是否有起伏。
3. 复核与设定集、结构设计的咬合，冲突先裁决。

## 注意事项
- 撰写前先判定本阶段文本类型（抽象大纲，非正文）与文风基调（对照 style.md），避免把正文写法带进大纲。
- 触犯红线的段落必须改写为抽象表述后再写入文件。
- 大纲只回答「发生了什么、为什么」，不回答「怎么演」——具体场景、台词与演出指令属于剧本正文阶段。
- 分支剧情只做节点标注，其 FLAG、变量与条件留给系统设计（若项目有）或正文标注。
- 若项目已有一份「视觉小说全栈设计」产出的剧情大纲（01-规划/outline.md），以它为基准、不另写一份：先核对与剧本结构设计的咬合，需要扩展时在该文件上增量修改并记录。
