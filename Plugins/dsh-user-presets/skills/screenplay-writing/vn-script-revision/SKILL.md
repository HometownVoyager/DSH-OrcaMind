# 剧本修改（vn-script-revision）

## 何时使用
- 用户要求"改剧本""改这一章/这段""这稿太散"时。
- 完成一稿后主动给出修改方案时（先方案后执行）。

## 修改轮次（每轮只做一件事）
1. 结构轮：logline 与成稿是否一致、共通线/个人线结构是否成立、选项与结局方向是否有效、转折点是否改变故事方向。
2. 段落轮：逐段问"这段推进情节、揭示人物还是埋设信息？"——都不做的删掉或合并；检查段落衔接、FLAG 变化与时间连续性（调用 continuity，先对 00-设定/anchors.md 做锚点核验）。
3. 对白轮：调用 character-voice 逐行检查；删掉直说与解释性对白；说话人标签与称呼对照 anchors.md 称谓网格三层口径。
4. 格式轮：按 vn-script-format 校对场景头（含视点声明）、演出指令、选项、FLAG 标注；对照 anchors.md 逐章核对年龄、称谓、信物与体态状态、空间拓扑与动线；检查范围连接符是否用了 `~`（统一改为 `-` 或 `- `）。
5. 定稿轮：错别字、标点、排版。

## 分支修订的额外检查
- 改分支节点时，检查下游所有分支段落、FLAG 与结局条件是否仍然一致（对照 outline.md 的分支节点预留与系统设计）。
- 合并或删除分支时，检查 scene-list.md 的跳转关系并同步更新。

## 稿本管理
- 每稿一个目录：draft-v1、draft-v2……新稿从上一稿复制，旧稿保留。
- 修改稿首行注明「第 n 稿 · 日期 · 修改范围」。
- 行业惯例（颜色稿/修订标记）在本模式中简化：用目录区分版本即可，用户需要再引入。

## 修改记录与复盘
每轮结束写入 03-修订/revision-log.md：
```markdown
## <日期> <轮次> · <范围>
- 删/改/新增：<具体条目>
- 理由：<一句话>
- 遗留：<待决问题>
```

每稿定稿后追加一段复盘：这一稿解决了什么、暴露出什么新问题、下一稿的目标与优先级。

## 执行纪律
- 一次只改一个层面（结构问题没解决前不做文字润色）。
- 大改（改路线、改结局、动人物线、删支线）必须先给用户方案并获得确认。
- 每次修改后同步更新 scene-list.md 与设定集，防止"改过的剧本"和"没改的设定"打架。
