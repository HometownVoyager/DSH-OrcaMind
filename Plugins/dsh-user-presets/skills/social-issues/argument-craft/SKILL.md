# 论证方法（argument-craft）

## 何时使用
- A 轨「选题立意」阶段：界定议题、立意与核心判断。
- A 轨「论证框架」阶段：设计论点、论据与反驳预案，落盘 论证框架.md。
- 成文或修改时回头核对论证是否成立、是否与框架一致。

## 选题与立意
- 议题界定：一篇评论只处理一个议题（一事一议）；议题写成一句话的「对象 + 争议点」，能被持相反观点的人理解而不产生歧义。
- 立意 = 核心判断：明确「要说什么」——一个可被反驳的判断句，不是话题描述（「谈谈××」不是立意，「××的做法弊大于利，因为…」才是）。
- 由头与现实针对性：由头是引出判断的新闻事实或公共事件，交代 5W 要素、简短（不超过全文 1/5）；针对性回答「为什么现在写、对谁有影响」。
- 立意不确定或素材单薄时，给出 2-3 个有差异的候选立意（各自含核心判断与支撑事实类型），逐一说明依据、代价与收益，请用户拍板后再进论证框架。

## 论点设计
- 全文只有一个中心论点，由头之后尽快亮出；分论点 2-4 层，每层从不同侧面支撑中心论点，层与层之间有递进或并列的明确关系。
- 论点必须明确可反驳：写得出「反方会说什么」的论点才成立；骑墙平衡腔（「一方面…另一方面」各打五十大板）不是论点，分析文应改走研究报告体。
- 论点句自检：能否一句话说清？换持相反立场的人能否明确反对？把判断换成话题描述后是否就不再成立？（三条都过才算论点。）

## 论据与机制
- 论据类型：事实论据（已核查的事实、数据、案例）、权威论据（政策原文、官方口径、专业判断，注明出处）为主，类比与推演为辅。
- **论证必须含机制**（定稿纪律）：每一层不止于表态——写清议题如何发生、通过什么链条影响谁；机制链条至少完成「起因 → 环节 → 影响对象 → 结果」的完整描述。
- 把议题放进关联背景（历史脉络、相关政策、利益相关方网络）中考量，呈现事物之间的联系，避免孤立就事论事。
- 每层论证须能回答三问：「依据是什么、机制是什么、对谁有何影响」；空泛的立场句不算论据。
- 事实与观点分轨：事实部分可溯源（注明时间、地点、信源），判断部分明确标注为作者判断；未经核实的传闻不得作为论据，信源存疑的在 考据/ 留核查记录并标注。
- 落点具体：判断落到具体影响（对谁、何时、何种程度），可核验；「高度重视」「形成合力」类空话不得单独充当论据。

## 反驳预案
- 预置对相反观点的回应：列出 1-3 个最可能、最有力的反驳（不是稻草人——写反方最强版本），逐一给出回应路径（事实纠偏、机制解释、边界限定、让步后重构）。
- 回应不了的强反驳如实标注「待补强」，不能假装已回应；必要时把它升级为论点的限定条件（「在……前提下」）。
- 让步技巧：承认对方论据中成立的部分，再说明为什么整体判断不变；让步要有边界，不让步到论点被掏空。

## 论证框架.md 结构
```markdown
# 论证框架：<议题一句话>
- 中心论点：<一句话核心判断>
- 由头：<新闻事实 5W 概述与信源>
- 分论点一：<判断句>
  - 论据：<已核查事实/数据/政策原文 + 信源>
  - 机制：<起因 → 环节 → 影响对象 → 结果>
- 分论点二：…
- 反驳预案：
  - 反方观点一：<最强版本> → 回应：<路径>
- 待核实事实：<清单，标注信源状态>
```

## 注意事项
- 论证框架未经用户确认不得成文；框架与成稿逐层对应，成文时发现框架站不住先回来改框架并说明。
- 论据引用的事实必须与 考据/ 记录一致，框架里列「待核实」的事实成文前必须核实或删除。
- 分层之间禁止重复用同一事实反复支撑不同分论点——信息重复说明分层有问题，重新设计层次。
