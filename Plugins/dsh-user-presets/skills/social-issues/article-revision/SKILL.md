# 修改定稿（article-revision）

## 何时使用
- A 轨「修改定稿」阶段：评论文章按轮次修改至定稿。
- B 轨方法论报告的修改轮次。
- 用户对成稿提出修改意见后的每一轮。

## 逐轮修改流程
1. **接收修改意见**：把用户意见拆成逐条清单（编号），区分事实性问题（必须改）、结构性问题（建议改并说明理由）、风格性问题（按规范裁量）；有异议的条目先讨论再动手，不擅自推翻用户意见。
2. **事实复核**：修改涉及的事实一律回到 考据/ 记录复核；新增事实先补考据（双源交叉验证）再入稿；标注「待核实」的事实若仍未核实，改稿时一并处理（核实、删除或保留标注并请用户裁决）。
3. **一致性核对**：成稿与 论证框架.md（A 轨）或 问题定义/根因分析/方案对比（B 轨报告）逐层对应——改了稿偏离框架的，先说明是否需要回改框架，经确认后同步更新框架文件。
4. **规范符合性逐项校对**：对照 `规范-议题.md` 的③产出格式与④红线逐项过——
   - 结构：标题/由头/论点/论证/收束（评论体）或各节齐全与编号（报告体）；
   - 格式：篇幅、信源标注位置与格式、编号体系；
   - 红线：人身攻击、推测当事实、骑墙、空话（「高度重视」类）、无出处数据、「一方面…另一方面」平衡腔逐条排查。
5. **修订记录**：每轮修改写入 修订记录.md（格式见下），README 进度同步更新。

## 修订记录.md 格式
```markdown
# 修订记录：<文章/报告名>
## 第 <n> 轮（YYYY-MM-DD）
- 修改依据：<用户意见编号 / 自查项>
- 修改内容：<逐条：位置 + 改动 + 理由>
- 事实复核：<新增/复核的事实与信源，对应考据记录编号>
- 规范校对：<红线排查结果，逐项 已过/已改/不适用>
- 遗留问题：<待确认事项>
```

## 定稿判定
- 修订记录中无未处理的事实问题、无待确认事项遗留，规范校对全部通过，且用户确认 → 定稿归入 成稿/（版本命名 `<主题>-v<n>.md`）。
- 定稿文件头注明：定稿日期、所用规范集、字数、信源清单指向（考据/ 目录）。

## 注意事项
- 历史版本只增不改：修改产出新版本文件，不覆盖旧版；版本号递增，重大改版（结构变化）另起版本号段。
- 每轮修改幅度与理由留痕，便于用户回看任意版本的差异。
- 改稿时发现信源被撤稿/更正的，立即回到考据记录处理并评估对全文论证的影响，主动向用户报告。
- 定稿后规范或事实更新导致结论变化的，标注「需修订」并请用户决定是否启动新一轮，不擅自重写定稿。
