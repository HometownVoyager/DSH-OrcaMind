# 资产制造·规格锁定（asset-make-spec-read）

## 何时使用
VN-资产制造（vn-asset-make）阶段每轮 Read 步：在已由用户从候选清单选定的「唯一一个子条目」上，只读确认该条资产条目所对应的规格、数量、优先级、分类子目录、文件名、格式与生成提示词，供后续 `asset-make-generate` 原样执行。

## 唯一落点 / 写死路径
- 本 skill **只读锁定规格，不写任何文件**，自身不产出文件、不追加任何行、不创建任何目录或文档。
- 唯一允许产出落点写死为 `<作品名>/03-Asset/generated/`；其中的二进制资产文件由后续 `asset-make-generate` 产出，本 skill 只负责把规格读准并报告，**绝不落盘**。
- 只读锁定来源（写死路径，只读）：
  - `<作品名>/03-Asset/asset-list.md`
  - `<作品名>/03-Asset/notes/bg.md`、`sprite.md`、`cg.md`、`bgm.md`、`sfx.md`、`ui.md`、`script.md`
  - `<作品名>/README.md`（状态机，只读校验「当前预设」为 vn-asset-make）
  - `<作品名>/Specifications.md`、`<作品名>/Direction.md`（首轮显式读，只读）
- `<作品名>/03-Asset/generated/` 是唯一二进制资产落点；`03-Asset/generated/` 下七类分类子目录写死为 `bg/`、`sprite/`、`cg/`、`bgm/`、`sfx/`、`ui/`、`script/`。

## 单轮单条目
- 每轮只处理 1 个子条目（1 个资产文件）：只读锁定 `asset-list.md` 与对应 `notes/*.md` 中那 1 条已确认条目，具体到 1 个文件名及其规格单条目。
- 不把「一类资产」「一份清单」「多张图」「补齐缺口」当作一个子条目；不在本轮内规划或预写后续子条目；子条目由用户从候选清单中选定，不自主规划本阶段子任务。
- 发现规格单内部矛盾、字段缺失或提示词不确定时，应停下用 `ask_user_question` 询问，不自行调和、不自行补全、不凭空假设。

## 执行要点
1. **每轮只处理 1 个子条目**：见上节，不一次性锁定多份规格或多轮条目。
2. **不跨阶段**：不读写下游阶段目录，不创建下游文件，不在对话中替下游做设计；不做上游阶段的事（不写资产清单、规格单、生成提示词），不做下游阶段的事（不写逐场演出剧本、不写游戏实现规格）。

其余同等强制的硬约束：
- 不写任何文件（含 README.md、asset-index.md、asset-gap.md、任何清单/规范/记录/索引类文档）。
- 不修改规格与提示词：按已确认内容原样读出、原样报告，不自行修改规格、不自行增补提示词。
- 不「顺手把缺口也补了」：发现缺口只报告、只询问，不补写、不顺带推进。
- 不伪造资产路径、资产 ID、差分名；不用占位内容冒充成品。
- 唯一产出落点是 `<作品名>/03-Asset/generated/`（`asset-make-status-sync` 对 `asset-index.md` / `asset-gap.md` 实际状态字段的协作补写是唯一例外，且只补实际状态字段）；本 skill 不写该落点、也不写该例外。

## 越界收敛原则
默认优先把改动限制在 `03-Asset/` 本列内；确有必要越出本列时只允许「读上游已确认内容」与「按 vn-gate 在 README.md 追加一行进度」，不借「有必要」扩张写权。本 skill 连 README.md 的追加也不做（那是 `asset-make-verify` 的职责），越界时只读、不写。违反任意一条应立即停下并询问用户。
