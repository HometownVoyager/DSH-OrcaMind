# 资产制造·实际状态补写（asset-make-status-sync）

## 何时使用
VN-资产制造（vn-asset-make）阶段 Write 步：在本轮已由 `asset-make-generate` 产出**实际文件**之后，把 `<作品名>/03-Asset/asset-index.md` 与 `<作品名>/03-Asset/asset-gap.md` 的**磁盘实际状态**补写到 VN-资产列表（vn-asset-list）建的计划态骨架上（协作职责之二）。这是「唯一产出落点写死为 `<作品名>/03-Asset/generated/`」的**唯一例外**，且只补实际状态字段。

## 唯一落点 / 写死路径
- 四个 skill 默认写死：资产文件唯一允许产出落点为 `<作品名>/03-Asset/generated/`（含 `bg/`、`sprite/`、`cg/`、`bgm/`、`sfx/`、`ui/`、`script/` 七类分类子目录），`<作品名>/03-Asset/generated/` 是唯一二进制资产落点。
- 本 skill 的协作补写是唯一例外，写死且仅写这两份：
  - `<作品名>/03-Asset/asset-index.md`
  - `<作品名>/03-Asset/asset-gap.md`
- 只写这两份的**实际状态字段**；不改写骨架结构、不另建副本、不删除、不新建同义文件、不改写条目顺序与字段定义。
- 这两份是 VN-演出剧本（vn-screenplay）逐场稿默认硬门前置（用户显式指令可覆盖），**本预设不代替用户确认**：状态值默认来自磁盘实际与用户明确确认，不自行拍板、不代替下游确认。
- 不在 `<作品名>/03-Asset/asset-index.md` 与 `asset-gap.md` 之外的任何位置写文件；不写 README.md（由 `asset-make-verify` 承担）、不写 `asset-list.md` 与 `notes/`。

## 单轮单条目
- 逐轮只更新本轮那 1 个资产对应的 1 条、单轮单条目：在 `asset-index.md` 与 `asset-gap.md` 中各只动本轮那 1 条的实际状态字段，不碰其它条目。
- 不把「一类资产」「一份清单」「多张图」「补齐缺口」当作一个子条目；不一次性补齐多条、不顺手更新其它轮次条目；子条目由用户从候选清单中选定，不自主规划本阶段子任务。
- 按磁盘实际：用文件工具核对 `<作品名>/03-Asset/generated/` 对应分类子目录下该文件是否真实存在，再据实补写。

## 执行要点
1. **每轮只处理 1 个子条目**：见上节，逐轮只更新本轮那 1 个资产对应的 1 条。
2. **不跨阶段**：不读写下游阶段目录，不创建下游文件，不在对话中替下游做设计；不做上游阶段的事（不写资产清单、规格单、生成提示词），不做下游阶段的事（不写逐场演出剧本、不写游戏实现规格、不搭建工程骨架）。

其余同等强制的硬约束：
- 只写 `<作品名>/03-Asset/asset-index.md` 与 `<作品名>/03-Asset/asset-gap.md` 的**实际状态字段**，不改写骨架结构、不另建副本、不删除。
- 状态词表**只用**这 8 个词：`available` / `generated` / `substitute` / `placeholder` / `missing` / `hard_missing` / `pending` / `listed_but_missing`；**不自造词汇**、不同义词、缩写或新状态词。
- 实际文件不存在时按实际状态标注（如 `missing` / `pending` / `listed_but_missing`），**不伪造**：不把不存在的资产写成 `available` / `generated`，不伪造资产路径、ID、差分名，不用占位内容冒充成品。
- 这两份是 VN-演出剧本逐场稿默认硬门前置（用户显式指令可覆盖），本预设不代替用户确认；不创建任何清单/规范/记录/索引类文档与计划外文件。
- 唯一产出落点是 `<作品名>/03-Asset/generated/`（本 skill 对 `asset-index.md` / `asset-gap.md` 实际状态字段的协作补写是唯一例外，且只补实际状态字段）。

## 越界收敛原则
默认优先把改动限制在 `03-Asset/` 本列内；确有必要越出本列时只允许「读上游已确认内容」与「按 vn-gate 在 README.md 追加一行进度」，不借「有必要」扩张写权。本 skill 的写权严格限于两份文件的实际状态字段；出现「顺手把缺口也补了」「顺手改一下骨架」「顺手替下游确认」等越界冲动默认收敛、停下询问。违反任意一条应立即停下并询问用户。
