# 资产制造·核对与 README 登记（asset-make-verify）

## 何时使用
VN-资产制造（vn-asset-make）阶段 Check / Write 步：在 `asset-make-generate` 产出本轮唯一 1 个资产文件之后，核对文件名与落点、登记 README.md 进度。本 skill 是四个 skill 中**唯一**写 `<作品名>/README.md` 的一个。

## 唯一落点 / 写死路径
- **唯一允许产出落点写死为 `<作品名>/03-Asset/generated/`**；`<作品名>/03-Asset/generated/` 是唯一二进制资产落点，七类分类子目录写死为 `bg/`、`sprite/`、`cg/`、`bgm/`、`sfx/`、`ui/`、`script/`。资产文件由 `asset-make-generate` 落盘，本 skill 只核对、不产出二进制资产。
- 本 skill 唯一允许写入的是 `<作品名>/README.md`（A 区 5 字段就地更新 + B 区只追加一行进度，状态置「待确认」），以及核对用的只读 `<作品名>/03-Asset/generated/`。
- 不写 `<作品名>/03-Asset/asset-list.md` 与 `<作品名>/03-Asset/notes/`；不写 `<作品名>/00-Bible/`、`<作品名>/01-Plan/`、`<作品名>/02-Script/` 与下游 `<作品名>/04-ScreenPlay/`、`<作品名>/05-Game/`。
- `asset-index.md` / `asset-gap.md` 的实际状态补写由 `asset-make-status-sync` 承担，**本 skill 不重复写入**、不改写其骨架结构、不另建副本。
- 不创建任何清单、规范、记录、索引类文档与计划外文件/目录；`asset-make-status-sync` 对 `asset-index.md` / `asset-gap.md` 实际状态字段的协作补写是「唯一产出落点写死为 `<作品名>/03-Asset/generated/`」的唯一例外，且只补实际状态字段。

## 单轮单条目
- 每轮只处理 1 个子条目（1 个资产文件）：只核对那 1 个已产出文件、只追加 1 行 README 进度、只做一次 Check。
- 不把「一类资产」「一份清单」「多张图」「补齐缺口」当作一个子条目；不一次性交付多份文件；不在本轮内规划或预写后续子条目；子条目由用户从候选清单中选定，不自主规划本阶段子任务。
- 核对项：产出文件名与规格单一致、落点在 `<作品名>/03-Asset/generated/` 对应分类子目录、无计划外文件。不一致应停下询问，不自行改名、不自行补写、不自行调和。

## 执行要点
1. **每轮只处理 1 个子条目**：见上节，一轮只核对 1 个资产文件、只追加 1 行进度。
2. **不跨阶段**：不读写下游阶段目录，不创建下游文件，不在对话中替下游做设计；不做上游阶段的事（不写资产清单、规格单、生成提示词），不做下游阶段的事（不写逐场演出剧本、不写游戏实现规格、不搭建工程骨架）。

其余同等强制的硬约束：
- README.md 按双区结构处理：A 区「当前状态」5 字段就地更新、B 区「进度记录」只追加一行且**不改写既有行**；AI 不自行把状态置为「已确认」（Write 完成后状态置「待确认」）。
- 不写 `<作品名>/03-Asset/asset-list.md` 与 `<作品名>/03-Asset/notes/`；不写 `<作品名>/00-Bible/`、`01-Plan/`、`02-Script/` 与下游 `<作品名>/04-ScreenPlay/`、`05-Game/`。
- `asset-index.md` / `asset-gap.md` 的实际状态补写由 `asset-make-status-sync` 承担，本 skill 不重复写入。
- 不创建任何清单/规范/记录/索引类文档与计划外文件；不伪造资产路径、资产 ID、差分名；不用占位内容冒充成品。
- 唯一产出落点是 `<作品名>/03-Asset/generated/`（协作补写实际状态字段是唯一例外）。

## 越界收敛原则
默认优先把改动限制在 `03-Asset/` 本列内；确有必要越出本列时只允许「读上游已确认内容」与「按 vn-gate 在 README.md 追加一行进度」，不借「有必要」扩张写权。本 skill 的写权仅止于 README.md 双区规则的那一处；发现越界（例如想顺手补 `asset-index.md`、想改写上游规格单）默认收敛、停下询问。违反任意一条应立即停下并询问用户。

## 白名单与目录纪律
`<作品名>/` 下只允许存在 **6 个编号目录 + 3 个根级文档**（白名单默认 6+3）：
- 6 个编号目录：`<作品名>/00-Bible/`、`<作品名>/01-Plan/`、`<作品名>/02-Script/`、`<作品名>/03-Asset/`、`<作品名>/04-ScreenPlay/`、`<作品名>/05-Game/`。
- 3 个根级文档：`<作品名>/README.md`、`<作品名>/Specifications.md`、`<作品名>/Direction.md`。
- 除此之外任何目录、任何文件不创建；`<作品名>/03-Asset/generated/` 是唯一二进制资产落点。

## Check 按 vn-continuity
Check 按 `vn-continuity` 执行：核对产出文件名与规格单一致、落点在 `<作品名>/03-Asset/generated/` 对应分类子目录、无计划外文件、无旧路径落点、无伪造资产；不一致应停下询问，不自行改名、不补写。Check 结论写入对话报告，不新建核查文档。

## README.md 双区结构
`<作品名>/README.md` 是唯一进度载体，双区结构（见 `vn-gate` §4）：
- A 区「当前状态」块 5 字段（当前预设 / 当前阶段 / 本轮子条目 / 状态(进行中|待确认|已确认) / 下一候选）**仅在用户确认后就地更新**；本轮 Write 完成后 `状态` 置 `待确认`。
- B 区「进度记录」区**只追加一行**（状态「待确认」）、永不改写或删除既有行。
- AI 不自行把状态置为「已确认」；阶段切换应等于用户手动切换到对应预设且 README.md 状态为「已确认」。

## 旧路径禁令（仅允许出现在「旧值/迁移/不/上游只读」语境）
下列旧路径默认**不作为产出落点**，只允许在本节「旧值/迁移/不」语境中出现：`00-设定/`、`01-规划/`、`02-系统/`、`02-剧本/`、`03-修订/`、`04-资产/`、`05-剧本/`、`06-演出/`、`assets/`、`规范-*.md`（含 `规范-视觉小说设计.md`、`规范-剧本.md`、`规范-演出.md`）、根级 `剧情精述.md`、以及 `logline.md`、`treatment.md`、`structure.md`、`character-voices.md`、`revision-log.md`、`inspirations.md`、独立 `endings.md`。它们只是迁移对照中的旧值，不把 `<作品名>/03-Asset/generated/` 之外的路径当作产出落点；统一六目录与合并后的文件名以 `<作品名>/03-Asset/` 新路径为准。
