# 基准事实层（vn-bible-anchors）

- 不调用其它阶段 skill，不看到下一阶段模板与字段定义。
- 白名单恒为「6 个编号目录 + 3 个根级文档」：`00-Bible/`、`01-Plan/`、`02-Script/`、`03-Asset/`、`04-ScreenPlay/`、`05-Game/` 与根级 `README.md`、`Specifications.md`、`Direction.md`；本 skill 的唯一落点只属于 `00-Bible/`。

## 唯一落点 / 写死路径
- `<作品名>/00-Bible/anchors.md` 是唯一落点、四节结构，是本项目不可漂移的客观物理与生理基准事实源，也是 `vn-continuity` 连续性核查的第一基准、正式事实源。**四节以本文件 §「唯一落点 / 写死路径」为唯一定义，与 `vn-continuity` §1 一致**；四份固定名 `.docx` 的分组是收录文档归类，不是 `anchors.md` 四节。
- 四节固定为：一、年龄与生理时间轴矩阵（年龄矩阵）；二、空间拓扑与动线模型（建筑属性、户型、动线连接、声光穿透法则）；三、称谓三层解耦网格（称谓网格：系统 Speaker ID、主观叙述层、对白呼告层）；四、核心资产与体态状态机（体貌锚点、信物流转状态机）。
- 三张表「年龄矩阵」「称谓网格」「信物流转状态机」应写全行列、单元格文字与状态迁移条件，不压缩丢失、不只留表头。
- 不写 `00-Bible/brainstorm.md`、`00-Bible/characters/`、`00-Bible/relationships.md`、`00-Bible/world.md`、`00-Bible/factions.md`、`00-Bible/geography.md`、`00-Bible/timeline.md`、`00-Bible/glossary.md`、`00-Bible/style.md`、`00-Bible/00-Bible-四份版/` 以及任何其它文件；不创建计划外文档。
- 不预写 `01-Plan/`（含其大纲、章节结构表、结局与分支条件等全部下游文件），不写入 `02-Script/`、`03-Asset/`、`04-ScreenPlay/`、`05-Game/` 等任何下游目录与文件，不越权写入、不替下游做设计。
- 首轮显式读一次 `Specifications.md` 与 `Direction.md`（后续轮不复读），读根级 `README.md` 校验「当前预设」，只读 `00-Bible/` 内本阶段已有产物。

## 单轮单条目
- 每轮只处理 1 个子条目：四节中的 1 节（或该节内的 1 个已确认常量条目）；本轮子条目由用户从候选清单中选定，AI 不自主规划阶段内子任务、不用一份整稿替代逐步确认。
- 只写已确认事实，不把 `00-Bible/brainstorm.md`（创意意图记录）当作基准参照，不把候选方向或未确认内容写成既定事实；正式事实源默认为 `00-Bible/anchors.md` 与各设定文档。
- 一切设定事实应由用户确认后方可落盘；用户未明示的内容只列开放问题条目标题、不展开，存在疑问、缺项或冲突用 ask_user_question 求证，由用户拍板，不自行裁决、不凭空假设。
- 以完整、连贯且包含因果关系的复合句为主，不碎片段落；不场景、台词、镜头、走位与演出指示；不「稳稳接住」「接住你」及其比喻义表述；不裸 `~`，连接符用 `-`，编号三位（`ch001` / `sc001`）。
- Read → Report → Confirm → Do → Check → Write → Stop 七步为默认顺序；用户显式指令可调整；Write 在 Confirm 之后、Stop 之前，只写这一个文件 + 就地更新 `README.md` A 区「当前状态」5 字段 + 在 B 区「进度记录」追加一行（状态置「待确认」）。
- Check：按 `vn-continuity` 核查这一个产物（锚点矩阵优先），按 `vn-spec` 校验统一目录与格式，按 `vn-gate` 校验单轮单条目；冲突停下请用户裁决。

## 执行要点

每轮只做 1 个子条目（用户可显式授权一次做多个；流程见 `vn-gate`）

不跨阶段写入（边界见 `vn-spec` 读写权限矩阵与 persona【指令裁决】）

- 不创建计划外文档、不跨阶段预写、不越权写入；违反任一红线应立即停下并用 ask_user_question 询问。
