# 资产列表（vn-asset-list）

## 何时使用
- 项目处于资产列表阶段（阶段6），或需要按新设定补充、修订资产清单时。

## asset-list.md 模板（04-资产/asset-list.md）
```markdown
# 资产清单

## 总表
| 编号 | 分类 | 名称 | 规格/说明 | 数量 | 优先级 | 依赖 |
|------|------|------|-----------|------|--------|------|
```

## 分类明细（04-资产/notes/）
- bg.md：背景——地点清单（来自世界观地理与剧情大纲）、构图要点、规格（分辨率）。
- sprite.md：立绘——角色、表情差分/服装差分、规格（半身/全身、分层方式）。
- cg.md：CG——事件 CG 清单、构图要点、规格。
- bgm.md：音乐——曲目清单、情绪与场合、时长与循环点。
- sfx.md：音效——列表、触发情境。
- ui.md：UI——主菜单、对话框、选项、存档读档、好感度展示等界面元素与交互说明。
- script.md：脚本文件——章节脚本文件划分、命名规则、文本量估算（字数/时长换算）。

## 优先级约定
- P0：主线必需资产（无则无法制作）。
- P1：重要分支与常用差分（影响体验完整度）。
- P2：补充差分与点缀（有余量再制作）。

## 执行步骤
1. 依次盘点前五个阶段的全部产出，把每个需求映射到资产条目。
2. 按分类开列清单，逐项写明规格、数量与优先级。
3. **同步基准事实层**：核心资产（信物/道具）与角色的体态、服饰差分，与 `00-设定/anchors.md` 第四节「核心资产与体态状态机」保持同一口径（持有者、佩戴/持有阶段、去向一致），它是剧本与演出阶段的第一基准。
4. 与用户确认范围与预算取舍，超预算时列取舍方案请用户裁决。

## 注意事项
- 规格写到可直接交付制作/外包的程度（分辨率、数量、交付格式）。
- 每项资产注明它服务于哪个剧情或系统需求，保证可追溯。
- 核心资产与体态状态以 anchors.md 为单一事实源：清单与锚点不一致时，先回锚点核验并请用户裁决，不在清单里自创设定或擅自改写锚点。
- 资产清单是对前五阶段的一致性的最终检验：发现需求缺口时回指对应阶段文档，而不是在清单里自创设定。
