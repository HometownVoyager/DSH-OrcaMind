# 设定连续性管理（vn-continuity）

## 何时使用
- 每轮对话开始检阅项目时（快速核查本阶段涉及文档与既有确认的咬合）。
- 每阶段产出落盘前（全量核查一次）。
- 修改已确认设定后（检查对下游文档的影响面）。
- 用户指出"前后矛盾""设定冲突"时（定位并请用户裁决）。

## 核查顺序（锚点矩阵优先）
先对 `00-设定/anchors.md` 做**定向靶向核查**，再按需展开全文检索：年龄与关键节点、称谓三层口径（Speaker ID/旁白称谓/对白呼告）、信物与体态状态、空间拓扑与动线逐项比对，然后核对 timeline.md、glossary.md 与各阶段文档；全文模糊检索只作兜底。

## 检查清单
0. **锚点 ↔ 各阶段**：本阶段产出涉及的角色年龄与关键节点、称谓口径、信物与体态、空间拓扑与动线是否符合 anchors.md；剧本模式接手后，`05-剧本/` 与 `剧情精述.md` 同样先过锚点核验（剧本侧缺 anchors.md 时提示其按「只增不改」补建）。
1. 人物 ↔ 世界观：角色目标与动机是否符合世界观规则（含超自然或特殊规则的代价与边界）与社会结构。
2. 人物 ↔ 人物：各角色动机能否相互对抗或支撑，与 relationships.md 的关系网一致。
3. 大纲 ↔ 设定：事件序列是否符合世界观规则与角色动机；大纲是否只含抽象层级内容（无场景/台词）。
4. 大纲 ↔ 人物弧线：关系变化节点与各角色成长弧线咬合。
5. 系统 ↔ 大纲：每个分支点在大纲中是否已预留，结局条件与已确认的结局方向一致，条件无互斥歧义。
6. 资产 ↔ 前五阶段：每项资产条目都能追溯到一个剧情或系统需求，清单不自行引入新设定。
7. 剧本 ↔ 设定/系统/资产：项目由剧本模式接手后，`05-剧本/` 与 `剧情精述.md` 的内容须与已确认的设定、系统设计与资产清单一致，冲突先请用户裁决。
8. 时间线与名词：新事件与专有名词以 timeline.md 与 glossary.md 为基准登记。

## 方法
- 每次核查先读 `00-设定/anchors.md`（基准事实层），再读其他基准文档；锚点核验通过后用检索工具做针对性抽查与兜底。
- 用检索工具全局搜索关键名/术语（人名、地名、组织、道具、规则名），对比出现处的上下文。
- 以已确认文档（README 的确认记录 + 各阶段文档）为基准；草稿中的新事实须经用户确认后，才反向补录进基准（属锚点内容的先改 anchors.md 并经用户裁决）。
- 跨阶段长线内容（伏笔、事件链、规则后果）在 continuity-log.md 中单独列"追踪事项"小节登记。

## 冲突处理
1. 发现新产出与已确认内容冲突时，先指出冲突并说明两种口径各自的来源，请用户裁决，不得自行选择其一后直接改写正式设定。
2. 裁决完成后必须记录：日期、冲突内容、裁决结果、修改了哪些文件。
3. 修改影响面大于单文件时（如改名、改核心规则），先全局检索全部出现位置，列出改动清单，经用户确认后逐处执行，最后全局复查一遍。

## continuity-log.md 格式（03-修订/continuity-log.md）
```markdown
# 设定连续性记录
## <日期>
- 查证：<冲突内容与双方口径来源>
- 裁决：<以谁为准、用户如何裁决>
- 修改：<改动的文件清单>

## 追踪事项
- <伏笔/事件链/规则后果，标注所在文档>
```
