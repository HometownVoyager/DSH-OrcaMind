# 剧情大纲（vn-story-outline）

## 何时使用
- 项目处于剧情大纲阶段（阶段4），或需要修订、扩展已确认的大纲时。

## 红线（最高优先级）
本阶段只允许抽象层级的描述，严格禁止具体到场景和发言的设计：
- 禁止写「某角色在某地点说出某句话」或任何台词级内容；
- 禁止写具体的镜头、舞台走位、演出指示；
- 只提供情节节点、冲突升级、情感转折、人物关系变化、章节功能与节奏结构。

错误示例：「雨夜，凛在车站对遥说：『我一直都在找你。』」（场景+台词）
正确示例：「凛与遥在重逢节点确认彼此的目标冲突，推动凛重新评估自身动机。」（情节节点+关系变化）

## outline.md 模板（01-规划/outline.md）
```markdown
# 剧情大纲

## 一句话故事
## 章节结构
每章一句话：章节功能（引入/铺垫/转折/高潮/收束）与节奏定位。
## 主要事件序列
按因果链排列的抽象事件节点，不写场景与台词。
## 冲突升级
外部冲突与内心冲突的升级阶梯：压力如何逐级加大。
## 情感节奏
情感曲线与转折点：读者/玩家的情绪在何处上扬或下坠。
## 人物关系变化
各主要关系的变化节点与方向。
## 结局方向
可能的结局与主题落点。
## 开放问题
```

## chapter-structure.md
章节表：章节号 / 章节功能 / 关键事件 / 情感节奏 / 分支点预留（留给系统设计阶段）。

## 执行步骤
1. **先锁锚点**：确认 `00-设定/anchors.md` 四节（年龄与生理时间轴矩阵/空间拓扑与动线模型/称谓三层解耦网格/核心资产与体态状态机）已填实并经用户确认（基准事实先行）；有缺项先回设定阶段补齐，不得带缺动笔大纲。
2. 先与用户确认结局方向与整体篇幅，再搭章节骨架。
3. 填事件序列，逐条检查因果链是否闭合、情感曲线是否有起伏。
4. 复核与人物设定、世界观设定的咬合，冲突先裁决。

## 注意事项
- 触犯红线的段落必须改写为抽象表述后再写入文件。
- 大纲只回答「发生了什么、为什么」，不回答「怎么演」——具体场景与台词不属于本代理的六个阶段。
- 分支剧情只做节点标注，其变量与条件留给系统设计阶段细化。
- 大纲里的时间跨度、年龄与关键节点必须与 anchors.md 一致；需要新事实时先在 anchors.md 补录并请用户确认，再写进大纲。
