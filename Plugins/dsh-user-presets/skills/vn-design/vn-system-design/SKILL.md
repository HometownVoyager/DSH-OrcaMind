# 系统设计（vn-system-design）

## 何时使用
- 项目处于系统设计阶段（阶段5），或需要修订、细化已确认的系统设计时。

## systems.md 模板（02-系统/systems.md）
```markdown
# 系统设计

## 交互系统
基本操作与信息呈现：对话、选项、存档读档、系统界面与快捷键。

## 选择与分支结构
分支点清单（编号、触发位置、选项、后果变量），分支的汇合与分歧。

## 路线设计
共通线 / 个人线 / 真结局线的划分、进入条件与相互锁关系。

## 好感度系统
数值来源（选项/事件）、是否对玩家可见、影响范围。

## 多结局条件
每个结局的达成条件、判定时机与优先级。

## 章节推进规则
章节解锁条件、锁章节、回溯与跳转机制。

## 系统层叙事逻辑
系统机制如何表达主题（如隐藏好感度、限时选项、二周目解锁）。
```

## endings.md（02-系统/endings.md）
结局表：结局编号 / 名称 / 达成条件 / 判定时机 / 优先级 / 对应剧情落点。

## 执行步骤
1. 以已确认的剧情大纲为输入，先列全部分支点，再设计变量与路线。
2. 每个结局写出可判定的达成条件，检查是否存在条件互斥或同时满足的冲突。
3. 与大纲逐点核对：每个分支点在剧情上是否已预留、是否破坏情感节奏。

## 注意事项
- 系统必须服务叙事，不为了复杂度而堆系统；每个机制都要能说清它提供的体验。
- 系统设计不得引入与 `00-设定/anchors.md` 冲突的新事实（角色年龄与关键节点、空间与动线、称谓口径、核心资产与体态状态）；变量、路线与结局条件涉及这些基准时先回锚点核验，冲突请用户裁决。
- 系统实现范围（引擎、平台、制作成本）先与用户确认，再决定机制取舍。
- 两个结局条件同时满足时必须给出优先级规则，不留歧义。
