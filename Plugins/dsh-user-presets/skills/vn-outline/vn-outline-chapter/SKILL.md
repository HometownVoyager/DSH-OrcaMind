# vn-outline-chapter · 单章大纲

> 本 skill 仅服务 VN 工作流第 2 阶段（order 31）「VN-剧情大纲设计 / vn-outline」，合并改造自 `vn-design/vn-story-outline`，默认使用中文。

## 1. 唯一落点 / 写死路径

- **唯一产出落点（写死）**：`<作品名>/01-Plan/outline.md`。本 skill 只向该文件写入「1 章大纲」，不写任何其它文件。
- 统一白名单默认为 **6 个编号目录 + 3 个根级文档**：`00-Bible/`、`01-Plan/`、`02-Script/`、`03-Asset/`、`04-ScreenPlay/`、`05-Game/` 六个编号目录，以及根级 `README.md`、`Specifications.md`、`Direction.md` 三份文档；除此之外任何目录或文件不创建。
- 本阶段写权只在 `01-Plan/` 那一列；`01-Plan/` 内本阶段既定文件只有 `outline.md`、`chapter-structure.md`、`endings-and-flags.md` 三份，本 skill 只负责 `outline.md`。
- `<作品名>/README.md` 不属大纲产出落点，只按双区结构更新状态并追加进度行（见 §4）。

## 2. 单轮单条目

- 一个子条目 = 一轮内只处理、只落盘、只核查的单一最小可确认单元；在 `vn-outline` 等于「1 章大纲」「1 条章节结构推进条目」「1 条结局条件」「1 条分支条件」「1 条好感度阈值/变量规则」「1 个 FLAG（含触发与回收条件）」「1 条多结局判定规则」「1 条章节推进规则」「1 段关系变化」中的**恰好一项**。
- 本 skill 每轮只处理 `01-Plan/outline.md` 中**恰好 1 章大纲**（或其中恰好 1 段关系变化）；不把整份大纲当作一个子条目，不在本轮内规划或预写后续子条目。
- 本轮子条目应由用户从候选清单中选定；AI 不自主规划阶段内子任务，不用一份整稿替代逐步确认。
- 默认强制：**每轮只处理 1 个子条目**。

## 3. 硬约束

- **每轮只处理 1 个子条目**：每轮 1 章大纲，不把两章或整份大纲合并为同一轮子条目。
- **不跨阶段**：不读取、创建或预写 `02-Script/`、`03-Asset/`、`04-ScreenPlay/`、`05-Game/` 等任何下游目录与文件，不写入 `02-Script/`、`03-Asset/`、`04-ScreenPlay/`、`05-Game/` 等下游，不在对话中替下游阶段做设计；不改写 `00-Bible/` 上游任何文件。
- **大纲抽象层级红线**：不具体到场景与发言，不台词、镜头、走位、演出指示；只写事件、冲突、节奏、关系变化与结局方向；不台词入大纲，不把 `00-Bible/` 设定原封不动复制进大纲，不预写 `02-Script/` 剧本正文。
- **内容边界**：结局方向只写方向，不写达成条件、分支条件、好感度、FLAG 与判定规则；上述规则只归唯一事实源 `<作品名>/01-Plan/endings-and-flags.md`，本文件不写。
- **文风与排版**：以完整、连贯且包含因果关系的复合句为主，不碎片段落；不「稳稳接住」「接住你」及其比喻义表述；不裸 `~`，连接符用 `-`，编号默认三位（如 `ch001`）。
- 一切大纲事实与结局方向应经用户确认后方可落盘；用户未明示的内容进「开放问题」清单且只列条目标题、不展开，不自行补全后写进正文。存在任何疑问、缺项、冲突或不确定，用 `ask_user_question` 求证，由用户拍板。
- 本节与 §6 中出现的一切旧值及同义文件名，默认处于「旧值 / 迁移对照 / 不」语境，**不作为产出落点**。

**上游只读清单（只读，不改写、不复制进 `01-Plan/` 作为新文件）**：

- `<作品名>/00-Bible/` 全部 Markdown：`anchors.md`、`brainstorm.md`、`characters/<角色名>.md`、`relationships.md`、`world.md`、`factions.md`、`geography.md`、`timeline.md`、`glossary.md`、`style.md`。
- 根级三份文档：`<作品名>/README.md`（唯一进度/阶段状态机）、`<作品名>/Specifications.md`（唯一规范事实源）、`<作品名>/Direction.md`（静态导航地图，只读，不进 `instructionFileCandidates`）。首轮 Read 应显式用文件工具读一次 `Specifications.md` 与 `Direction.md`，后续轮不复读。
- 本预设不挂 `office-reader` / `office-editor`，不读取 `00-Bible/00-Bible-四份版/` 下四个 `.docx`；四份 `.docx` 不参与 `vn-continuity` 核查。

**Check**：按 `vn-continuity` 核查这**一个**产物（只核查本轮产物及其直接上游已确认文件，见 `vn-continuity` §2），按 `vn-spec` 校验统一目录与格式，按 `vn-gate` 校验单轮单条目；不全量核查、不顺手改非本轮文件、不预写下游。发现任何冲突立即停下，用 `ask_user_question` 请用户裁决，不自行改写已确认内容。

**README.md 双区结构**：A 区「当前状态」块 5 个字段（`当前预设` / `当前阶段` / `本轮子条目` / `状态` / `下一候选`）仅在用户确认后**就地更新**（就地字段更新不算改写既有记录）；B 区「进度记录」区**只追加一行**、永不改写或删除既有行。AI 不自行把状态置为「已确认」；只有「已确认」才允许推进。

## 5. 单章大纲条目模板（每轮只写这一节）

```markdown
# 剧情大纲

## ch001 · <章节功能>
- 事件：以完整、连贯且包含因果关系的复合句写该章推动的抽象事件节点，不写场景与发言。
- 冲突：以完整复合句写外部冲突与内心冲突在本章的升级阶梯，不写台词与镜头。
- 节奏：以完整复合句写本章在情感曲线上的定位与转折，不写演出指示。
- 关系变化：以完整复合句写本章各主要关系的变化节点与方向，不写走位。
- 结局方向：以完整复合句写本章通向的主题落点与结局方向，不写达成条件与判定规则。

## 开放问题
- 只列条目标题、不展开。
```

本章之外的内容默认留待用户后续轮次逐条确认，本轮不预写。
