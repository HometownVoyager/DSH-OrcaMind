# vn-outline-endings-flags · 结局与分支条件（唯一事实源）

> 本 skill 仅服务 VN 工作流第 2 阶段（order 31）「VN-剧情大纲设计 / vn-outline」，合并改造自 `vn-design/vn-system-design`，默认使用中文。

## 1. 唯一落点 / 写死路径

- **唯一产出落点（写死）**：`<作品名>/01-Plan/endings-and-flags.md`，且它是结局条件、分支条件、好感度、多结局、FLAG、章节推进规则的**唯一事实源**。本 skill 只向该文件写入「1 条规则」，不写任何其它文件。
- 统一白名单默认为 **6 个编号目录 + 3 个根级文档**：`00-Bible/`、`01-Plan/`、`02-Script/`、`03-Asset/`、`04-ScreenPlay/`、`05-Game/` 六个编号目录，以及根级 `README.md`、`Specifications.md`、`Direction.md` 三份文档；除此之外任何目录或文件不创建。
- 本阶段写权只在 `01-Plan/` 那一列；`01-Plan/` 内本阶段既定文件只有 `outline.md`、`chapter-structure.md`、`endings-and-flags.md` 三份，本 skill 只负责 `endings-and-flags.md`。
- 不另建 `<作品名>/01-Plan/endings.md`、`<作品名>/01-Plan/systems.md` 或任何同义文件；结局与分支规则只归 `endings-and-flags.md` 这一份。
- 下游（VN-剧情写作 / VN-演出剧本 / VN-游戏制造）对本文件**只读**，不另建 `endings.md`、`systems.md` 或任何同义文件。
- `<作品名>/README.md` 不属规则产出落点，只按双区结构更新状态并追加进度行（见 §4）。

## 2. 单轮单条目

- 一个子条目 = 一轮内只处理、只落盘、只核查的单一最小可确认单元；在 `vn-outline` 等于「1 章大纲」「1 条章节结构推进条目」「1 条结局条件」「1 条分支条件」「1 条好感度阈值/变量规则」「1 个 FLAG（含触发与回收条件）」「1 条多结局判定规则」「1 条章节推进规则」「1 段关系变化」中的**恰好一项**。
- 本 skill 每轮只在 `01-Plan/endings-and-flags.md` 中写入**恰好 1 条规则**（1 条结局条件 / 1 条分支条件 / 1 条好感度阈值或变量规则 / 1 个 FLAG / 1 条多结局判定规则 / 1 条章节推进规则，六选一）；不把全部规则当作一个子条目，不在本轮内规划或预写后续子条目。
- 本轮子条目应由用户从候选清单中选定；AI 不自主规划阶段内子任务，不用一份整稿替代逐步确认。
- 默认强制：**每轮只处理 1 个子条目**。

## 3. 硬约束

- **每轮只处理 1 个子条目**：每轮 1 条规则，不把两条及以上规则合并为同一轮子条目。
- **不跨阶段**：下游 `02-Script/`、`03-Asset/`、`04-ScreenPlay/`、`05-Game/` 等一切目录只读，不读取、创建、预写或写入，不在对话中替下游阶段做设计；不写到 `<作品名>/01-Plan/outline.md`、`<作品名>/01-Plan/chapter-structure.md` 或 `02-Script/` 等下游；不改写上游 `00-Bible/` 任何文件。
- **规则只写条件与判定**：只写可判定的条件、变量、阈值、优先级、判定时机、触发与回收条件、解锁与跳转规则；不场景与发言，不台词、镜头、走位、演出指示，不把剧情正文或场景扩写进本文件；以完整、连贯且包含因果关系的复合句为主，不碎片段落，不裸 `~`，连接符用 `-`，编号默认三位（如 `ch001`）。
- **唯一事实源不可分散**：不另建 `01-Plan/endings.md`、`01-Plan/systems.md` 或任何同义文件；不把结局条件、分支条件、好感度、FLAG、多结局判定、章节推进规则分散写入 `01-Plan/outline.md`、`01-Plan/chapter-structure.md` 或任何其它位置。
- **判定无歧义**：两个及以上结局条件同时满足时应给出优先级规则，不留歧义；规则不引入与 `00-Bible/anchors.md` 四节锚点矩阵冲突的新事实，涉及基准事实时先回锚点核验，冲突请用户裁决。
- 一切规则与条件应经用户确认后方可落盘；用户未明示的内容进「开放问题」清单且只列条目标题、不展开，不自行补全后写进正文。存在任何疑问、缺项、冲突或不确定，用 `ask_user_question` 求证，由用户拍板。
- 本节与 §6 中出现的一切旧值及同义文件名，默认处于「旧值 / 迁移对照 / 不」语境，**不作为产出落点**。

**上游只读清单（只读，不改写、不复制进 `01-Plan/` 作为新文件）**：

- `<作品名>/00-Bible/` 全部 Markdown：`anchors.md`、`brainstorm.md`、`characters/<角色名>.md`、`relationships.md`、`world.md`、`factions.md`、`geography.md`、`timeline.md`、`glossary.md`、`style.md`。
- 根级三份文档：`<作品名>/README.md`（唯一进度/阶段状态机）、`<作品名>/Specifications.md`（唯一规范事实源）、`<作品名>/Direction.md`（静态导航地图，只读，不进 `instructionFileCandidates`）。首轮 Read 应显式用文件工具读一次 `Specifications.md` 与 `Direction.md`，后续轮不复读。
- 本预设不挂 `office-reader` / `office-editor`，不读取 `00-Bible/00-Bible-四份版/` 下四个 `.docx`；四份 `.docx` 不参与 `vn-continuity` 核查。

**Check**：按 `vn-continuity` 核查这**一个**产物（只核查本轮产物及其直接上游已确认文件，见 `vn-continuity` §2），按 `vn-spec` 校验统一目录与格式，按 `vn-gate` 校验单轮单条目；`Check` 时只验证本轮产物是否与唯一事实源一致，不据此新建 `endings.md` / `systems.md` 或任何同义文件，不把结局条件散落进其它文件；不全量核查、不顺手改非本轮文件、不预写下游。发现任何冲突立即停下，用 `ask_user_question` 请用户裁决，不自行改写已确认内容。

**README.md 双区结构**：A 区「当前状态」块 5 个字段（`当前预设` / `当前阶段` / `本轮子条目` / `状态` / `下一候选`）仅在用户确认后**就地更新**（就地字段更新不算改写既有记录）；B 区「进度记录」区**只追加一行**、永不改写或删除既有行。AI 不自行把状态置为「已确认」；只有「已确认」才允许推进。

## 5. 规则条目模板（每轮只写这一条，六选一）

```markdown
# 结局与分支条件（唯一事实源）

## 本轮规则：<规则类型：结局条件 / 分支条件 / 好感度阈值或变量规则 / FLAG / 多结局判定规则 / 章节推进规则>
- 条件：以完整、连贯且包含因果关系的复合句写可判定的触发条件，不写场景与发言。
- 变量与阈值：以完整复合句写所涉变量、取值范围或阈值，不写演出指示。
- 判定时机与优先级：以完整复合句写何时判定、与其它条件同时满足时的优先级，不留歧义。
- 触发 / 回收 / 解锁结果：以完整复合句写条件成立后的判定结果，不写剧情正文。

## 开放问题
- 只列条目标题、不展开。
```

本条之外的规则默认留待用户后续轮次逐条确认，本轮不预写。
