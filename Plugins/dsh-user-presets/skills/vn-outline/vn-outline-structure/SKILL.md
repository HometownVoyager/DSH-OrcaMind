# vn-outline-structure · 章节结构表

> 本 skill 仅服务 VN 工作流第 2 阶段（order 31）「VN-剧情大纲设计 / vn-outline」，合并改造自 `vn-design/vn-story-outline`，默认使用中文。

## 1. 唯一落点 / 写死路径

- **唯一产出落点（写死）**：`<作品名>/01-Plan/chapter-structure.md`。本 skill 只向该文件写入「1 条章节推进条目」，不写任何其它文件。
- 统一白名单默认为 **6 个编号目录 + 3 个根级文档**：`00-Bible/`、`01-Plan/`、`02-Script/`、`03-Asset/`、`04-ScreenPlay/`、`05-Game/` 六个编号目录，以及根级 `README.md`、`Specifications.md`、`Direction.md` 三份文档；除此之外任何目录或文件不创建。
- 本阶段写权只在 `01-Plan/` 那一列；`01-Plan/` 内本阶段既定文件只有 `outline.md`、`chapter-structure.md`、`endings-and-flags.md` 三份，本 skill 只负责 `chapter-structure.md`。
- 不另建 `<作品名>/01-Plan/structure.md` 或任何同义结构表；章节结构表只认 `chapter-structure.md` 这一份。
- `<作品名>/README.md` 不属结构表产出落点，只按双区结构更新状态并追加进度行（见 §4）。

## 2. 单轮单条目

- 一个子条目 = 一轮内只处理、只落盘、只核查的单一最小可确认单元；在 `vn-outline` 等于「1 章大纲」「1 条章节结构推进条目」「1 条结局条件」「1 条分支条件」「1 条好感度阈值/变量规则」「1 个 FLAG（含触发与回收条件）」「1 条多结局判定规则」「1 条章节推进规则」「1 段关系变化」中的**恰好一项**。
- 本 skill 每轮只在 `01-Plan/chapter-structure.md` 中写入**恰好 1 条章节推进条目**（对应第 N 章）；不把整份结构表当作一个子条目，不在本轮内规划或预写后续子条目。
- 本轮子条目应由用户从候选清单中选定；AI 不自主规划阶段内子任务，不用一份整稿替代逐步确认。
- 默认强制：**每轮只处理 1 个子条目**。

## 3. 硬约束

- **每轮只处理 1 个子条目**：每轮 1 条章节推进条目，不把两条及以上条目合并为同一轮子条目。
- **不跨阶段**：不读取、创建或预写 `02-Script/`、`03-Asset/`、`04-ScreenPlay/`、`05-Game/` 等任何下游目录与文件，不写入下游目录，不在对话中替下游阶段做设计；不改写 `00-Bible/` 上游任何文件。
- **章节编号硬规则**：章节编号默认三位 `ch001`、`ch002`……；分支后缀默认 `ch001-2a` 形式（连接符用 `-`），不裸 `~`；不碎片段落，以完整、连贯且包含因果关系的复合句为主。
- **内容边界**：本文件只写章节号、章节功能、关键事件、情感节奏与分支点预留标注；不把结局条件、分支条件、好感度、FLAG、多结局判定与章节推进规则写进本文件，上述一切**只归唯一事实源 `<作品名>/01-Plan/endings-and-flags.md`**；分支剧情在本文件只做节点标注，变量与条件不写。
- 不另建 `01-Plan/structure.md` 或任何同义结构表；不把 `00-Bible/` 设定原封不动复制进结构表；不具体到场景与发言，不台词、镜头、走位、演出指示。
- 一切结构事实应经用户确认后方可落盘；用户未明示的内容进「开放问题」清单且只列条目标题、不展开，不自行补全后写进正文。存在任何疑问、缺项、冲突或不确定，用 `ask_user_question` 求证，由用户拍板。
- 本节与 §6 中出现的一切旧值及同义文件名，默认处于「旧值 / 迁移对照 / 不」语境，**不作为产出落点**。

**上游只读清单（只读，不改写、不复制进 `01-Plan/` 作为新文件）**：

- `<作品名>/00-Bible/` 全部 Markdown：`anchors.md`、`brainstorm.md`、`characters/<角色名>.md`、`relationships.md`、`world.md`、`factions.md`、`geography.md`、`timeline.md`、`glossary.md`、`style.md`。
- 根级三份文档：`<作品名>/README.md`（唯一进度/阶段状态机）、`<作品名>/Specifications.md`（唯一规范事实源）、`<作品名>/Direction.md`（静态导航地图，只读，不进 `instructionFileCandidates`）。首轮 Read 应显式用文件工具读一次 `Specifications.md` 与 `Direction.md`，后续轮不复读。
- 本预设不挂 `office-reader` / `office-editor`，不读取 `00-Bible/00-Bible-四份版/` 下四个 `.docx`；四份 `.docx` 不参与 `vn-continuity` 核查。

**Check**：按 `vn-continuity` 核查这**一个**产物（只核查本轮产物及其直接上游已确认文件，见 `vn-continuity` §2），按 `vn-spec` 校验统一目录与格式，按 `vn-gate` 校验单轮单条目；不全量核查、不顺手改非本轮文件、不预写下游。发现任何冲突立即停下，用 `ask_user_question` 请用户裁决，不自行改写已确认内容。

**README.md 双区结构**：A 区「当前状态」块 5 个字段（`当前预设` / `当前阶段` / `本轮子条目` / `状态` / `下一候选`）仅在用户确认后**就地更新**（就地字段更新不算改写既有记录）；B 区「进度记录」区**只追加一行**、永不改写或删除既有行。AI 不自行把状态置为「已确认」；只有「已确认」才允许推进。

## 5. 章节结构条目模板（每轮只写这一条）

```markdown
# 章节结构表

| 章节号 | 章节功能 | 关键事件（抽象，禁止场景与发言） | 情感节奏 | 分支点预留（只标节点，不写条件） |
|---|---|---|---|---|
| ch001 | 以完整复合句写引入/铺垫/转折/高潮/收束之一 | 以完整、连贯且包含因果关系的复合句写抽象事件节点 | 以完整复合句写情绪上扬或下坠的定位 | 以完整复合句标注分支节点存在，条件一律留空、只归 endings-and-flags.md |

## 开放问题
- 只列条目标题、不展开。
```

本条之外的章节条目默认留待用户后续轮次逐条确认，本轮不预写。
