# 交接与状态机验收（staging-acceptance）

## 何时使用
- 每一轮 Read 步开始时，先校验上游交接与只读前置条件。
- 宣布某一轮或整套逐场演出剧本融合稿完成之前。
- 用户要求「验收一下」「看看当前预设对不对」时。

## 职责定位（02 底本 + 演出指示融合稿）
本阶段以 `<作品名>/02-Script/` 纯剧本正文为唯一底本，叠加演出指示写成逐场融合稿，产出只落在 `<作品名>/04-ScreenPlay/`。本 skill 沿用 vn-staging `staging-acceptance` 的「校验/判定」内核，改为校验上游交接、README 状态机与「当前预设」匹配。

## 唯一落点 / 写死路径
- **唯一产出目录写死 `<作品名>/04-ScreenPlay/`**，固定产出仅 `演出精述.md` / `draft-vN/scNNN.md` / `scene-map.md` 三类。
- 本 skill 为只读校验型：不产出新文档；仅在「合法交接」时按 `vn-gate` §4 的双区结构对 `<作品名>/README.md` 就地登记 A 区「当前预设」为 `vn-screenplay` 并在 B 区追加一行交接登记。
- README.md 双区结构：A 区「当前状态」块 5 字段（当前预设 / 当前阶段 / 本轮子条目 / 状态(进行中|待确认|已确认) / 下一候选）就地更新，B 区「进度记录」只追加一行、永不改写或删除既有行；AI 不自行把状态置为「已确认」。
- 白名单为**6 个编号目录 + 3 个根级文档**：`00-Bible/ 01-Plan/ 02-Script/ 03-Asset/ 04-ScreenPlay/ 05-Game/` 六目录，加根级 `README.md`、`Specifications.md`、`Direction.md` 三文档（不是 6+2）。`Direction.md` 是静态导航地图、不记录逐轮进度；制作计划与逐轮进度只归 README.md。
- cwd 应是 `<作品名>/` 或其子目录；显式读 `<作品名>/Specifications.md`（存在性校验）与 `<作品名>/README.md`（状态机校验）。

## 三分支判定（§4.3 §5）
按 README.md 的「当前预设」按三分支判定，状态机字段为 当前预设 / 当前阶段 / 本轮子条目 / 状态(进行中|待确认|已确认) / 下一候选，只有「已确认」才允许推进：
1. **匹配自己**（当前预设 = vn-screenplay / VN-演出剧本）：直接继续本轮，不动文件。
2. **合法交接**（紧邻上游预设 id 且 状态=已确认）：本预设首轮就地登记 A 区「当前预设」为自己的 id，并在 B 区追加一行交接登记后继续本轮（不算 AI 自行切换）。
3. **其余不匹配**：**立即停下询问、不动任何文件**——不读其它文件后顺手改、不补建、不顺带推进、不写入任何文件。

## 单轮单条目
- **每轮只处理 1 个子条目**：一轮只做一项验收判定或一条交接登记，由用户从候选清单中选定，不自主规划本阶段子任务。
- **不跨阶段**：不读写下游阶段目录、不创建下游文件、不在对话中替下游做设计；不做上游阶段的事。
- 只增不改：不改写上游只读文件；README.md 只按双区结构登记/追加。
- 不复制 `02-Script/` 纯正文另建同义文件。

## 七步循环与 Check
- Read → Report → Confirm → Do → Check → Write → Stop。Read 显式读 `<作品名>/README.md`、`<作品名>/Specifications.md` 与根级 `Direction.md`；Confirm / Stop 两组常用选项可按需选用，不必互斥套用（见 `vn-gate` §2）：Confirm 组「就做这一个 / 换一个子条目 / 先不做，停下询问」，Stop 组「认可本轮成果 / 换一个子条目重做 / 本阶段已确认，进入下一预设」。
- Check 按 `vn-continuity`：场次号连续、状态词合法、路径一致、无伪造资产、无引擎语法、进度落盘。
- Write 只写这一个文件（只增不改），并就地更新 README.md A 区 5 字段 + 在 B 区追加一行（状态「待确认」）。

## 8 条核心原则
① 实际资产优先于资产列表（`03-Asset/generated/` 磁盘实际为准，`asset-list.md` 是需求文档，`asset-index.md` 只读）。② 不伪造资产路径、资产 ID、差分名。③ 不将就也不死板（缺口显式化，不凑合使用未确认资产，不擅自改写剧本）。④ 缺口显式化（以 `03-Asset/asset-gap.md` 为准，按 8 词状态词表在融合稿中标注引用，不默默绕过/另写缺口文档/改写资产缺口表）。⑤ 融合稿与引擎转写分离（不引擎语法、路径、扩展名、引擎资源加载语法）。⑥ 长流程落盘（进度应落磁盘，每轮只增不改写入 04-ScreenPlay/ 并在 README.md 追加一行）。⑦ 单 Agent 推进（不多 Agent 协作文档、分工表、交接协议）。⑧ 主动询问、确认后整理（存在疑问应主动询问，确认后才整理落盘，不凭空假设）。
