# 演出融合稿一致性核查（staging-continuity）

## 何时使用
- 每轮产出落盘之前（对应七步循环的 Check 步）。
- 定稿某一稿次或交付整套逐场融合稿之前。
- 上游剧本或资产发生变更之后，判断哪些场次受影响时。
- 用户提出「检查一下有没有前后矛盾」时。

## 职责定位（02 底本 + 演出指示融合稿）
本阶段以 `<作品名>/02-Script/` 纯剧本正文为唯一底本，叠加演出指示写成逐场融合稿，产出只落在 `<作品名>/04-ScreenPlay/`。本 skill 沿用 vn-staging `staging-continuity` 的「五维核查」内核，改为只核查本阶段融合稿；Check 按 `vn-continuity` 只核查本轮产物及其直接上游已确认文件，不承担全链基准。

## 唯一落点 / 写死路径
- **唯一产出目录写死 `<作品名>/04-ScreenPlay/`**，固定产出仅 `演出精述.md` / `draft-vN/scNNN.md` / `scene-map.md` 三类。
- `SC-001` 三位递增不复用、不跳号改写：场次号自 `SC-001` 起按三位十进制递增（`SC-001`、`SC-012`、`SC-100`），一经分配不复用。
- `<作品名>/04-ScreenPlay/draft-vN/sc001.md` 三位编号：逐场融合稿文件名默认三位（`sc001.md`…），`scene-map.md` 场次号 `SC-001` 三位递增不复用。
- 白名单为**6 个编号目录 + 3 个根级文档**：`00-Bible/ 01-Plan/ 02-Script/ 03-Asset/ 04-ScreenPlay/ 05-Game/` 六目录，加根级 `README.md`、`Specifications.md`、`Direction.md` 三文档（不是 6+2）。`Direction.md` 是静态导航地图、不记录逐轮进度；制作计划与逐轮进度只归 README.md。

## 核查维度（每项须基于读到的文件，不凭印象勾选）
| 维度 | 比对对象 | 要回答的问题 |
|------|----------|--------------|
| 覆盖性 | 融合稿 ↔ `02-Script/` 底本 | 每一章、每一段是否都有归属场次，有无漏演或多演 |
| 台词一致性 | 融合稿 ↔ `02-Script/` 底本 | 台词是否与底本逐字一致，未被改写、删减或错位 |
| 引用一致性 | 融合稿 ↔ `03-Asset/asset-index.md`（只读） | 每个 ID 是否真实存在、状态是否与只读索引一致 |
| 标注一致性 | 融合稿 ↔ `03-Asset/asset-gap.md`（只读） | 非 `available` 引用是否都有标注、状态是否与只读缺口表一致 |
| 跨场连续性 | 场次稿之间 | 站位、服饰、时间推进、背景沿用、情绪曲线是否连贯 |

核查清单：
- [ ] 场次号连续（`SC-001` 三位递增不复用）、`scene-map.md` 与各场稿一致、无悬空编号。
- [ ] 状态词合法：只用 8 词状态词表，无自造词。
- [ ] 路径一致：唯一产出落点为 04-ScreenPlay/，无旧路径作为事实源或落点。
- [ ] 无伪造资产：无编造的路径、ID、差分名、BGM 名、CG 编号；引用对应磁盘实际资产。
- [ ] 无引擎语法：逐场融合稿**不写路径、不写扩展名、不写引擎资源加载语法**。
- [ ] 进度落盘：本轮产物已写入磁盘，README.md B 区已追加一行（状态「待确认」）。
- [ ] 未复制 `02-Script/` 纯正文：04-ScreenPlay/ 只有底本+演出指示融合稿，无同义纯正文文件。
- [ ] 无计划外文档：04 只含三类固定产出。

## 冲突处理
事实源优先级：磁盘实际资产 > `03-Asset/asset-index.md`（只读）> 上游已确认内容 > 本阶段产出。属于本阶段产出的错误（引用错 ID、状态写错、站位矛盾）直接修正并说明；属于上游内容的冲突**不自行改写上游**，列出冲突并停下询问；属于资产现实的冲突停下询问并按缺口流程呈报，不自行修订只读索引/缺口表。

## 硬门
没有 `<作品名>/03-Asset/asset-index.md` 与 `<作品名>/03-Asset/asset-gap.md` 且未经用户确认之前，**默认不开始逐场演出剧本（用户显式指令可覆盖）**；这两份由 vn-asset-list / vn-asset-make 协作生成，本预设只读、不改写、不另建副本。

## 只读与禁写
- 上游 `<作品名>/00-Bible/`、`<作品名>/01-Plan/`、`<作品名>/02-Script/`、`<作品名>/03-Asset/`（含 asset-index.md / asset-gap.md / generated/）与根级 `Direction.md`、`Specifications.md` 只读，不改写。
- `README.md` 采用双区结构（见 `vn-gate` §4）：A 区「当前状态」块 5 字段（当前预设 / 当前阶段 / 本轮子条目 / 状态 / 下一候选）就地更新，B 区「进度记录」只追加一行、永不改写或删除既有行；状态默认「待确认」，不自行置「已确认」。
- **不引用旧路径作为事实源**；不创建计划外文档与计划外目录；不一次性交付多份文档；不预写 `<作品名>/05-Game/`。

## 旧路径语境（不作为产出落点，仅迁移对照）
`00-设定/ 01-规划/ 02-系统/ 02-剧本/ 03-修订/ 04-资产/ 05-剧本/ 06-演出/ assets/ 规范-*.md / 剧情精述.md（根级）` 等旧路径**不作为产出落点**，只允许出现在「旧值 / 迁移 / 不 / 上游只读」语境：旧 `05-剧本/draft-vN/`→`02-Script/draft-vN/`（上游只读）、根级 `剧情精述.md`→`02-Script/剧情精述.md`（上游只读）、`04-资产/asset-list.md`→`03-Asset/asset-list.md`（上游只读）、`06-演出/`→`04-ScreenPlay/`、`assets/`→`03-Asset/generated/`。

## 单轮单条目
- **每轮只处理 1 个子条目**：一轮只核查 1 个产物（1 场融合稿或 `scene-map.md` 中 1 个条目），由用户从候选清单中选定，不自主规划本阶段子任务。
- **不跨阶段**：不读写下游阶段目录、不创建下游文件、不在对话中替下游做设计；不做上游阶段的事。
- 只增不改：不改写上游只读文件；修正本阶段错误亦以只增不改方式另起新文件，不覆盖既有落盘文件。

## 七步循环与 Check
- Read → Report → Confirm → Do → Check → Write → Stop。Read 显式读 `<作品名>/README.md`、`<作品名>/Specifications.md` 与根级 `Direction.md`，以及 `02-Script/` 底本、只读 asset-index.md / asset-gap.md、generated/ 磁盘实际资产、`04-ScreenPlay/` 已有产物；Confirm / Stop 两组常用选项可按需选用，不必互斥套用（见 `vn-gate` §2）。
- Check 按 `vn-continuity`：只核查本轮产物及其直接上游已确认文件，逐条留痕（通过 / 不通过 / 待裁决）。
- Write 只写这一个文件（只增不改），就地更新 README.md A 区 5 字段 + 在 B 区追加一行（状态「待确认」）。

## 8 条核心原则
① 实际资产优先于资产列表（磁盘实际为准，asset-list.md 是需求文档，asset-index.md 只读）。② 不伪造资产路径、资产 ID、差分名。③ 不将就也不死板（缺口显式化，不凑合使用未确认资产，不擅自改写剧本）。④ 缺口显式化（以 `03-Asset/asset-gap.md` 为准，按 8 词状态词表在融合稿中标注引用，不默默绕过/另写缺口文档/改写资产缺口表）。⑤ 融合稿与引擎转写分离（不引擎语法、路径、扩展名、引擎资源加载语法）。⑥ 长流程落盘（进度应落磁盘，不只存在对话里，每轮只增不改写入 04-ScreenPlay/ 并在 README.md 追加一行）。⑦ 单 Agent 推进（不多 Agent 协作文档、分工表、交接协议）。⑧ 主动询问、确认后整理（存在疑问应主动询问，确认后才整理落盘，不凭空假设）。

## 8 词状态词表
只用 `available / generated / substitute / placeholder / missing / hard_missing / pending / listed_but_missing` 这 8 个词标注资产状态；不自造同义词、缩写或新状态词。
