# 单场演出提示编排（staging-cues）

## 何时使用
- 为某一场戏编排台词、表情、音乐、转场 cue 时。
- 复查既有场次融合稿的演出密度与情绪走向时。
- 每轮 Do 步执行「本轮唯一一个」逐场融合稿子条目时。

## 职责定位（02 底本 + 演出指示融合稿）
**以 `<作品名>/02-Script/` 纯剧本正文（台词/叙述/场景表）为唯一底本**，叠加演出指示（镜头/立绘/BGM/转场 cue）写成逐场演出剧本融合稿。本 skill 沿用 vn-staging `staging-cues` 的「听觉与节奏 cue」内核，扩展为单场演出提示编排（台词、表情、音乐、转场 cue），产出只落在 `<作品名>/04-ScreenPlay/`。

## 唯一落点 / 写死路径
- **唯一产出目录写死 `<作品名>/04-ScreenPlay/`**，固定产出仅 `演出精述.md` / `draft-vN/scNNN.md` / `scene-map.md` 三类。
- **只写 `<作品名>/04-ScreenPlay/draft-vN/scNNN.md`**：本 skill 一轮只写这一个逐场融合稿文件（三位编号，如 `sc001.md`）。
- 白名单为**6 个编号目录 + 3 个根级文档**：`00-Bible/ 01-Plan/ 02-Script/ 03-Asset/ 04-ScreenPlay/ 05-Game/` 六目录，加根级 `README.md`、`Specifications.md`、`Direction.md` 三文档（不是 6+2）。`Direction.md` 是静态导航地图、不记录逐轮进度；制作计划与逐轮进度只归 README.md。

## 编排规则（只增不改）
- **只增不改**：在底本之上叠加演出指示，不改写、不删减、不重排 `02-Script/` 纯剧本正文台词；台词与底本逐字一致，只整理与标注演出。
- **不复制纯正文另建同义文件**：`04-ScreenPlay/` 只写「底本 + 演出指示」融合稿，不复制纯正文，不在 04 内另建与 `02-Script/` 同义的纯剧本文件。
- 台词 cue：带上游定位（章-段-序号），保留原文措辞，写明语气与切换时机。
- 表情 cue：只引用 `03-Asset/asset-index.md`（只读）中该立绘实际拥有的差分，索引里没有的按缺口流程走，不编造差分名。
- 音乐 cue：只引用只读索引中实际存在的 `BGM_*` / `SFX_*`；淡入淡出、静默、环境音只写意图与时机，不写曲线与参数。
- 转场 cue：用自然语言描述意图（直切 / 淡入淡出 / 黑场 / 白闪 / 溶解），同一部作品转场词汇统一。
- **不写路径、不写扩展名、不写引擎资源加载语法**：逐场融合稿不引擎语法，不写引擎命令、配置、参数表、通道编号与文件格式参数，只写引用、时机与意图。
- 引用按 8 词状态词表标注；非 `available` 引用应在「缺口与标注」区有对应条目，与只读 `03-Asset/asset-gap.md` 一致，不默默绕过。

## 硬门
没有 `<作品名>/03-Asset/asset-index.md` 与 `<作品名>/03-Asset/asset-gap.md` 且未经用户确认之前，**默认不开始逐场演出剧本（用户显式指令可覆盖）**；未满足硬门应停下询问，不预写逐场稿。这两份由 vn-asset-list / vn-asset-make 协作生成，本预设只读、不改写、不另建副本。

## 只读与禁写
- 上游 `<作品名>/00-Bible/`、`<作品名>/01-Plan/`、`<作品名>/02-Script/`、`<作品名>/03-Asset/`（含 asset-index.md / asset-gap.md / generated/）与根级 `Direction.md`、`Specifications.md` **只读**，不改写、不另建副本。
- 不创建计划外文档与计划外目录；不一次性交付多份文档；不预写 `<作品名>/05-Game/`。
- **单 Agent 推进：不编写多 Agent 协作文档、分工表、交接协议。**

## 旧路径语境（不作为产出落点，仅迁移对照）
`00-设定/ 01-规划/ 02-系统/ 02-剧本/ 03-修订/ 04-资产/ 05-剧本/ 06-演出/ assets/ 规范-*.md / 剧情精述.md（根级）` 等旧路径**不作为产出落点**，只允许出现在「旧值 / 迁移 / 不 / 上游只读」语境：旧 `05-剧本/draft-vN/`→`02-Script/draft-vN/`（上游只读）、`06-演出/`→`04-ScreenPlay/`、`assets/`→`03-Asset/generated/`、`规范-演出.md`→`Specifications.md`、根级 `剧情精述.md`→`02-Script/剧情精述.md`（上游只读）。不引用旧路径作为事实源。

## 单轮单条目
- **每轮只处理 1 个子条目**：一轮只做 1 场逐场融合稿，由用户从候选清单中选定，不自主规划本阶段子任务、不在本轮内规划或预写后续子条目。
- **不跨阶段**：不读写下游阶段目录、不创建下游文件、不在对话中替下游做设计；不做上游阶段的事（改写设定/大纲/剧本正文/资产清单与规格/资产索引与缺口）。
- 只增不改：只写 04-ScreenPlay/ 这一处；不改写上游只读文件；README.md 只按双区结构追加一行。

## 七步循环与 Check
- Read → Report → Confirm → Do → Check → Write → Stop。Read 显式读 `<作品名>/README.md`、`<作品名>/Specifications.md` 与根级 `Direction.md`，读 `02-Script/` 底本、只读 asset-index.md / asset-gap.md、generated/ 磁盘实际资产、`04-ScreenPlay/` 已有产物；Confirm / Stop 两组常用选项可按需选用，不必互斥套用（见 `vn-gate` §2）：Confirm 组「就做这一个 / 换一个子条目 / 先不做，停下询问」，Stop 组「认可本轮成果 / 换一个子条目重做 / 本阶段已确认，进入下一预设」。
- Check 按 `vn-continuity`：场次号连续、状态词合法、路径一致、无伪造资产、无引擎语法、进度落盘、未复制 02-Script 正文。
- Write 只写这一个文件（只增不改），就地更新 README.md A 区 5 字段 + 在 B 区追加一行（状态「待确认」）。

## 8 条核心原则
① 实际资产优先于资产列表（磁盘实际为准，asset-list.md 是需求文档，asset-index.md 只读）。② 不伪造资产路径、资产 ID、差分名。③ 不将就也不死板（缺口显式化，不凑合使用未确认资产，不擅自改写剧本）。④ 缺口显式化（以 `03-Asset/asset-gap.md` 为准，按 8 词状态词表在融合稿中标注引用，不默默绕过/另写缺口文档/改写资产缺口表）。⑤ 融合稿与引擎转写分离（不引擎语法、路径、扩展名、引擎资源加载语法）。⑥ 长流程落盘（进度应落磁盘，每轮只增不改写入 04-ScreenPlay/ 并在 README.md 追加一行）。⑦ 单 Agent 推进（不多 Agent 协作文档、分工表、交接协议）。⑧ 主动询问、确认后整理（存在疑问应主动询问，确认后才整理落盘，不凭空假设）。

只用 `available / generated / substitute / placeholder / missing / hard_missing / pending / listed_but_missing` 这 8 个词标注资产状态；不自造同义词、缩写或新状态词。
