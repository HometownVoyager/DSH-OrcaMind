# 演出精述撰写（staging-direction）

## 何时使用
- 撰写或更新 `<作品名>/04-ScreenPlay/演出精述.md` 中的 1 个条目时。
- 需要按场次概括「这场戏演什么、画面怎么走、情绪怎么变、用了哪些资产、有哪些缺口与标注」时。
- 每轮 Do 步选中「演出精述.md 的 1 个条目」作为唯一子条目时。

## 职责定位（02 底本 + 演出指示融合稿）
本阶段以 `<作品名>/02-Script/` 纯剧本正文为唯一底本，叠加演出指示写成逐场融合稿，产出只落在 `<作品名>/04-ScreenPlay/`。本 skill 沿用 vn-staging `staging-direction` 的「视觉演出设计/分场」内核，改为**撰写演出精述**：把「上下游与路径」表与制作计划默认交给根级 `Direction.md` / `README.md`（本 skill 只读引用，不另写这两份）。

## 唯一落点 / 写死路径
- **唯一产出目录写死 `<作品名>/04-ScreenPlay/`**，固定产出仅 `演出精述.md` / `draft-vN/scNNN.md` / `scene-map.md` 三类。
- **本 skill 只写 `<作品名>/04-ScreenPlay/演出精述.md`**：一轮只写其中 1 个条目，只增不改。
- 「上下游与路径」表以根级 `Direction.md` 的**静态导航**为准（只读）：`Direction.md` 是静态导航地图、不记录逐轮进度、不是事实源/状态机；本 skill 只读引用，不改写既有条目、不复制其内容、不写入逐轮进度、不另建「总体说明 / 制作计划」文档。
- **制作计划与逐轮进度只归 `README.md`**：README.md 采用双区结构（见 `vn-gate` §4），A 区「当前状态」块 5 字段（当前预设 / 当前阶段 / 本轮子条目 / 状态 / 下一候选）就地更新，B 区「进度记录」只追加一行、永不改写或删除既有行；本 skill 只读引用 `Direction.md`，不另写这两份。
- 白名单为**6 个编号目录 + 3 个根级文档**：`00-Bible/ 01-Plan/ 02-Script/ 03-Asset/ 04-ScreenPlay/ 05-Game/` 六目录，加根级 `README.md`、`Specifications.md`、`Direction.md` 三文档（不是 6+2）。

## 演出精述写法（只增不改）
- 按 `SC-001` 三位递增不复用逐条写「逐场精述」：每条含场次号、地点·时间、对应上游章-段，用复合句完整概括这场戏演什么、画面怎么走、情绪怎么变、用了哪些资产、有哪些缺口与 8 词状态词表标注；可独立读懂。
- 每完成一场或一次修订，只增不改地追加/更新对应条目；不覆盖或改写既有落盘条目，精述与已确认融合稿不一致时以融合稿与已确认内容为准并在本轮内补正说明。
- 资产引用以 `03-Asset/generated/` 磁盘实际文件与只读 `03-Asset/asset-index.md` / `asset-gap.md` 为准；不伪造资产路径、ID、差分名。
- 逐场演出剧本不引擎语法：不写路径、不写扩展名、不写引擎资源加载语法；演出精述同样只写演出意图。
- **不把 `02-Script/` 正文复制进 `04-ScreenPlay/`**：演出精述是概括与演出指示，不是纯正文副本。

## 硬门
没有 `<作品名>/03-Asset/asset-index.md` 与 `<作品名>/03-Asset/asset-gap.md` 且未经用户确认之前，**默认不开始逐场演出剧本（用户显式指令可覆盖）**；这两份由 vn-asset-list / vn-asset-make 协作生成，本预设只读、不改写、不另建副本。

- 不创建计划外文档与计划外目录；不一次性交付多份文档；不预写 `<作品名>/05-Game/`；不编写多 Agent 协作文档、分工表、交接协议（单 Agent 推进）。

## 单轮单条目
- **每轮只处理 1 个子条目**：一轮只写 `演出精述.md` 中的 1 个条目，由用户从候选清单中选定，不自主规划本阶段子任务、不在本轮内规划或预写后续子条目。
- **不跨阶段**：不读写下游阶段目录、不创建下游文件、不在对话中替下游做设计；不做上游阶段的事。
- 只增不改：不改写上游只读文件与 `Direction.md` 既有条目。

## 七步循环与 Check
- Read → Report → Confirm → Do → Check → Write → Stop。Read 显式读 `<作品名>/README.md`、`<作品名>/Specifications.md` 与根级 `Direction.md`（只读静态导航），以及 `02-Script/` 底本、只读 asset-index.md / asset-gap.md、`04-ScreenPlay/` 已有产物；Confirm / Stop 两组常用选项可按需选用，不必互斥套用（见 `vn-gate` §2）。
- Check 按 `vn-continuity`：场次号连续、状态词合法、路径一致、无伪造资产、无引擎语法、进度落盘。
- Write 只写这一个文件（只增不改），就地更新 README.md A 区 5 字段 + 在 B 区追加一行（状态「待确认」）。

## 8 条核心原则
① 实际资产优先于资产列表（磁盘实际为准，asset-list.md 是需求文档，asset-index.md 只读）。② 不伪造资产路径、资产 ID、差分名。③ 不将就也不死板（缺口显式化，不凑合使用未确认资产，不擅自改写剧本）。④ 缺口显式化（以 `03-Asset/asset-gap.md` 为准，按 8 词状态词表在融合稿中标注引用，不默默绕过/另写缺口文档/改写资产缺口表）。⑤ 融合稿与引擎转写分离（不引擎语法、路径、扩展名、引擎资源加载语法）。⑥ 长流程落盘（进度应落磁盘，每轮只增不改写入 04-ScreenPlay/ 并在 README.md 追加一行）。⑦ 单 Agent 推进（不多 Agent 协作文档、分工表、交接协议）。⑧ 主动询问、确认后整理（存在疑问应主动询问，确认后才整理落盘，不凭空假设）。
