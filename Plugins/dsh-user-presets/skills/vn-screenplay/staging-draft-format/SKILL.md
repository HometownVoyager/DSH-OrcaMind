# 逐场融合稿与场次表格式（staging-draft-format）

## 何时使用
- 撰写任何一场逐场演出剧本融合稿之前（先确认格式，再动笔）。
- 定稿某一稿次之前。
- 审阅既有场次稿、判断它是否合格时。
- 起草或修订 `scene-map.md` 场次表格式时。

## 职责定位（02 底本 + 演出指示融合稿）
本阶段以 `<作品名>/02-Script/` 纯剧本正文为唯一底本，叠加演出指示写成逐场演出剧本融合稿，产出只落在 `<作品名>/04-ScreenPlay/`。本 skill 沿用 vn-staging `staging-draft-format` 的「格式规范」内核，改为定义**融合稿**（底本 + 演出指示）格式。

## 唯一落点 / 写死路径
- **唯一产出目录写死 `<作品名>/04-ScreenPlay/`**，固定产出仅三类：`演出精述.md`、`draft-vN/scNNN.md`（逐场演出剧本融合稿）、`scene-map.md`（演出侧场次表）。
- 本 skill 定义格式规范，本身不另写规范文档、不建任何计划外文档（旧「规范-演出.md」等旧值仅作迁移对照，不作为产出落点）；格式要点只用于约束 `draft-vN/sc001.md` 与 `scene-map.md` 的写法。
- 白名单为**6 个编号目录 + 3 个根级文档**：`00-Bible/ 01-Plan/ 02-Script/ 03-Asset/ 04-ScreenPlay/ 05-Game/` 六目录，加根级 `README.md`、`Specifications.md`、`Direction.md` 三文档（不是 6+2）。`Direction.md` 是静态导航地图、不记录逐轮进度；制作计划与逐轮进度只归 README.md。

## 格式规范（三位编号 / SC-001 / 场次号不复用）
- 逐场融合稿文件名默认三位编号：`<作品名>/04-ScreenPlay/draft-vN/sc001.md`（`sc001.md`、`sc012.md`、`sc100.md`）；稿次用目录区分 `draft-v1/`、`draft-v2/`，新稿次不覆盖旧稿次。
- `scene-map.md` 场次号 `SC-001` 起三位递增、不复用、不跳号改写；拆分与合并产生的新编号顺延，旧编号在 `scene-map.md` 中标注去向，避免悬空引用。
- 每场应登记与 `02-Script/` 底本的对应关系（章-段），格式如 `ch003-2a`；一场覆盖多段时全部列出。
- 融合稿模板（底本 + 演出指示）：场次头、场次功能、上游视点、出场、背景、BGM、环境音、音效、转场入/出、**演出**步骤、**缺口与标注**区。不适用的小节写「无」并给理由，不留空。
- 资产引用语法：反引号包裹 ID，ID 后紧跟括号状态，状态取自 8 词状态词表；替代类写出来源；非 `available` 引用应在「缺口与标注」区一一对应。
- **不写路径、不写扩展名、不写引擎资源加载语法**：逐场演出剧本融合稿不引擎语法，不写引擎命令、配置、参数表与文件格式参数，只写引用、时机与意图。
- 台词保留 `02-Script/` 底本原文措辞（带上游定位），只整理与标注演出，不改写台词。
- **不把 `02-Script/` 正文复制进 `04-ScreenPlay/`**：`04-ScreenPlay/` 只写「底本 + 演出指示」融合稿，不复制纯正文另建同义文件。

## 硬门（默认前置，用户显式指令可覆盖）
**没有 `<作品名>/03-Asset/asset-index.md` 与 `<作品名>/03-Asset/asset-gap.md` 且未经用户确认之前，默认不开始逐场演出剧本（用户显式指令可覆盖）**。未满足硬门应停下询问，不预写逐场稿。这两份由 vn-asset-list（建骨架）与 vn-asset-make（补磁盘实际状态）协作生成，本预设只读、不改写、不另建副本。

## 进度应落磁盘
长流程落盘：进度应落磁盘，不只存在对话里；每轮只增不改地写入 `04-ScreenPlay/` 并在 README.md 追加一行。README.md 采用双区结构：A 区「当前状态」块 5 字段（当前预设 / 当前阶段 / 本轮子条目 / 状态 / 下一候选）就地更新，B 区「进度记录」只追加一行、永不改写或删除既有行；状态默认「待确认」，不自行置「已确认」。

## 常见错误（自检逐条对照）
| 错误 | 正确做法 |
|------|----------|
| 写了引擎命令/路径/扩展名 | 只写意图与 ID |
| 引用磁盘上不存在的 ID、差分名 | 走缺口流程或标 `pending`，禁止伪造 |
| 状态词自造 | 只用 8 词状态词表 |
| 引用了资产但不写状态 | ID 后紧跟状态 |
| 标注区与引用不一致 | 两边逐条对齐 |
| 改写了 `02-Script/` 台词 | 保留原文，意见写进标注区并请裁决 |
| 缺口只写在对话里没落盘 | 在融合稿标注区显式标注（不另写缺口文档） |
| 复制 `02-Script/` 纯正文进 04 | 只写融合稿 |
| 一次性写多份文档 | 一轮只写 1 个文件 |

## 只读与禁写
- 上游 `<作品名>/00-Bible/`、`<作品名>/01-Plan/`、`<作品名>/02-Script/`、`<作品名>/03-Asset/`（含 asset-index.md / asset-gap.md / generated/）与根级 `Direction.md`、`Specifications.md` 只读。
- 不创建计划外文档与计划外目录；**不一次性交付多份文档**；不预写 `<作品名>/05-Game/`；不编写多 Agent 协作文档、分工表、交接协议。

## 旧路径语境（不作为产出落点，仅迁移对照）
`00-设定/ 01-规划/ 02-系统/ 02-剧本/ 03-修订/ 04-资产/ 05-剧本/ 06-演出/ assets/ 规范-*.md / 剧情精述.md（根级）` 等旧路径**不作为产出落点**，只允许出现在「旧值 / 迁移 / 不 / 上游只读」语境：旧 `06-演出/draft-vN/sc001.md` → `04-ScreenPlay/draft-vN/sc001.md`、旧 `05-剧本/draft-vN/` → `02-Script/draft-vN/`（上游只读）、`assets/` → `03-Asset/generated/`、根级 `剧情精述.md` → `02-Script/剧情精述.md`（上游只读）、`规范-演出.md` → `Specifications.md`。不引用旧路径作为事实源。

## 单轮单条目
- **每轮只处理 1 个子条目**：一轮只定义/审阅 1 个格式条目或 1 份融合稿格式，由用户从候选清单中选定，不自主规划本阶段子任务。
- **不跨阶段**：不读写下游阶段目录、不创建下游文件、不在对话中替下游做设计；不做上游阶段的事。
- 只增不改：不改写上游只读文件；不一次性交付多份文档。

## 七步循环与 Check
- Read → Report → Confirm → Do → Check → Write → Stop。Read 显式读 `<作品名>/README.md`、`<作品名>/Specifications.md` 与根级 `Direction.md`，以及 `02-Script/` 底本、只读 asset-index.md / asset-gap.md、`04-ScreenPlay/` 已有产物；Confirm / Stop 两组常用选项可按需选用，不必互斥套用（见 `vn-gate` §2）。
- Check 按 `vn-continuity`：场次号连续、状态词合法、路径一致、无伪造资产、无引擎语法、进度落盘、未复制 02-Script 正文。
- Write 只写这一个文件（只增不改），就地更新 README.md A 区 5 字段 + 在 B 区追加一行（状态「待确认」）。

## 8 条核心原则
① 实际资产优先于资产列表（磁盘实际为准，asset-list.md 是需求文档，asset-index.md 只读）。② 不伪造资产路径、资产 ID、差分名。③ 不将就也不死板（缺口显式化，不凑合使用未确认资产，不擅自改写剧本）。④ 缺口显式化（以 `03-Asset/asset-gap.md` 为准，按 8 词状态词表在融合稿中标注引用，不默默绕过/另写缺口文档/改写资产缺口表）。⑤ 融合稿与引擎转写分离（不引擎语法、路径、扩展名、引擎资源加载语法）。⑥ 长流程落盘（进度应落磁盘，每轮只增不改写入 04-ScreenPlay/ 并在 README.md 追加一行）。⑦ 单 Agent 推进（不多 Agent 协作文档、分工表、交接协议）。⑧ 主动询问、确认后整理（存在疑问应主动询问，确认后才整理落盘，不凭空假设）。

## 8 词状态词表
只用 `available / generated / substitute / placeholder / missing / hard_missing / pending / listed_but_missing` 这 8 个词标注资产状态；不自造同义词、缩写或新状态词。

- **不跨阶段**
