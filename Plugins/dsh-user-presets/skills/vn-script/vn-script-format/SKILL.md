# 剧本正文格式、场景头与视点纪律（vn-script-format）

## 何时使用
- 每次撰写或改写 `02-Script/draft-vN/` 下剧本正文时。
- 每轮 Do 前按本 skill 的「场景起飞检查卡」完成锚点核对再下笔。

## 唯一落点 / 写死路径
- **正文落点写死 `02-Script/draft-vN/ch001.md`**：按章分文件，三位编号（`ch001.md`、`ch002.md` …，保证排序稳定）；分支段用后缀区分（**`ch001-2a`**、`ch001-2b`），跳转关系在选项处注明，分支编号按 `01-Plan/endings-and-flags.md`。本阶段唯一可写列为 `02-Script/`，**新落点默认 `02-Script/`**。
- **全局默认视点模式默认读 `Specifications.md`**（全局默认视点模式声明处），**不引用 `规范-剧本.md`** 或任何其它规范文件；场景头 `【视点：角色】`、起飞检查卡、多心声禁令默认保留。
- 场景表默认写 `02-Script/scene-list.md`，场次命名与编号按 `Specifications.md` ③节；不另建 `scene-map.md`（属 VN-演出剧本）。正文每完成一章或一次修订，应在同一子条目内同步更新 `02-Script/剧情精述.md`。
- 不裸 `~`；编号体系用 `-` 连接符。

### 不落点（旧值 / 不语境）
- 旧值 `02-剧本/`、`05-剧本/` 两套正文目录默认统一为 `02-Script/`，**不作为产出落点**、不再创建、不写入、不引用为事实源。
- 其余旧值见文末「旧值 / 迁移对照（不作为产出落点）」，不作为产出落点。

## 本轮批量（1~4 章不定）
- **一轮写 1~4 章，章数不定**：本轮实际写几章由本轮范围决定——用户已写明章数/范围时按用户指令；未写明时由 agent 依据 `01-Plan/chapter-structure.md` 的章节结构与本轮可用上下文，在 1~4 章内自主定一个章数并在 Report 里声明（例如「本轮 ch003 - ch005，共 3 章」），不必每轮都问「写几章」。用户显式指定的章数优先；超过 4 章时按宪法第 2 条由用户显式授权，否则本轮上限仍为 4 章。
- 一个子条目 = `02-Script/draft-vN/` 下 1 个章节文件（1 章正文 / 1 个分支段 / 1 次已拍板的局部修订），或 `02-Script/scene-list.md` 中 1 条场次记录，或 `02-Script/剧情精述.md` 中 1 章精述，或 `02-Script/Draft/` 下 1 份零散草稿；本轮可含 1~4 个同类子条目，各自独立写入、独立核查、独立在 `README.md` 记一行。
- 本轮的 1~4 章必须是 `chapter-structure.md` 中相邻的连续章（或同一章内连续的分支段），不跨过未写的章挑着写；每章动笔前各过一次「场景起飞检查卡」。Check 按 `vn-continuity` 逐个产物核查，不只抽第一个；Write 写本轮各章文件 + 每章强制同步项 + README A 区 5 字段 + B 区按本轮子条目数追加对应行数，状态置「待确认」。
- 「剧本正文每完成一章或一次修订，同步更新 `02-Script/剧情精述.md`、`02-Script/scene-list.md`」属每章的强制同步项，应在同一轮 Do → Check → Write 内随该章一起完成，不拆到下一轮、不另算一个子条目。
- `README.md` A 区「本轮子条目」登记本轮章号范围（如 `ch003 - ch005`），B 区「进度记录」本轮追加本轮章数对应的行数（一行一章），只追加、不改写或删除既有行；状态由用户在确认中明确认可后才置「已确认」，AI 不自行置位。
- 阶段切换 = 用户手动切换到对应预设且 README 状态=已确认；用户已在同一条消息里写明本轮范围或做法时视为已确认，不必重复提问（宪法第 2 条）。

## 有限创意主动性（2026-11-13 恢复）
- **上游已确认事实绝不松动**：`00-Bible/anchors.md`、`01-Plan/` 的章节结构 / 结局 / 分支 / FLAG 与角色档案「说话方式」仍是硬基准；发现上游缺漏、字段缺失或与正文冲突时，仍须停下并回指对应上游文档请用户裁决，不改写上游、不把新事实反向补录进上游、不新造 FLAG / 专有名词 / 设定。
- **仅当上游已确认骨架留白时允许有限提议**：若 `01-Plan/chapter-structure.md` 已给出本轮章的功能、节奏与冲突节点，但未规定具体对白、动作细节、场景内的小事件或桥段，且现有素材不足以支撑本段正文，可以主动给出 **2-3 个有差异的候选写法**（逐一说明依据、代价与收益），请用户拍板后再正式创作。候选只涉及「怎么写这场戏」，不涉及「改设定 / 改大纲 / 改结局 / 改分支条件 / 补上游事实」。
- **标注与落点**：候选一律明确标注「推测 / 待拍板」，只出现在对话或 `02-Script/Draft/` 零散草稿中，绝不混入 `02-Script/draft-vN/` 正式正文、`scene-list.md`、`剧情精述.md` 或 README 的已确认内容；用户拍板前不落正式文件。用户拍板后按选定候选写正文，并在 README B 区本轮进度行注明「本轮采用候选 N」。
- 不因本段放宽「上游只读」：候选讨论不授权写入 `00-Bible/` 与 `01-Plan/`；若用户想把候选升级为设定，须切换到上游预设处理。

## 共用纪律（真源见 vn-shared，本文不复述）
- 目录树与读写权限按 `vn-spec`（6 编号目录 + 3 根级文档；本预设唯一可写列 `02-Script/`，根级仅按双区结构维护 README.md）；命名与格式按 `vn-spec` §5；一致性核查按 `vn-continuity`（本轮各产物 + 直接上游已确认文件，锚点矩阵优先）；每轮流程与 README 双区状态机按 `vn-gate`（Read → Report → Confirm → Do → Check → Write → Stop，`ask_user_question` 只是默认确认手段、本轮不设固定末位工具调用）。
- 与三份 shared skill 措辞冲突时按 persona【指令裁决】第 4 条：`vn-gate`（流程）> `vn-spec`（目录与格式）> `vn-continuity`（核查），且以 persona 为准；阶段 skill 内不再重复目录白名单、上游只读清单、七步循环、旧值迁移表等整块模板。
- `02-Script/Draft/` 只进不出：零散草稿只写入，不读取为事实源、不参与连续性核查、不自动收编。旧值（`00-设定/` `01-规划/` `02-剧本/` `05-剧本/` `03-修订/` `06-演出/` `assets/` `规范-剧本.md` 等）一律不作为产出落点、不创建、不写入、不引用为事实源；旧值迁移对照见 bundle `README.md`。
- 正文只写台词、叙述与场景表，不写演出 cue / 大纲层概述 / 资产与实现层级内容；编号三位 `ch001`、分支 `ch001-2a`、连接符用 `-`、禁裸 `~`；以完整复合句为主、不写碎片段落；不用「稳稳接住 / 接住你」的比喻义。
- **按需最小加载**：每轮只加载本轮实际用到的 `vn-shared` 分项与本阶段 skill；不把 10 份 `vn-script` skill 一次性全读、不加载其它阶段 skill、不预先展开后续子条目模板。
## 动笔前判定
- 每次写正文前，先判定本段的文本类型（对白 / 叙述 / 内心独白 / 画外 / 演出指令 / 选项）与文风基调（对照 `00-Bible/style.md` 与 `00-Bible/characters/<角色名>.md` 的「说话方式」字段），并确定本场景的氛围基调与各出场角色的心情 / 唤醒度（低 / 中 / 高），据此选择对应写法。
- 判定所需信息不足时先向用户求证；素材不足以支撑本段内容时先给候选方案讨论、用户拍板后再正式创作；写新章节或关键场景前，先按「场景起飞检查卡」完成锚点核对再下笔。

## 三级视点模式（POV Configuration System）
本项目在 `Specifications.md` 中声明**全局默认视点模式**；单场戏可通过场景头显式交接视点。绝不使用「绝对不他人内心 / 绝对单一视角」之类一刀切死规则——视点纪律是动态模式配置，事实严密与艺术自由并重。

### 模式 1：单主角强沉浸模式（Strict Single POV）
- 全剧严格绑定单一主角；他人内心完全不可见；视线死角受人体物理法则约束（背后动静只能靠听觉、触感或他人事后转述感知）。场景头无需逐场标注视点（默认继承全局主视点）。

### 模式 2：场段交替轮换模式（Switching POV）
- 允许按章节或场景切换主导视点；视点归属于谁，谁即获得第一人称叙述与内心独白特权。每次交接应在场景头显式声明 `【视点：角色】`。

### 模式 3：电影化群像 / 上帝剪辑模式（Cinematic / Multi-Angle）
- 允许客观镜头描写空镜、全知叙述与幕间发生之事。客观过场用 `【幕间 / 客观视点】` 声明：无第一人称主角，采用摄影机客观镜头白描。

### 动态特权与限制转移（视点一旦交接，立即生效）
1. **特权转移**：声明 `【视点：角色】` 后，`角色（内心）：……` 立即合法且优先；旁白叙述中的第一人称「我」自动转指该角色；心理活动、嗅觉、触觉等全部感官以其身心感受为准。
2. **限制转移**：此时原主视点角色退行为外部观察对象，**不书写其内心独白**；其心情只能通过外在动作被当前视点角色观察。
3. **多心声禁令（No Simultaneous Mind-reading）**：**绝对不在同一个场景段落中同时出现两个角色的无声内心独白**，杜绝「神游视角漂移」。一个场景段落内，内心特权只有一份。

## 场景头视点声明语法（默认保留）
- 基础场景头：`## 场景 N · 地点 — 昼/夜/晨/昏`。同地点连续推进不重复写。
- 模式 2 交接视点：`## 场景 2 · 旧书店后廊 — 昼 【视点：夏天风】`（显式交接）。
- 模式 3 客观过场：`## 场景 3 · 老街尽头公用电话亭 — 夜 【幕间 / 客观视点】`。
- 未显式声明时，默认继承 `Specifications.md` 声明的全局默认主视点，**不引用 `规范-剧本.md`**。

## 场景起飞检查卡（Pre-flight Stamp）——动笔前强制执行（默认保留）
长篇写作中事实漂移的根源是上下文注意力稀释：在输出大篇幅正文前，先「打印并自检」一组关键实体元数据，注意力会被锚定在基准事实上。**每写一个新章节或关键场景前**，在草稿头部显式输出检查卡，逐项对照 `00-Bible/anchors.md` 与 `Specifications.md` 核对，核对无误后方可正式下笔：
```markdown
<!-- SCENE_PREFLIGHT_START -->
【场景起飞检查卡】
- 场景编号与时段：ch001 / Day 1 晨
- 场段主导视点：<角色>（严格物理听视死角，不可读取他人内心）
- 物理空间与动线：<按 00-Bible/anchors.md 空间拓扑核对>
- 登场角色与年龄：<按 00-Bible/anchors.md 年龄矩阵核对>
- 核心称谓核对：<按 00-Bible/anchors.md 称谓网格三层解耦核对>
- 关键资产状态：<按 00-Bible/anchors.md 核心资产与体态状态机核对>
<!-- SCENE_PREFLIGHT_END -->
```
检查卡字段与 `00-Bible/anchors.md` 四节一一对应；核对中发现矛盾先回指 `00-Bible/anchors.md` 与用户裁决，不带病下笔，不自创设定。

## 通用版面与剧本结构
- 章内按段落推进，每个段落是一次「文本推进」单位，一般 1-3 个短句；以完整、连贯且包含因果关系的复合句为主，不碎片段落、不单句堆砌、不用短句清单代替叙述（见 writing-craft）。
- 旁白与叙述：不加前缀的段落。对白：`角色名：台词`，每行一位角色，对白不加引号，长对白分段写；说话人标签与旁白 / 对白中的称呼按 `00-Bible/anchors.md` 称谓网格三层解耦，互不混淆。
- 内心独白：`角色名（内心）：……`；画外音 / 回忆声：`角色名（画外）：……`；内心独白受视点模式约束。
- 演出指令单独成行，用【】标出，只写需求、不写引擎实现；默认克制标注，只在画面、声音、情绪确实需要变化时标注。**不把演出 / 资产 / 实现层级内容写进正文**：不写镜头调度、演出分镜、资产规格、生成提示词、实现规格、数值表等下游层级内容。
- 选项与分支：`【选项】` 下逐条 `1. 选项文本 → 跳转 ch001-2a`；选项文本默认玩家视角，若采用主角口吻先与用户确认口径；FLAG 与变量变化在选项或段落末尾标注 `FLAG：xxx=1`，正文只引用不新造，以 `01-Plan/endings-and-flags.md` 为唯一事实源。
- 不裸 `~`；日期范围写 `6月10日 - 6月11日`，编号区间写 `Day 1 - Day 2`、`ch001 - ch005`，统一采用半角减号配空格或短横线（`-`）代替。
- 叙述只写可见可闻、且可被演出表达的内容；动作与状态用具体行为表达（「她攥紧衣角，指节发白」而不是「她很紧张」）；氛围与唤醒度应与对白、旁白、独白与演出指令一致并随其变化；不全场死水般的平静语气。

## 交付
- 正文按章写入 `02-Script/draft-vN/ch001.md`（三位编号，分支后缀 `ch001-2a`）；**不**写入 `02-剧本/`、`05-剧本/` 或任何其它目录。
- 每写完一批段落，更新 `02-Script/scene-list.md` 段落 / 场景表；每完成一章或一次修订，应在同一子条目内同步更新 `02-Script/剧情精述.md`。
- 新场景 / 新地点默认回指 `00-Bible/` 上游空间物理事实，不在正文里新建设定、不补写上游文件。

## 执行要点
