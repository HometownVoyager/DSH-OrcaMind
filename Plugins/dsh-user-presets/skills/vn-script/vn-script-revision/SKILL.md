# 已确认章节局部修订（vn-script-revision）

## 何时使用
- 用户要求「改剧本」「改这一章 / 这段」「这稿太散」时。
- 用户从候选清单中选定「对已确认 `02-Script/draft-vN/ch001.md` 的一次局部修订」子条目时。
- 完成一稿后需要先给修改方案、用户确认后再执行时。

## 唯一落点 / 写死路径
- **修订只作用于 `02-Script/draft-vN/ch001.md`（含 `ch001-2a` 分支段）**：三位编号、分支后缀 `ch001-2a` 按 `01-Plan/endings-and-flags.md` 编号。本阶段唯一可写列为 `02-Script/`，**新落点默认 `02-Script/`**。
- **修订后应同步 `02-Script/剧情精述.md`**：该同步项属同一子条目的强制同步项，应在同一轮 Do → Check → Write 内完成，不拆成下一轮、不另算一个子条目；精述与修订后正文不一致时，以修订后正文与已确认内容为准并当场修正精述。
- **修订记录并入 `README.md` 阶段确认记录**（B 区进度记录），取消独立修订目录。
- 修订范围只限用户已明确确认的局部（视点、台词或场景头等），不顺带改写设定、大纲或下游内容；发现上游缺口时停下并用 `ask_user_question` 回指对应上游文档，由用户拍板，不自创设定、不改写上游事实。

### 不落点（旧值 / 不语境）
- **不写 `03-修订/revision-log.md`、`continuity-log.md`**，不另建同义修订日志，取消独立修订目录；默认并入 `README.md` 阶段确认记录。
- 其余旧值见文末「旧值 / 迁移对照（不作为产出落点）」，不作为产出落点。

## 本轮批量（1~4 章不定）
- **一轮写 1~4 章，章数不定**：本轮实际写几章由本轮范围决定——用户已写明章数/范围时按用户指令；未写明时由 agent 依据 `01-Plan/chapter-structure.md` 的章节结构与本轮可用上下文，在 1~4 章内自主定一个章数并在 Report 里声明（例如「本轮 ch003 - ch005，共 3 章」），不必每轮都问「写几章」。用户显式指定的章数优先；超过 4 章时按宪法第 2 条由用户显式授权，否则本轮上限仍为 4 章。
- 一个子条目 = `02-Script/draft-vN/` 下 1 个章节文件（1 章正文 / 1 个分支段 / 1 次已拍板的局部修订），或 `02-Script/scene-list.md` 中 1 条场次记录，或 `02-Script/剧情精述.md` 中 1 章精述，或 `02-Script/Draft/` 下 1 份零散草稿；本轮可含 1~4 个同类子条目，各自独立写入、独立核查、独立在 `README.md` 记一行。
- 本轮的 1~4 章必须是 `chapter-structure.md` 中相邻的连续章（或同一章内连续的分支段），不跨过未写的章挑着写；每章动笔前各过一次「场景起飞检查卡」。Check 按 `vn-continuity` 逐个产物核查，不只抽第一个；Write 写本轮各章文件 + 每章强制同步项 + README A 区 5 字段 + B 区按本轮子条目数追加对应行数，状态置「待确认」。
- 「剧本正文每完成一章或一次修订，同步更新 `02-Script/剧情精述.md`、`02-Script/scene-list.md`」属每章的强制同步项，应在同一轮 Do → Check → Write 内随该章一起完成，不拆到下一轮、不另算一个子条目。
- `README.md` A 区「本轮子条目」登记本轮章号范围（如 `ch003 - ch005`），B 区「进度记录」本轮追加本轮章数对应的行数（一行一章），只追加、不改写或删除既有行；状态由用户在确认中明确认可后才置「已确认」，AI 不自行置位。
- 阶段切换 = 用户手动切换到对应预设且 README 状态=已确认；用户已在同一条消息里写明本轮范围或做法时视为已确认，不必重复提问（宪法第 2 条）。

## 有限创意主动性（2026-11-13 恢复）
- **上游已确认事实绝不松动**：`00-Bible/anchors.md`、`01-Plan/` 的章节结构 / 结局 / 分支 / FLAG 与角色档案「说话方式」仍是硬基准；发现上游缺漏、字段缺失或与正文冲突时，仍须停下并回指对应上游文档请用户裁决，不改写上游、不把新事实反向补录进上游、不新造 FLAG / 专有名词 / 设定。
- **仅当上游已确认骨架留白时允许有限提议**：若 `01-Plan/chapter-structure.md` 已给出本轮章的功能、节奏与冲突节点，但未规定具体对白、动作细节、场景内的小事件或桥段，且现有素材不足以支撑本段正文，可以主动给出 **2-3 个有差异的候选写法**（逐一说明依据、代价与收益），请用户拍板后再正式创作。候选只涉及「怎么写这场戏」，不涉及「改设定 / 改大纲 / 改结局 / 改分支条件 / 补上游事实」。
- **标注与落点**：候选一律明确标注「推测 / 待拍板」，只出现在对话或 `02-Script/Draft/` 零散草稿中，绝不混入 `02-Script/draft-vN/` 正式正文、`scene-list.md`、`剧情精述.md` 或 README 的已确认内容；用户拍板前不落正式文件。用户拍板后按选定候选写正文，并在 README B 区本轮进度行注明「本轮采用候选 N」。
- 不因本段放宽「上游只读」：候选讨论不授权写入 `00-Bible/` 与 `01-Plan/`；若用户想把候选升级为设定，须切换到上游预设处理。

## 共用纪律（真源见 vn-shared，本文不复述）
- 目录树与读写权限按 `vn-spec`（6 编号目录 + 3 根级文档；本预设唯一可写列 `02-Script/`，根级仅按双区结构维护 README.md）；命名与格式按 `vn-spec` §5；一致性核查按 `vn-continuity`（本轮各产物 + 直接上游已确认文件，锚点矩阵优先）；每轮流程与 README 双区状态机按 `vn-gate`（Read → Report → Confirm → Do → Check → Write → Stop，`ask_user_question` 只是默认确认手段、本轮不设固定末位工具调用）。
- 与三份 shared skill 措辞冲突时按 persona【指令裁决】第 4 条：`vn-gate`（流程）> `vn-spec`（目录与格式）> `vn-continuity`（核查），且以 persona 为准；阶段 skill 内不再重复目录白名单、上游只读清单、七步循环、旧值迁移表等整块模板。
- `02-Script/Draft/` 只进不出：零散草稿只写入，不读取为事实源、不参与连续性核查、不自动收编。旧值（`00-设定/` `01-规划/` `02-剧本/` `05-剧本/` `03-修订/` `06-演出/` `assets/` `规范-剧本.md` 等）一律不作为产出落点、不创建、不写入、不引用为事实源；旧值迁移对照见 bundle `README.md`。
- 正文只写台词、叙述与场景表，不写演出 cue / 大纲层概述 / 资产与实现层级内容；编号三位 `ch001`、分支 `ch001-2a`、连接符用 `-`、禁裸 `~`；以完整复合句为主、不写碎片段落；不用「稳稳接住 / 接住你」的比喻义。
- **按需最小加载**：每轮只加载本轮实际用到的 `vn-shared` 分项与本阶段 skill；不把 10 份 `vn-script` skill 一次性全读、不加载其它阶段 skill、不预先展开后续子条目模板。
## 修改轮次（每轮只做一件事，沿用 screenplay-writing 全链并改造）
1. 结构轮：本轮修订是否与 `01-Plan/chapter-structure.md` 章节结构、选项与 `01-Plan/endings-and-flags.md` 结局 / 分支 / FLAG 条件一致（只读核对，不改写上游）。
2. 段落轮：逐段问「这段推进情节、揭示人物还是埋设信息？」——都不做的删掉或合并；检查段落衔接、FLAG 变化与时间连续性（调用 continuity，先对 `00-Bible/anchors.md` 做锚点核验）。
3. 对白轮：调用 character-voice 逐行检查，删掉直说与解释性对白；说话人标签与称呼对照 `00-Bible/anchors.md` 称谓网格三层口径。
4. 格式轮：按 vn-script-format 校对场景头（含 `【视点：角色】` 视点声明）、起飞检查卡、多心声禁令、选项、FLAG 标注；对照 `00-Bible/anchors.md` 逐章核对年龄、称谓、信物与体态状态、空间拓扑与动线；检查范围连接符是否用了裸 `~`（统一改为 `-` 或 `- `）。
5. 定稿轮：错别字、标点、排版；不裸 `~`。

## 分支修订的额外检查
- 改分支节点时，检查下游所有分支段落、FLAG 与结局条件是否仍然一致，只读对照 `01-Plan/endings-and-flags.md`（唯一事实源），不另建 `endings.md`、`systems.md` 或任何同义文件。
- 合并或删除分支时，检查 `02-Script/scene-list.md` 的跳转关系并同步更新；分支后缀 `ch001-2a` 按 `01-Plan/endings-and-flags.md` 编号。

## 稿本管理
- 每稿一个目录：`draft-v1`、`draft-v2`……新稿从上一稿复制，旧稿保留；默认位于 `02-Script/draft-vN/` 下。
- 修改稿首行注明「第 n 稿 · 日期 · 修改范围」；用目录区分版本，用户需要再引入行业惯例（颜色稿 / 修订标记）。
- 修订记录（删 / 改 / 新增、理由、遗留待决问题、复盘）默认并入 `README.md` 阶段确认记录，不另建独立修订日志。

## 执行要点
- 只写 `02-Script/` 本列、根级按双区结构维护 README.md；不跨阶段写入、不创建白名单外文件、不自行置「已确认」。其余按上文「共用纪律」与「本轮批量」执行，不复述。
