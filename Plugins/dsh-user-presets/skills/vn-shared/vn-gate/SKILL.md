# vn-gate · 默认每轮流程与 README 状态机

本 skill 定义 VN 七预设共享的**默认工作节奏**。它不是绝对门禁：各预设 persona 的【指令裁决】段优先级最高，用户显式指令可覆盖本 skill 的一切流程与确认要求。规则措辞以「默认」为主，不因未使用绝对化措辞而降低效力。

## 0. 与宪法的关系（先读）

- 硬红线只有三条，写在每个预设 persona 的【指令裁决】第 1 条：① 不跨阶段写入 ② 不创建白名单外文件 ③ 不自行把 README 状态置「已确认」。
- 本 skill 其余内容（七步顺序、单轮单条目、提问与确认、A/B 组选项、状态机）均为**默认节奏**，用户指令与之冲突时以用户为准；用户已在同一条消息里写明范围或做法时视为已确认。
- 三份共享 skill 冲突时按 `vn-gate`（流程）> `vn-spec`（目录与格式）> `vn-continuity`（核查）执行；都不与宪法冲突。
- 各阶段 skill 里重复出现的目录白名单 / 七步循环 / README 状态机 / 核查范围只是便于离线阅读的副本，与 `vn-shared` 三份 SKILL.md 冲突时以 `vn-shared` 为准，不逐条复述比对。
- 历史文档（施工文档、旧预设、旧七步 `Read→Report→Plan→Do→Check→Write→Ask`、已 `disabled` 的预设）**不是现行规则来源**，不据此溯源或核验本轮行为。

## 1. 默认七步循环

```
Read → Report → Confirm → Do → Check → Write → Stop
```

| 步 | 默认动作 |
|---|---|
| **Read** | 按固定顺序：① 读 `README.md` 状态机（校验「当前预设」是否匹配自己，见 §4）② 首轮另显式用文件工具读一次根级 `Specifications.md` 与 `Direction.md`（后续轮按已读内容执行，不复读）③ 读本阶段已有产物（上游只读）。`Specifications.md` / `README.md` / `AGENTS.md` 由 `agent-instructions` 自动注入，不算显式文件工具读。 |
| **Report** | 报「当前阶段 / 已完成 key / 本轮待办子条目」；可附 ≤3 个下一候选标题，只列标题、不展开内容。 |
| **Confirm** | 默认用 `ask_user_question` 请用户确认「本轮就做这一个」，或改选候选；用户已在同一条消息里写明范围时跳过提问，直接进入 Do。 |
| **Do** | 只做被确认的子条目（本轮 1~4 个、章数不定），产出到本阶段「写」列目录。 |
| **Check** | 按 `vn-continuity` 逐个核查本轮各产物，按 `vn-spec` 校验目录与格式。 |
| **Write** | 写本轮各子条目的文件 + 就地更新 `README.md` A 区「当前状态」5 字段 + B 区「进度记录」按本轮子条目数追加对应行数（状态置「待确认」）。 |
| **Stop** | 停下，报告本轮结果与下一候选标题，等用户下一轮指令。 |

**默认每轮 1~4 个子条目、章数不定**：`vn-script`（VN-剧情写作）一轮写 1~4 章连续正文，其余 6 个 VN 预设默认 1 个子条目；实际数量由本轮范围决定——用户写明范围时按用户指令，未写明时由 agent 在本阶段上限内自主声明并在 Report 里报出，不必每轮追问。用户显式授权可超出默认上限（宪法第 2 条）。各子条目仍各自独立写入、独立核查、独立在 README B 区记一行。

## 2. 收尾与提问

- Confirm 与 Stop 可用 `ask_user_question`，但**本轮的工具调用顺序没有「最后一个必须是某个工具」的硬不变量**；报告、交付（`present`）、README 状态登记都是正常步骤，按实际需要安排。
- 「README 状态登记」与「成果交付」的时点：默认在本轮 Write 之后、下一轮 Read 之前完成（可在本轮 Stop 之前完成）。本轮不设固定末位工具调用，因此两者都不属于「提问之后禁止的动作」，不存在时序矛盾。
- 两组常用选项（可按需选用，不必互斥套用）：
  - Confirm 组：就做这一个 / 换一个子条目 / 先不做，停下询问。
  - Stop 组：认可本轮成果 / 换一个子条目重做 / 本阶段已确认，进入下一预设。
- 提问具体、简洁、给可选方案；存在疑问、缺项、冲突或不确定时默认求证，由用户拍板，不凭空假设。

## 3. 候选清单的边界（消除「禁止规划后续」与「列下一候选」的歧义）

- **允许**：列出下一候选子条目的**标题**，最多 3 个，不展开内容、不写字段、不写草案、不写设计建议。这不算「规划 / 预写 / 预告后续子条目」。
- **算越界**：为后续子条目写字段、模板、占位内容、候选方案或「以后可以……」的展开；替下游阶段做设计。
- `下一候选` 字段登记的是上述「只列标题」的清单，无后续候选时记「无」。

## 4. README 双区状态机

`README.md` 是唯一进度 / 阶段状态机（每轮先读）。A 区「当前状态」5 字段：`当前预设` / `当前阶段` / `本轮子条目` / `状态` / `下一候选`。

| 字段 | 定义 |
|---|---|
| `当前预设` | 当前应工作的 `VN-*` 预设 id；用户手动切换预设后，由新预设首轮 Read 就地登记，AI 不代改。 |
| `当前阶段` | 该预设对应阶段名。 |
| `本轮子条目` | 本轮被用户确认处理的子条目范围（如 `ch003 - ch005`；单条目时写该条目）。 |
| `状态` | 三值：`进行中` \| `待确认` \| `已确认`。 |
| `下一候选` | 下一轮候选子条目标题清单，只列标题、不展开；无后续候选记「无」。 |

状态转换（默认）：
```
进行中 --Write 完成--> 待确认
待确认 --用户明确确认--> 已确认
已确认 --用户切换/确认下一轮--> 进行中
```

- `已确认` 默认由用户在确认中给出后，AI 代为登记；AI 不自行置位。用户显式授权时按其授权处理。
- B 区「进度记录」只追加、不改写或删除既有行。裁决结论（见 `vn-continuity` §5）追加一行记入。
- 阶段切换 = 用户手动切换到对应预设 + README `状态=已确认`（用户显式指令覆盖时以指令为准）。
- **首轮「当前预设」校验三分支**（全章唯一判定）：① 匹配自己 → 继续；② 合法交接（紧邻上游预设 id 且 `状态=已确认`）→ 首轮就地登记为自己的 id 并追加一行交接登记后继续；③ 其余不匹配 → 停下询问、不动文件。

## 5. 跨阶段边界

- 每个预设只写自己那一列目录；上游只读，下游默认不读、不写、不创建、不在对话中替其做设计。
- `vn-continuity` 的核查范围以本轮各产物及其**直接上游已确认文件**为限，不探测下游、不做全链全量体检（见该文件 §2）。
- 锁 1 由配置保证：`customSkillDirs` 只挂 `vn-shared` 与本阶段 skill，物理上看不到下一阶段 skill。
- 上游发现缺漏时停下询问，不回写、不补全。

## 6. 越界时的纠正

发现自己越界（跨阶段写入、创建计划外文件、自行置「已确认」、把上游改了等）：

1. 停下当前动作，不再发起新的写操作。
2. 用 `ask_user_question` 报告越界动作、涉及文件、影响与当前 README 状态，不淡化。
3. 不自行删除 / 覆盖 / 改写已越界写出的文件来「恢复原状」，不自行改回 README。
4. 由用户裁决「保留并补确认 / 撤销（须用户明确指令）/ 换子条目重来」；裁决按 `vn-continuity` §5 追加一行记入 B 区，之后开始新一轮。
5. 若越界动作本身是用户显式指令要求的，按宪法第 3 条处理（一句话点明冲突 + 二选一），不反复自辩。
