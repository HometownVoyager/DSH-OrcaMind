# 实际资产盘点（staging-asset-audit）

## 何时使用
- 演出设计开工第一步：尚未建立 `06-演出/资产索引.md` 时。
- 用户新增、替换或删除资产文件之后。
- 每轮工作中需要确认某个资产是否真的存在时（随时可做的局部核对）。
- 交付验收之前，确认索引与磁盘一致。

## 第一原则：实际文件优先
`04-资产/asset-list.md` 与 `04-资产/notes/` 是**需求文档**，记录「这部作品需要哪些资产」；`assets/` 是**库存**，记录「现在手上有什么」。两者不一致是常态，不是异常。任何资产是否可用，一律以磁盘上的实际文件为准；列表里登记了而磁盘上没有的，就是缺口（`listed_but_missing`），不是可用资产。

禁止凭列表推断资产存在，也禁止在索引里写入没有实际文件对应的条目——除非该条目的状态明确是 `generated`（由你生成并落盘）或 `placeholder`。

## 扫描规则
1. 从项目资产根目录开始枚举（默认 `assets/`；项目另有约定时用 `总体说明.md` 登记的路径）。
2. 分类按子目录判定，目录缺失或结构不同时按扩展名推定：
   - `bg/` 背景 ｜ `sprite/` 立绘 ｜ `cg/` 事件 CG ｜ `bgm/` 音乐 ｜ `sfx/` 音效 ｜ `script/` 文本类资产（含无演出剧本）｜ `ui/` 界面素材。
   - 图片：`.png .jpg .jpeg .webp .psd .kra .aseprite`；音频：`.ogg .mp3 .wav .flac .m4a`；文本：`.md .txt .json .csv .yaml`。
3. 逐个文件读取：文件名、相对路径、扩展名、体积；能读到尺寸或时长的就读，读不到就留空并标「未探测」。
4. 立绘差分按文件名的后缀族归组（如 `yuri_uniform_normal.png`、`yuri_uniform_worried.png` 归为同一立绘的两档表情），在备注里写出该立绘实际拥有的差分清单——这份清单是后续演出设计能引用什么表情的唯一依据。
5. 只读取与登记，**不搬动、不改名、不转换**任何资产文件。

## 资产 ID 约定
索引中为每件资产分配一个稳定 ID，供中间稿引用。ID 用大写下划线，前缀表分类：

| 前缀 | 分类 | 示例 |
|------|------|------|
| `BG_` | 背景 | `BG_ROOFTOP_DUSK` |
| `SP_` | 立绘（含差分后缀） | `SP_YURI_UNIFORM`、`SP_YURI_UNIFORM_WORRIED` |
| `CG_` | 事件 CG | `CG_YURI_ROOFTOP` |
| `BGM_` | 音乐 | `BGM_TENSE_LOW` |
| `SFX_` | 音效 | `SFX_DOOR_OPEN` |
| `UI_` | 界面素材 | `UI_DIALOG_FRAME` |
| `SCRIPT_` | 文本类资产 | `SCRIPT_CH003_NOSTAGE` |

分配纪律：
- 项目或上游已有 ID 体系时沿用上游 ID，不要另起一套。
- 文件已经带有可用的命名习惯时，优先从文件名派生 ID 而非重新发明。
- ID 一经分配即稳定，后续不要因为改名而漂移；确需变更时同步更新全部引用并记入裁决记录。
- **不得编造 ID**：磁盘上没有、也没有由你生成的资产，不配 ID。

## 资产索引模板（06-演出/资产索引.md）

```markdown
# 实际资产索引

- 扫描根目录：assets/
- 最近扫描：<日期>
- 统计：available <n> ｜ generated <n> ｜ substitute <n> ｜ placeholder <n> ｜ 其他见 资产缺口.md

## 背景
| 资产 ID | 分类 | 名称 | 文件位置 | 规格 | 状态 | 备注 |
|---------|------|------|----------|------|------|------|
| `BG_ROOFTOP_DUSK` | 背景 | 天台·黄昏 | assets/bg/rooftop_dusk.png | 1920×1080 | available | — |

## 立绘
| 资产 ID | 角色 | 服饰 | 表情差分 | 文件位置 | 状态 | 备注 |
|---------|------|------|----------|----------|------|------|

## 事件 CG
| 资产 ID | 名称 | 文件位置 | 规格 | 状态 | 备注 |
|---------|------|----------|------|------|------|

## 音乐
| 资产 ID | 曲名 | 文件位置 | 时长 | 情绪功能 | 状态 | 备注 |
|---------|------|----------|------|----------|------|------|

## 音效
| 资产 ID | 名称 | 文件位置 | 时长 | 触发情境 | 状态 | 备注 |
|---------|------|----------|------|----------|------|------|

| 资产 ID | 名称 | 文件位置 | 状态 | 生成依据 | 备注 |
|---------|------|----------|------|----------|------|
```

分类下无任何条目时保留小节并写「无」，不要删掉小节——空小节本身就是信息（该分类零库存）。

## 状态判定流程
对每件资产依次判定：

1. 磁盘上能读到文件，且与需求相符 → `available`。
2. 文件存在但明确是过渡品（命名含 `temp`/`wip`，或用户声明是临时件）→ `placeholder`。
3. 文件存在但与需求有差异（尺寸不符、差分不全、风格不符），且用户已确认以它顶替 → `substitute`（备注写真差异）。
4. 文件由你生成并落盘（目前仅文本类，如无演出剧本）→ `generated`（备注写生成依据与日期）。
5. 需求存在、磁盘没有，但有替代或降级路径 → 不进本索引，记入 `资产缺口.md` 并标 `missing`。
6. 需求存在、磁盘没有，且对应场次无法设计 → 记入 `资产缺口.md` 并标 `hard_missing`。
7. 已识别但用户尚未裁决 → `pending`，同时写入 `资产缺口.md` 的待裁决行。

索引里只登记「手上真有的东西」与它们的实际状态；「缺的东西」统一归 `资产缺口.md`，两者不要混写，避免同一件事两处记、两处不一致。

## 核对纪律
- 每次报告中给出统计数字（各分类几件、各状态几件），让用户一眼看出库存规模。
- 索引与磁盘不一致时，以磁盘为准并当场修正索引，同时在对话中说明修正了什么。
- 发现文件被删除或改名导致已有中间稿引用悬空时，立即报告并列入缺口，不得静默忽略。

## 执行步骤
1. 定位资产根目录（默认 `assets/`，以 `总体说明.md` 登记为准）。
2. 枚举文件，按分类与差分族整理。
3. 逐件分配 ID、读取规格、判定状态。
4. 写入或更新 `06-演出/资产索引.md`，更新统计行与扫描日期。
5. 把发现的缺口移交 `staging-gap-triage` 处理，并在对话中报告盘点结果。
