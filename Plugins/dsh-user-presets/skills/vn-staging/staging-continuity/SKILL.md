# 演出一致性核查（staging-continuity）

## 何时使用
- 每轮产出落盘之前（与七步循环的 Check 步对应）。
- 定稿某一稿次或交付整套中间稿之前。
- 上游剧本或资产发生变更之后，需要判断哪些场次受影响时。
- 用户提出「检查一下有没有前后矛盾」时。

## 五个核查维度

| 维度 | 比对对象 | 要回答的问题 |
|------|----------|--------------|
| 覆盖性 | 演出稿 ↔ 上游剧本 | 上游每一章、每一段是否都有归属场次，有没有漏演或多演 |
| 对白一致性 | 演出稿 ↔ 上游剧本 | 引用的台词是否与上游原文一致，有没有被改写、删减或错位 |
| 引用一致性 | 演出稿 ↔ 资产索引 | 每一个 ID 是否真实存在于索引，状态是否与索引一致 |
| 标注一致性 | 演出稿 ↔ 资产缺口 | 非 `available` 的引用是否都有标注条目，标注是否与缺口表状态一致 |
| 跨场连续性 | 场次稿之间 | 立绘站位、服饰、时间推进、背景沿用、情绪曲线是否连贯 |

## 逐维核查清单

### 覆盖性
- [ ] 上游剧本的章-段编号逐一列出，每一段都能指到某个场次。
- [ ] 没有凭空新增的场次或剧情；演出设计不产生新情节。
- [ ] 拆分与合并过的场次在 `scene-map.md` 中有去向记录，无悬空编号。

### 对白一致性
- [ ] 台词引用带上游定位（章-段-序号），定位可回查。
- [ ] 台词文本与上游逐字一致；确需调整时已在标注区标明并取得裁决。
- [ ] 台词的先后顺序与上游一致；因演出需要调整顺序时已显式说明。

### 引用一致性
- [ ] 稿中每个 ID 都能在 `资产索引.md` 中查到。
- [ ] 稿中状态与索引中的状态一致；不一致时以索引（磁盘事实）为准并修正稿件。
- [ ] 立绘差分引用确实存在于该立绘的实际差分清单中。
- [ ] 没有路径、扩展名或引擎语法混入。

### 标注一致性
- [ ] 每个非 `available` 引用都有对应的标注条目。
- [ ] 标注条目的处理方案与状态（待裁决／已裁决 + 日期）与 `资产缺口.md` 一致。
- [ ] `placeholder` 条目明确写了「验收前必须替换」。

### 跨场连续性
- [ ] 角色站位在相邻场次之间合理衔接（上场在右、下场突然在左需有调度说明）。
- [ ] 服饰与时间推进一致（黄昏场到夜晚场要有时段变化依据）。
- [ ] 背景沿用写明来源场次，不出现「同一地点两种描述」。
- [ ] 情绪曲线无断裂：上一场收在何处，这一场从哪里起，能连起来。
- [ ] `scene-map.md` 的场次表与各场稿的实际内容一致。

### 上游基准事实核查（anchors 优先）
- [ ] 上游项目存在 `00-设定/anchors.md` 时，先读它：场次稿涉及的年龄与关键节点、称谓三层口径（Speaker ID/旁白称谓/对白呼告）、信物与体态状态、空间拓扑与动线逐项对照锚点，再进入五维核查。
- [ ] 上游缺 anchors.md 时，按五维核查照常进行，并在交付报告中提示上游补建基准事实层（不代为新建上游文件）。
- [ ] 场次稿中发现的事实类矛盾（年龄、称谓、信物与体态状态、空间拓扑与动线）一律视为上游内容冲突，走下方冲突处理第 4 条，不得自行改写上游。

## 冲突处理
1. 冲突当场记录：冲突事项、涉及场次与文档、两侧原文、判定。
2. 判定事实源优先级：**磁盘实际资产 > 资产索引 > 上游已确认内容 > 本模式产出**。
3. 属于本模式产出的错误（引用错 ID、状态写错、站位矛盾）→ 直接修正，并在报告中说明改了什么。
4. 属于上游内容的冲突（剧本自相矛盾、需求与设定不符）→ **不得自行改写上游**，列出冲突并请用户裁决。
5. 属于资产现实的冲突（资产缺失导致某场无法按原设计演出）→ 移交 `staging-gap-triage` 走缺口流程。
6. 全部判定写入 `06-演出/资产缺口.md` 的裁决记录或项目既有的 `03-修订/continuity-log.md`（上游已有该文件时沿用，不新建第二份）。

## 执行步骤
1. 确定核查范围：本轮改动的场次，以及所有引用了变更资产的场次。
2. 按五个维度逐项过清单，逐条留痕（通过/不通过/待裁决）。
3. 修可自决的，记需裁决的，移交属缺口的。
4. 在报告中给出核查摘要：查了什么范围、发现几处问题、如何处理。
5. 更新 `制作计划.md` 的场次状态与 README 的进度记录。

## 注意事项
- 核查要真的去读文件比对，不要凭印象勾选清单；判定必须基于读到的内容。
- 核查发现的问题优先在本轮内解决；确实需要用户裁决的，集中提出而不是逐个打断。
- 只核查本轮范围时，明确说明未覆盖哪些场次，不暗示已全篇检查过。
- 早期核查可以抽查，交付前的核查必须逐场覆盖。
