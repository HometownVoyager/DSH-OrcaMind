# 视觉演出设计（staging-direction）

## 何时使用
- 把上游剧本切分为可演出的场次时。
- 为某一场戏设计立绘调度、背景切换、CG 与视觉转场时。
- 复查既有场次稿的演出密度与画面合理性时。

## 分场规则
1. 场次边界一般落在：地点变化、时间跳变、视角或叙述者切换、演出规模明显变化（如进入 CG 段）之处。
2. 每场戏必须有明确且单一的剧情功能（推进情节 / 揭示人物 / 埋设信息）。一场戏承担两件事以上时，考虑拆场；一场戏什么都不承担时，考虑与相邻场次合并，并在报告里说明理由。
3. 场次编号三位递增（`SC-001`），一经分配不复用；拆分与合并产生的新编号顺延，旧编号在 `scene-map.md` 中标注去向，避免悬空引用。
4. 每场戏都要登记与上游剧本的对应关系（章-段），这是后续连续性核查的主键。
5. 场次切分以自然演出节奏为准：读起来一口气演完的段落不要硬切成两场。

## 立绘调度

### 站位体系
立绘横向站位统一用五档描述，全项目一致：

| 站位 | 含义 |
|------|------|
| 左外 | 贴近左边缘，通常用于次要角色或即将退场者 |
| 左 | 画面左三分之一 |
| 中 | 画面正中，用于单人独白或对峙焦点 |
| 右 | 画面右三分之一 |
| 右外 | 贴近右边缘 |

需要更细致的位置时（如两人并肩、三人错落），在站位后补一句自然语言说明（「左，略靠中线，与右位的悠里形成对望」），不要自创第六档编号。

### 入场、移动与退场
- 入场要写清：时机（在哪句台词或哪个动作之前/同时/之后）、方向（自左/自右/自画面深处）、是否带位移、入场时的表情与服饰。
- 移动要写清：起点、终点、触发时机、速度感（缓步/急促/瞬间切入）。移动通常与台词或音效同步，写明与哪一句同步。
- 退场要写清：方向、是否淡出、退场后画面是否留空镜，以及退场是否伴随音效。
- 三人以上同框时，明确谁在中轴、谁是陪衬，避免所有人均分画面导致焦点涣散。

### 表情、动作与服饰差分
- 表情只能引用 `资产索引.md` 中该立绘**实际拥有**的差分；索引里没有的表情，按 `staging-gap-triage` 走缺口流程，不得编造差分名。
- 表情切换要写切换时机：通常在台词前、台词中段或台词后，不同时机表达不同含义（提前切换显得预料之中，延后切换显得反应滞后），写清意图。
- 动作分两类：一类由差分承载（如「抱臂」立绘），只能引用实际差分；一类由演出描述承载（如「微微侧头」），用自然语言写，但要意识到它可能需要额外素材，不确定时标注为待确认。
- 服饰切换必须写明切换点与理由（换场、时间推进、剧情事件）；同场次内若无剧情理由不要换装。

## 背景与 CG
- 背景切换写清时机与过渡方式（直切/淡入淡出/黑场过渡等）；同一背景在两场之间不切换时，也要在稿中说明「沿用 SC-00X 背景」，避免读者以为漏写。
- 背景可以有时段与天气变体（同地点的黄昏/夜晚/雨天），一律作为独立资产引用，不得用同一 ID 含糊带过。
- CG 插入点要写清：触发时机（哪句台词或哪个动作）、CG 退出后的画面状态（回到立绘/回到背景/转场）、以及该 CG 是否为一次性或可复用。
- CG 缺失时按缺口流程处理，降级方案（立绘 + 背景 + 音效 + 停顿）要写进中间稿标注区，并说明张力损失在哪。

## 视觉转场
转场用自然语言描述意图，不写引擎实现。常用类型：

| 转场 | 适用情境 |
|------|----------|
| 直切 | 同场景内连续动作、节奏紧凑处 |
| 淡入 / 淡出 | 开场、收尾、时间跳跃 |
| 黑场过渡 | 时间或地点大幅跳转、情绪段落收束 |
| 白闪 | 冲击性事件、意识中断、回忆切入 |
| 溶解 | 柔和的时间流逝、情绪绵延 |
| 推移（左右/上下） | 空间连续移动、跟随视线转移 |
| 模糊过渡 | 主观感受、恍惚、失焦 |

转场时长用秒数或相对描述（「约 1.5 秒」「略长于一拍」）表达意图即可，具体参数属于下游转写阶段。同一部作品内转场词汇要统一，不要在 A 场写「淡出」、B 场写「渐隐」指同一件事。

## 节奏与等待
- 等待与静默是演出手段，不是空白：写明它让什么落地（上一句台词的余韵、一个决定的重量、一次呼吸）。
- 静默要标注时长量级（「约 2 秒」「明显长于常规停顿」）与画面状态（是否保持立绘、是否推进镜头、是否切空镜）。
- 整场戏给出节奏曲线：起（进入）、承（展开）、转（冲突或转折）、收（收束），并说明哪一处是全场最重的节拍。
- 避免全场同一密度：连续多场都是「立绘 + 台词 + 立绘 + 台词」时，主动指出并建议一到两处变化（CG、空镜、静默、转场）。

## 书写范式
中间稿的 **演出** 区按有序步骤写，每步包含：画面状态 → 资产引用 → 动作或台词同步 → 时机。示例：

```markdown
**演出**
1. 淡入 1.5s。远景：空旷天台，晚霞低垂。`BG_ROOFTOP_DUSK`（available）
2. 悠里自画面左侧入画 `SP_YURI_UNIFORM`（available），表情 normal → worried，站位左。
3. 台词（ch003-2a-04）「……你今天来得很早。」——语气刻意放平。表情在台词中段切换。
4. 立绘位移：左 → 中，与本句同步，缓步。
5. 原定 CG `CG_YURI_ROOFTOP`（missing）降级为立绘 + 背景，见标注区。
6. 静默约 2s（让上一句落地），镜头与立绘保持不变。
7. 淡出 1.0s，转场至 SC-013。
```

## 注意事项
- 演出设计必须服务于剧情与情绪，不做无谓的炫技式调度；每一步都要能回答「为什么要这样演」。
- 一场戏里立绘切换过密会让玩家疲劳；同一角色的表情变化在同一场次内通常不超过三到四次。
- 不写引擎语法、不写路径、不写函数与参数表；只写意图。
- 设计时始终对照 `资产索引.md`：脑子里想到的效果如果手上没有对应资产，先走缺口流程，不要先写进稿子再回头发现做不出来。
