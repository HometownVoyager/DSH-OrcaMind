# 演出设计项目搭建（staging-project-bootstrap）

## 何时使用
- 用户要求为一部视觉小说做演出设计（演出中间稿、分场、立绘调度、演出表）且项目尚无 `06-演出/` 时。
- 每轮对话开始检阅项目状态、每轮结束时更新进度与确认记录。
- 接手已有项目但缺 `规范-演出.md` 或 `06-演出/` 骨架时：先按本 skill 模板补建（已有内容照实填入，不确定处标注待确认），再展开工作。

## 只增不改
本模式只新增 `06-演出/` 与工作区主目录的 `规范-演出.md`，并在项目 README 追加本阶段的行。`00-设定/`、`01-规划/`、`02-系统/`、`03-修订/`、`04-资产/`、`05-剧本/` 的既有文件一律不重写，`剧情精述.md` 与 `规范-剧本.md` 只读。

## 标准结构

```
<工作区>/
├── 规范-演出.md                 # 演出中间稿规范（工作区主目录，与 <作品名>/ 并列）
└── <作品名>/
    ├── README.md                # 上游已有；本模式只追加行
    ├── 剧情精述.md              # 上游只读
    ├── 00-设定/                 # 上游只读：含 anchors.md 全局基准事实层（锚点矩阵核验依据）
    ├── 04-资产/                 # 上游只读：asset-list.md + notes/{bg,sprite,cg,bgm,sfx,ui,script}.md
    ├── 05-剧本/                 # 上游只读：draft-vN/ 逐章剧本 + scene-list.md
    ├── assets/                  # 实际资产文件；本模式只核实与登记，不搬动、不改名
    │   └── bg/ sprite/ cg/ bgm/ sfx/ script/
    └── 06-演出/                 # 本模式产出
        ├── 总体说明.md
        ├── 资产索引.md
        ├── 资产缺口.md
        ├── 演出精述.md
        ├── 制作计划.md
        └── draft-v1/
            ├── sc001.md …       # 逐场演出中间稿，三位编号
            └── scene-map.md     # 场次表
```

自建项目（无 00–05 编号目录）时，按项目既有结构定位剧本正文、剧情精述与资产列表，把实际路径映射写进 `总体说明.md`；`06-演出/` 与 `assets/` 的约定保持不变。项目已有自己的资产目录习惯时尊重用户结构，但要在 `总体说明.md` 中登记实际路径。

## 文档模板

### 06-演出/总体说明.md

```markdown
# 演出总体说明

- 作品名：<作品名>
- 引擎与平台目标：<如 Ren'Py / PC，或「未定，待用户确认」>
- 本阶段范围：演出中间稿（分场、立绘调度、背景与听觉提示、CG 与转场、节奏），不含引擎转写
- 演出风格基调：<整体演出密度、镜头感、节奏倾向；未定则标「待确认」>

## 上下游与路径
| 环节 | 预设 / 来源 | 实际路径 |
|------|-------------|----------|
| 设定与系统 | 视觉小说全栈设计 | 00-设定/ · 02-系统/ |
| 基准事实层 | 视觉小说全栈设计 | 00-设定/anchors.md |
| 资产需求清单 | 视觉小说全栈设计 | 04-资产/asset-list.md · 04-资产/notes/ |
| 剧本正文 | 剧本创作 | 05-剧本/draft-vN/ |
| 剧情精述 | 剧本创作 | 剧情精述.md |
| 实际资产文件 | 本模式核实 | assets/ |
| 演出规范 | 本模式 | ../规范-演出.md |

## 术语表
| 术语 | 含义 |
|------|------|

## 待确认事项
| 日期 | 事项 | 状态 |
|------|------|------|
```

### 06-演出/资产索引.md

字段定义见 `staging-asset-audit` skill。骨架：

```markdown
# 实际资产索引

- 扫描根目录：assets/
- 最近扫描：<日期>
- 统计：available <n> ｜ generated <n> ｜ substitute <n> ｜ placeholder <n> ｜ 缺口见 资产缺口.md

## 背景
| 资产 ID | 分类 | 名称 | 文件位置 | 规格 | 状态 | 备注 |
|---------|------|------|----------|------|------|------|
```

### 06-演出/资产缺口.md

字段定义与裁决流程见 `staging-gap-triage` skill。骨架：

```markdown
# 资产需求与缺口

- 比对依据：04-资产/asset-list.md + 04-资产/notes/ ｜ 实际：assets/ ｜ 最近比对：<日期>

## 缺口总表
| 缺口 ID | 分类 | 需求来源 | 影响场次 | 等级 | 处理方案 | 状态 |
|---------|------|----------|----------|------|----------|------|

## 裁决记录
| 日期 | 缺口 | 用户裁决 | 影响范围 |
|------|------|----------|----------|
```

### 06-演出/演出精述.md

```markdown
# 演出精述

## 当前进度
<写到第几场、第几稿、正在处理的场次；比 README 具体>

## 逐场精述
### SC-001 ｜ <地点>·<时间> ｜ 对应上游 <章-段>
<用复合句完整概括：这场戏演什么、画面怎么走、情绪怎么变、用了哪些资产、有哪些缺口与标注；可独立读懂>
```

更新纪律：每完成一场或一次修订，立即更新对应条目与进度；回溯修改时同步改写受影响场次的精述；精述与中间稿或已确认内容不一致时，以中间稿与已确认内容为准并当场修正精述。

### 06-演出/制作计划.md

```markdown
# 制作计划与状态

- 当前轮次：第 <n> 轮
- 当前稿次：draft-v<n>

## 场次清单
| 场次 | 地点·时间 | 上游对应 | 状态 | 阻塞点 |
|------|-----------|----------|------|--------|
```

场次状态取值：`未开始` / `设计中` / `待确认` / `已定稿` / `已阻塞`。阻塞点写明缺什么、等谁裁决。

### 06-演出/draft-vN/scene-map.md

```markdown
# 场次表

| 场次 | 地点 | 时间 | 出场角色 | 剧情功能 | 背景 | BGM | 缺口数 |
|------|------|------|----------|----------|------|-----|--------|
```

## README 登记（只追加）
在项目 README.md 的阶段确认记录与进度记录表中追加本阶段的行，不改写上游已登记的行。字段沿用上游表头：阶段写「演出设计」，确认内容写本轮达成的结论，进度记录写产出的文件。

## 执行步骤
1. 确认项目身份与上游状态：读 README.md、`剧情精述.md`、`规范-剧本.md` 与 `00-设定/anchors.md`（存在时，作为基准事实层），定位 `04-资产/`、`05-剧本/` 与项目资产目录；找不到时必须先向用户索取或确认从零开始。
2. 按「开工规范检查」处理 `规范-演出.md`：已有且完整直接采用；没有或不完整则给三个方向由用户选，选定后落盘四节骨架。
3. 创建 `06-演出/` 目录骨架与五份文档，先只写能确定的字段，其余标注「待确认」。
4. 加载 `staging-asset-audit` 扫描实际资产，填入 `资产索引.md`。
5. 加载 `staging-gap-triage` 比对需求与实际，填入 `资产缺口.md`。
6. 在 README 追加本阶段的行，并在对话中报告骨架已建、下一步建议（通常是先裁决阻塞级缺口）。

## 注意事项
- 阶段不可跳：没有 `资产索引.md` 与 `资产缺口.md` 之前，不要开始逐场中间稿——演出设计必须建立在资产事实之上。
- 骨架里的每个字段都要么写实、要么明确标「待确认」，不得留空让人猜。
- 用户已有自己的目录习惯时尊重用户结构，但至少保证「规范、实际资产索引、缺口、演出稿、制作计划」五类内容可被找到。
- 项目根本没有上游剧本时不要硬造：演出设计需要剧本作为依据，请用户先提供剧本或确认由上游预设产出。
