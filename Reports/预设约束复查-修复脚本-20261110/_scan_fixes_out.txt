   6| # vn-gate · 默认每轮流程与 README 状态机
   7| 
   8| 本 skill 定义 VN 七预设共享的**默认工作节奏**。它不是绝对门禁：各预设 persona 的【指令裁决】段优先级最高，用户显式指令可覆盖本 skill 的一切流程与确认要求。规则措辞以「默认」为主，不因未使用绝对化措辞而降低效力。
   9| 
  10| ## 0. 与宪法的关系（先读）
  11| 
  12| - 硬红线只有三条，写在每个预设 persona 的【指令裁决】第 1 条：① 不跨阶段写入 ② 不创建白名单外文件 ③ 不自行把 README 状态置「已确认」。
  13| - 本 skill 其余内容（七步顺序、单轮单条目、提问与确认、A/B 组选项、状态机）均为**默认节奏**，用户指令与之冲突时以用户为准；用户已在同一条消息里写明范围或做法时视为已确认。
  14| - 三份共享 skill 冲突时按 `vn-gate`（流程）> `vn-spec`（目录与格式）> `vn-continuity`（核查）执行；都不与宪法冲突。
  15| - 历史文档（施工文档、旧预设、旧七步 `Read→Report→Plan→Do→Check→Write→Ask`、已 `disabled` 的预设）**不是现行规则来源**，不据此溯源或核验本轮行为。
  16| 
  17| ## 1. 默认七步循环
  18| 
  19| ```
  20| Read → Report → Confirm → Do → Check → Write → Stop
  21| ```
  22| 
  23| | 步 | 默认动作 |
  24| |---|---|
  25| | **Read** | 按固定顺序：① 读 `README.md` 状态机（校验「当前预设」是否匹配自己，见 §4）② 首轮另显式用文件工具读一次根级 `Specifications.md` 与 `Direction.md`（后续轮按已读内容执行，不复读）③ 读本阶段已有产物（上游只读）。`Specifications.md` / `README.md` / `AGENTS.md` 由 `agent-instructions` 自动注入，不算显式文件工具读。 |

  27| | **Confirm** | 默认用 `ask_user_question` 请用户确认「本轮就做这一个」，或改选候选；用户已在同一条消息里写明范围时跳过提问，直接进入 Do。 |
  28| | **Do** | 只做被确认的子条目，产出到本阶段「写」列目录。 |
  29| | **Check** | 按 `vn-continuity` 只核查这 1 个产物，按 `vn-spec` 校验目录与格式。 |
  30| | **Write** | 只写这 1 个文件 + 就地更新 `README.md` A 区「当前状态」5 字段 + B 区「进度记录」追加一行（状态置「待确认」）。 |
  31| | **Stop** | 停下，报告本轮结果与下一候选标题，等用户下一轮指令。 |
  32| 
  33| 默认每轮只做 1 个子条目；用户可显式授权「一次做完多个子条目 / 跳过逐轮确认」，按授权节奏执行（宪法第 2 条）。

  38| - 「README 状态登记」与「成果交付」的时点：默认在**下一轮 Read 之前**完成，也可在本轮 Stop 之前完成；两者都不属于「提问之后禁止的动作」，不存在时序矛盾。
  39| - 两组常用选项（可按需选用，不必互斥套用）：
  40|   - Confirm 组：就做这一个 / 换一个子条目 / 先不做，停下询问。
  41|   - Stop 组：认可本轮成果 / 换一个子条目重做 / 本阶段已确认，进入下一预设。

  47| - **算越界**：为后续子条目写字段、模板、占位内容、候选方案或「以后可以……」的展开；替下游阶段做设计。
  48| - `下一候选` 字段登记的是上述「只列标题」的清单，无后续候选时记「无」。

  51|

  53| 
  54| | 字段 | 定义 |
  55| |---|---|
  56| | `当前预设` | 当前应工作的 `VN-*` 预设 id；用户手动切换预设后，由新预设首轮 Read 就地登记，AI 不代改。 |
  57| | `当前阶段` | 该预设对应阶段名。 |
  58| | `本轮子条目` | 本轮被用户确认处理的那 1 个子条目（用户授权多条目时按授权记）。 |
  59| | `状态` | 三值：`进行中` \| `待确认` \| `已确认`。 |
  60| | `下一候选` | 下一轮候选子条目标题清单，只列标题、不展开；无后续候选记「无」。 |

  62| 状态转换（默认）：
  63| ```
  64| 进行中 --Write 完成--> 待确认
  65| 待确认 --用户明确确认--> 已确认

  68| 
  69| - `已确认` 默认由用户在确认中给出后，AI 代为登记；AI 不自行置位。用户显式授权时按其授权处理。
  70| - B 区「进度记录」只追加、不改写或删除既有行。裁决结论（见 `vn-continuity` §5）追加一行记入。
  71| - 阶段切换 = 用户手动切换到对应预设 + README `状态=已确认`（用户显式指令覆盖时以指令为准）。

  73|

  87| 3. 不自行删除 / 覆盖 / 改写已越界写出的文件来「恢复原状」，不自行改回 README。
  88| 4. 由用户裁决「保留并补确认 / 撤销（须用户明确指令）/ 换子条目重来」；裁决按 `vn-continuity` §5 追加一行记入 B 区，之后开始新一轮。
